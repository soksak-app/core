# 기능 상태

[English](features.md)

검증 결과는 명시한 구현에만 적용한다. 테스트 통과는 배포 완료를 의미하지 않는다.

## 진행 중 구현 체크리스트

`[ ]`는 미구현 또는 미검증, `[~]`는 작업 또는 검증 중, `[o]`는 명시한 항목의 근거 확인을 뜻한다. 코드 조사 결과가 동작 검증을 완료하지 않는다. 승인된 [터미널 런타임](spec/terminal-runtime.ko.md)은 표면별 세션 수명과 별도 PTY 헬퍼 설계를 대체하며 이 변경은 다시 빌드한 앱에서 아직 검증되지 않았다.

- [o] PTY close, consumer 정리, 무시된 터미널 엔진 이벤트, 미지원 조합 입력 경로 조사.
- [o] 독립 세션과 명시적 정상 종료를 갖춘 영속 터미널 서비스 하나를 구현했다. 현재 HEAD의 Tauri·Wails 검사에서 서비스 하나와 독립 PTY 자식 3개를 확인했고 서비스를 종료하지 않고 PTY를 회수했다.
- [o] 내부 표면 웹뷰를 창당 앱 DOM 하나와 논리 네이티브 컨테이너로 교체. 다시 빌드한 Tauri와 Wails 검사에서 앱 DOM 하나와 독립 문서 WebView를 확인했다.
- [~] 실제 기동과 첫 표면 생성에서 관측한 통합 오류를 수정한다: 잘못된 AppKit appearance selector, 표면 포트 레지스트리 범위, 최초 설정 경로, 메인 뷰 등록 시점, Tauri 표면 맵 자기 잠금, Wails 창/뷰 핸들 혼동. 기동 화면과 프로세스 스택으로 실패를 확인했으며 터미널 3개를 사용하는 전체 앱 검증은 여전히 필요하다.
- [o] macOS 네이티브 컨테이너 구성요소에서 논리 표면 3개, 외부 문서 뷰 2개, 실측 앱 DOM 개수, 클리핑, 명시적 메인 뷰 입력 식별을 검증했다. 재빌드한 호스트 결과는 아니다.
- [o] 네이티브 창 상태에서 논리 표면이 누락되는 문제를 재현하고 수정했다. 웹뷰만 측정하던 구현에서 컨테이너 3개 검사가 실패했고 네이티브 컨테이너 상태 추가 후 통과했다. 양쪽 호스트의 읽기 경로도 실측 컨테이너를 사용하며 재빌드한 호스트 검증은 남아 있다.
- [o] 네이티브 표시 대기에서 URL 출처 추정을 제거했다. 새 동일 출처 문서 검사는 수정 전 3.007초 지연으로 실패했고 수정 후 0.009초로 통과했다. 앱 DOM 자체 표시와 열린 트랜잭션 검사는 유지하며 구성요소 검사 11개가 통과했다. 재빌드한 호스트 검증은 남아 있다.
- [o] 잘못된 base64 입력의 앞부분만 수락하지 않고 요청 전체를 거부한다. 기존 디코더에서 잘못된 입력 검사가 실패했고 수정 후 인코딩 검사 2개가 통과했다.
- [o] 프로젝트 복귀의 프로세스 개수 검사를 설정 범위의 서비스·셸 PID 동일성 검사로 바꿨다. 다시 빌드한 Tauri와 Wails에서 터미널 서비스 하나, PTY 자식 3개, 3회 프로젝트 복귀 중 서비스·세션 PID 동일성, 좀비 자식 없음을 통과했다.
- [o] 터미널 3개와 완전한 빠른 제스처로 터미널 경계 침범과 셸 흰 픽셀 각각 검증. 재빌드한 Tauri와 Wails의 프로젝트 복귀·고정 셀 드래그 캡처가 통과했으며, `make -C native/darwin test`의 fractional WebView 검사도 통과했다.
- [~] 외부 문서 appearance와 네이티브 클릭 소유권 수정. 앱 통합 검증은 대기 중.
- [ ] 설정 가능한 커서 렌더링 구현·검증.
- [ ] 선택, 클립보드, 파일·이미지 입력, 인라인 이미지, 시퀀스 지원 목록 구현.
- [o] 진단 녹화 상한 도달은 실제 프레임 수와 명시적 `limited` 상태를 반환한다. 전체 제스처 검증은 상한에서 끝난 증거만 거부하며 녹화 결과 자체는 실패로 바꾸지 않는다.
- [ ] Wails도 Tauri와 같은 상한 녹화 계약을 제공하도록 구현한다. `diagnostics.capture.stop`은 실제 프레임 수, `limited`, `longestGap`을 모두 반환해야 한다.
- [ ] Wails의 네이티브 모달 WebView 수명주기를 구현한다. `OverlayShow`가 모달 문서를 생성·숨김·로드·배치·표시·포커스하고 갱신·종료해야 한다. 투명 분할 모달(`mode=menu`)과 반투명 설정 모달(`mode=dialog`)을 모두 검증한다.
- [~] 고정한 기준 문서의 OSC 표준 선택자와 선택한 벤더 확장을 전부 목록화하고 효과·응답 또는 정책·플랫폼 거부를 검사한다.
- [~] 고정한 기준 문서의 CSI final byte·매개변수 형식·private mode·장치 응답을 전부 목록화하고 검사한다. 스크롤은 CSI(`S`, `T`, `r`, `J`, `K`)로 분리해 보이는 그리드·스크롤백·커서·alternate screen·선택을 각각 검사한다.
- [~] 네이티브 조합 문자 처리와 확정 입력 순서 구현. 실제 한글 IME 검증은 대기 중.
- [ ] 복원 단계 측정과 실제 최초 표시까지 loading/ready/error 제공.
- [~] 양쪽 호스트 빌드·검증, 정상 자원 회수, 충돌 재연결, 업데이트 재시작 검증. 현재 HEAD의 Tauri·Wails에서 프로젝트 3회 복귀 중 서비스·셸·세션·문서 식별자를 유지했고, 정상 터미널 탭 종료 후 모든 PTY 자식을 회수했다. 충돌 재연결과 업데이트 재시작은 남아 있다.

## Tauri/Wails 대칭 감사 (2026-09-21)

기계적 호스트 검사가 현재 실패한다. `make hosts-check`가 `apps/tauriv2/test/runtime.test.mjs: no counterpart in apps/wailsv3`를 보고한다. Wails에 없는 것은 Tauri 런타임 계약을 검증하는 테스트이며, 이 결과만으로 Wails 런타임 구현 자체가 없다고 판단하지 않는다.

진단 녹화 상한 계약도 비대칭이다. Tauri의 `diagnostics.capture.stop`은 `frames`, `count`, `limited`, `longestGap`을 반환하지만, 현재 Wails는 `frames`, `count`, `longestGap`만 반환하고 `platform.Capturer`에도 `CaptureLimited` 연산이 없다. 공용 macOS 캡처 구현과 녹화 상태 검사는 양쪽 호스트에 있으므로, 확인된 차이는 Wails의 상한 상태 계약과 그 검증이며 Wails 캡처 구현 전체가 없는 것은 아니다.

모달 구현에는 더 큰 차이가 확인됐다. Tauri의 `modals::show`는 자식 네이티브 WebView를 만들고 `/overlay.html`을 로드한 뒤 `ready` 전까지 숨기며, 모드별 배경을 적용하고 위로 올린 후 포커스를 준다. Wails의 `OverlayShow`는 모달 상태를 저장하고 `modal-content`만 발행하며 모달 WebView를 생성하거나 로드하지 않는다. Wails의 `ConfigureModal`과 `FocusModal`도 선언만 있고 호출 지점이 없다. 따라서 DOM/네이티브 구조 정리 후 Wails에서는 투명 분할 모달과 반투명 설정 모달이 모두 실제로 존재하지 않는다. 이것은 외관 테스트만의 실패가 아니라 구현 경로 누락이다.

호스트 테스트 파일 이름은 `recording_test`를 포함해 현재 서로 일치한다. 구조 검사는 앱 런타임 테스트에서 멈추기 전 다른 누락된 대응 파일을 보고하지 않았다. 근거 없는 다른 Tauri 전용 기능은 이 감사에서 추가하지 않았다.

실제 PTY 세션 종료 검사는 이미 종료한 자식을 닫을 때 `No such process`로 실패했다. 해당 자식의 종료를 명시적으로 확인하고 회수하도록 수정한 뒤 같은 두 세션 검사가 생략 없이 통과했다. 서비스 전체 재연결, 자손 프로세스 정리, 반복 종료 자원 측정은 남아 있다.

## 이전 검증

macOS의 터미널 키보드 전달을 수정했다(2026-09-20). Tauri의 빈 그림 이벤트 콜백이 네이티브 입력을 버렸고, 터미널 플러그인도 두 호스트에서 조합키의 문자를 버렸다. 수정 전 터미널 3개 네이티브 입력 검사는 Tauri의 일반 문자 입력과 Wails의 Ctrl+U에서 실패했다. 수정 후 다시 빌드한 두 호스트에서 8개 검사(상위 검사 2개, 터미널 검사 6개)가 실패·생략 없이 통과했다. 네이티브 클릭, 문자 입력, Backspace, Ctrl+U, Enter, 정확히 한 번의 명령 출력, 다른 터미널과의 격리를 확인했다. `terminal.screen`이 사이드카 화면 알림을 공개하며 검사는 화면 내용을 반복 조회하지 않는다. 네이티브 검사, 패키지 검사, 두 빌드, 구조 검사가 통과했다. 이 결과는 키보드 입력 검증이며 남은 합성 실패를 검증하지 않는다. 처음 보고된 창은 보존했다.

현재 합성 검증(2026-09-21, macOS 26.6.2)은 이 문서에 기록한 다시 빌드한 호스트 범위에서 통과했다. 기준 Wails 빌드에서는 셸 흰 픽셀과 터미널 경계 침범이 재현됐다. Wails 빈 터미널의 원인은 `compositionDeclare` 등록과 불변 선언 경로가 빠져 있었던 것이며, 이제 호스트는 선언되지 않은 배치를 거부하고 배치 전에 선언을 기록한다. 다시 빌드한 Tauri와 Wails에서 각각 3개 터미널 프로젝트 복귀 검사와 고정 셀 빠른 분할기 검사가 통과했다. 검사는 실제 이동, 6회 왕복, 모든 캡처의 터미널 3개 영역, 흰 픽셀·보더 침범 없음, 안정된 글리프 지표, 터미널·세션 복원을 요구한다. `make -C native/darwin test`, `make docs-check`, `git diff --check`도 통과했다. 프로세스 수명, 커서, OSC, IME, 로딩 요구사항은 아직 별도 항목이다.

현재 HEAD 확인(2026-09-21, macOS 26.6.2): `660d176`에서 빌드한 바이너리로 같은 3터미널 빠른 분할기·프로젝트 복귀 검사를 Tauri(1/1, 6.14초)와 Wails(1/1, 5.42초)에서 각각 통과했다. Wails 실행 로그의 `vcs.revision=660d176`도 확인했다. 이 결과는 해당 빌드 리비전의 두 호스트 합성 동작만 확정하며, 남은 런타임·커서·프로토콜·IME·복원 요구사항을 완료시키지 않는다.

2026-09-08 라이브러리 단순화 검증은 두 macOS 호스트를 다시 빌드하고 재시작했다. 전체 예제 검사에서 37개 통과, 녹화 프레임 수 부족으로 2개 실패(Wails 56개·Tauri 55개, 기준 60개 초과), 2× 화면 하나만 연결되어 화면 전환 검사 2개를 생략했다. 실패한 2개는 같은 코드와 기준으로 재검사하여 통과했다. 프레임 수 부족은 간헐적으로 발생하며 이번 변경에서 수정하지 않았다. Go 3/3·Rust 3/3 저장소 검사와 `make docs-check`를 통과했다. Windows·Linux 네이티브 실행은 미검증이다. 변경하지 않은 배치 라이브러리는 `1a921b4` 기준 테스트 310개 통과·변이 142개 검출 결과를 유지한다.

녹화 완전성(2026-09-17): 녹화는 프레임을 별도 큐에서 쓰고 `diagnostics.capture.stop`이 가장 긴 표시 간격을 알린다. 끌기 녹화는 100ms를 넘으면 실패한다. 이전에는 2×에서 최대 480ms 걸린 디스크 쓰기가 프레임을 버렸고, 위에 적은 간헐적 프레임 수 실패의 원인이었다. 창 크기 변경과 최대화는 `resize.test.mjs`가 측정한다. AppKit 또는 Wails 애니메이션 동안 배치는 창 프레임보다 250~400ms 늦게 따라오며(WebKit/WebKit#72971, tauri-apps/tao#1207), 변경이 끝난 프레임은 창 크기와 맞는다.
