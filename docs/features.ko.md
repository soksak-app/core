# 기능 상태

[English](features.md)

검증 결과는 명시한 구현에만 적용한다. 테스트 통과는 배포 완료를 의미하지 않는다.

| 기능 | 구현 | 검증 | 배포 |

| 브라우저 페이지와 문서 영역 | 표면은 플러그인 페이지만 표시하며 `surface.url`은 제거했다. 표면 페이지는 [문서 영역](spec/native-surfaces.ko.md#문서-영역)(`attachDocument`, `page.document`)을 붙이고, macOS 호스트는 표면 웹뷰 안의 웹뷰로 영역을 만든다(`native/darwin/src/document_view.m`). 소유 표면 확인, 소유 표면에만 보내는 상태 이벤트, 표면 제거·페이지 다시 로드 시 정리, 대화 상자 블러, `host.window`의 `documents`, `host.hit`의 `document`를 포함한다. 브라우저 플러그인 페이지는 주소창, `browser.location`, `browser.*` 명령과 dom 항목을 갖는다 | 패키지 검사, 호스트 검사, `make native-test`(`document_view_test`와 그 네이티브 스크롤 검사, `webview_geometry_test`의 영역 배율 검사 포함), `make release-check`를 포함한 release 빌드, `diagnostics` 유무별 macOS·Windows Tauri 호스트 `cargo check`, Windows `go vet`이 통과한다. 다시 빌드한 macOS 디버그 호스트의 창 검사(2026-09-18, 내장 2× 디스플레이): 56개 실행, 56개 통과, 건너뜀 0, 연속 3회 | 미배포 |
| 작업 공간 패키지와 셸 사이드카 | 배치 라이브러리, 워크벤치, 플러그인 API, 플러그인 3개, 셸 사이드카, 애플리케이션 3개, macOS 공용 라이브러리로 구성한 pnpm 작업 공간. 애플리케이션이 `environment.json`에 플러그인을 선언하고 셸 세션은 `sidecars/shell`에서 실행한다 | `b1f6f61`에서 패키지 테스트, 네이티브 단위 검사, 두 네이티브 빌드 통과. 다시 빌드한 macOS 호스트의 창 검사 38개 중 26개 통과, 10개 실패, 디스플레이 전환 검사 2개 생략. 두 셸 검사 통과. 실패 10개는 분리 전 `22c313b`에서도 발생한다: 창 단추 중앙 검사(45px 제목 행, 단추 y 14.5), 이에 의존하는 흔들기 검사, Wails 정렬·바쁜 스크립트 검사 | 미배포 |
| 노출(status, command, dom) | [명세](spec/exposure.ko.md)에 따른 코어, 표면 문서, 모달 문서, 호스트, 셸 항목. 표면 페이지는 플러그인 API로 등록한다. 요청은 표면을 지정할 수 있다 | 패키지 검사, 호스트 검사, `make native-test`가 통과한다. 코어 명령은 예약한 그리기가 끝난 뒤 답한다. 다시 빌드한 macOS 디버그 호스트의 창 검사(2026-09-18, 내장 2× 디스플레이): 56개 실행, 56개 통과, 건너뜀 0, 연속 3회. 웹 인스펙터를 표면에 붙였을 때와 닫은 뒤에 표면이 프레임을 유지하는지는 `native/darwin/tests/webview_inspector_test.m` 이 검사한다. 창 단추는 AppKit 의 것이다. 창마다 항목 없는 unified compact 도구막대를 붙여 제목줄을 40pt 로 만들고, 페이지는 첫 행 높이를 단추 영역에서 얻는다. 표시 대기가 외부 문서와 숨긴 문서를 제외하는지, `host.window.presented`가 창의 열린 배치 트랜잭션을 기다리는지, 표시한 프레임의 표시 시각을 보고하는지는 `native/darwin/tests/surface_layout_test.m`이 검사한다. 모달 문서는 호스트의 변경 순서대로 내용과 위치를 적용한다(`modal-order.test.mjs`, `modal.test.mjs`에서 `diagnostics.modal.hold`로 붙잡은 첫 응답). 녹화를 표시 시각에 멈추게 한 뒤 최대화·되돌리기 검사는 연속 30회 통과했다. 두 호스트는 첫 창을 만들기 전에 `NSWindowResizeTime`을 0.001로 등록한다. 배치가 창보다 늦은 시간은 그전에 Wails 263ms, Tauri 432ms였고 이후 최대 116ms이며, 검사는 150ms를 넘으면 실패한다(연속 20회 통과, `native/darwin/tests/window_motion_test.m`은 0.350초와 0.003초를 측정한다) | 미배포 |
| 로컬 엔드포인트, CLI, MCP | 두 macOS 호스트의 Unix 소켓 엔드포인트와 `endpoint.json`, 디버그 빌드의 진단 메서드, `soksak` CLI, `soksak-mcp`. 창 검사는 엔드포인트만 사용한다. Windows와 Linux 전송은 미구현 | 두 호스트의 엔드포인트·중계 검사, client, CLI, MCP 검사 통과. 두 호스트는 SIGTERM, SIGINT, SIGHUP에서 일반 종료로 끝나고 수신 전에 끝난 프로세스의 소켓을 제거한다(`tests/termination_test.*`, `tests/endpoint_test.*`, 각 디버그 호스트에 시작 직후와 4초 뒤 SIGTERM 전송: 종료 코드 0, 소켓과 `endpoint.json` 남지 않음). 위 창 검사를 엔드포인트로 실행. 디버그 빌드의 왕복 p50(2026-09-17): 호스트만 142–443µs, 메인 페이지 중계 1.5–2.7ms, 표면 중계 1.4–7.5ms([운영](operations/examples.ko.md#진단)) | 미배포 |
| 네이티브 입력과 창 단추 | `input.pointer`와 `input.key`는 애플리케이션을 활성화하지 않고 네이티브 이벤트를 전달한다. 누름과 뗌은 문서가 받은 뒤 답하고, 스크롤은 대상 뷰가 표시한 뒤 뷰의 좌표 단위로 전달한다. 버튼 없는 이동은 키 창이 필요하며, `activate`는 창을 먼저 활성화하고 멈춘 단계를 알린다. 표면과 모달 페이지는 키보드 초점을 옮기지 못한다. 창 단추는 첫 행 가운데에 두고, AppKit이 가져가면 다음 표시 전에 되돌린다 | `make -C native/darwin test`와 `make -C native/darwin test-activation`이 통과한다(활성화는 Terminal이 최전면일 때이며, 양보하지 않는 최전면 애플리케이션은 거절로 보고된다). 위의 창 단추·메뉴 검사가 통과한다 | 미배포 |

Windows는 미구현 오류를 반환한다. [명세](spec/hosts.ko.md) | 패키지 테스트, `make boundaries`, `make platforms`, `make hosts-check`, `make native-test`, 두 macOS 빌드가 통과했다. Wails 호스트의 Windows 대상 `go vet`·`go build`와 Tauri 호스트의 `x86_64-pc-windows-msvc` 대상 `cargo check`가 경고 없이 통과했다. Windows 대상 Tauri 애플리케이션 크레이트는 이 macOS 장비에 없는 Windows 리소스 컴파일러(`llvm-rc`) 단계에서 멈춘다. 외부 1× 디스플레이만 연결한 상태에서 창 검사 38개 중 22개 통과, 14개 실패, 2개 생략이며, 실패 목록은 이전 1× 실행과 같고 셸·라이브러리·프로젝트 창·호스트 비교 검사는 통과했다 | 미배포 |
| 설정 범위 탭 | 일반 본문에 전역·프로젝트 탭 제공. 설정 대상 프로젝트가 적용값·기본 저장·제공 범위를 결정한다. 라이브러리는 공통 설정과 전역 탭만 사용하며 작업 화면 복귀 시 프로젝트 덮어쓰기를 복원한다 | 두 macOS 호스트 재빌드. 관련 설정·프로젝트·라이브러리·모달 검사 18개 통과, 실패 0개, 생략 0개. 범위 위치·분류 전환·JSON 저장·초기화·라이브러리 외관 동작·작업 화면 복원을 포함한다. 네이티브 라이브러리 설정 외관 확인 | 미배포 |

2026-09-08 라이브러리 단순화 검증은 두 macOS 호스트를 다시 빌드하고 재시작했다. 전체 예제 검사에서 37개 통과, 녹화 프레임 수 부족으로 2개 실패(Wails 56개·Tauri 55개, 기준 60개 초과), 2× 화면 하나만 연결되어 화면 전환 검사 2개를 생략했다. 실패한 2개는 같은 코드와 기준으로 재검사하여 통과했다. 프레임 수 부족은 간헐적으로 발생하며 이번 변경에서 수정하지 않았다. Go 3/3·Rust 3/3 저장소 검사와 `make docs-check`를 통과했다. Windows·Linux 네이티브 실행은 미검증이다. 변경하지 않은 배치 라이브러리는 `1a921b4` 기준 테스트 310개 통과·변이 142개 검출 결과를 유지한다.

녹화 완전성(2026-09-17): 녹화는 프레임을 별도 큐에서 쓰고 `diagnostics.capture.stop`이 가장 긴 표시 간격을 알린다. 끌기 녹화는 100ms를 넘으면 실패한다. 이전에는 2×에서 최대 480ms 걸린 디스크 쓰기가 프레임을 버렸고, 위에 적은 간헐적 프레임 수 실패의 원인이었다. 창 크기 변경과 최대화는 `resize.test.mjs`가 측정한다. AppKit 또는 Wails 애니메이션 동안 배치는 창 프레임보다 250~400ms 늦게 따라오며(WebKit/WebKit#72971, tauri-apps/tao#1207), 변경이 끝난 프레임은 창 크기와 맞는다.
