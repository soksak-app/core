# Memory saver

[한국어](memory-saver.ko.md)

Pending proposal for F198. Its approved content moves into `docs/spec/plugins.md`, `docs/spec/settings.md`, `docs/spec/exposure.md`, `docs/spec/hosts.md` and `docs/spec/logging.md`, and this file is removed.

## Problem

A tab that is not shown is never released. `dormant()` in `packages/workbench/index.html` commits every tab that is not shown as an invisible surface: the other tabs of each card and every tab of every space and project. `disposeSurfacesExcept` releases only tabs that no longer exist, and a surface is released only when its tab closes (`closeTab` → `disposeSurface`). A hidden document tab keeps its WebContent process and page; a hidden DOM tab keeps its DOM and objects in the main page process; a hidden image tab keeps its image region. F196.29 clears the back-forward cache of a hidden document region, but its shown page and process stay.

## Decision

The core unloads a hidden tab and restores it from its stored state when it is shown again. One setting turns this on or off. The core alone decides when; a plugin declares whether its tabs can be unloaded and keeps its state current.

Terms: **unload** (release the surface of a tab that stays in the layout) and **restore** (mount an unloaded tab again from its state). No other word names these two operations.

### Rules

1. **The core decides.** Only the core decides when a tab is unloaded and restored. A plugin has no timer and no unload decision.
2. **Every plugin declares.** A surface in `plugin.json` declares `surface.unload`: `false`, or `{format, maxBytes}` for a plugin whose tabs can be unloaded. It is required unless the plugin declares `background`, and forbidden when it does: a plugin with a background session keeps its session through the background path (F192). `validateManifest` rejects a manifest that breaks either rule. A tab whose plugin declares `false` is never unloaded and appears in the status with the reason `undeclared`; a tab of a plugin with `background` appears with the reason `background`.
3. **State is written on each change, kept in memory at once, stored per tab.** A declaring plugin writes the state it needs, as JSON, through `context.tab.state.write(value)` whenever it changes. The write is synchronous into memory, so an unload in the same task sees the latest value. The core stores it per tab as `{format, value}` in the tab state store (see Stored format), the value in memory is never dropped and the stored value follows it within one second (see Stored format); each store write of a tab is the event `page.tab.state.stored {tab, bytes}`. A value that is not JSON or exceeds `maxBytes` is refused with an error that names the tab and the size. After the surface is disposed, `state.write` from the old context is refused with an error that names the tab and `disposed`, logged once per context, so an old instance cannot overwrite the state of a restored one; a plugin stops its pending work with the existing `context.closing` signal, which aborts at dispose. A restored surface reads `context.tab.state.read()`, which is `null` when the store has no entry for the tab; a stored format other than the declared one is refused with a restore error that names the tab and the format found. Only state written through this API survives an unload, a crash or a restart; each plugin states in its own specification what it gives up.
4. **Protections.** A tab is not unloaded while any of these holds; each is a reason of the enumeration in rule 7, and a tab can have several:
   - `shown`: the shown tab of its card in a shown space.
   - `recent`: shown less than the delay ago.
   - `keep:modified`: the tab reports unsaved changes through the existing `context.tab.modified`; the core reads it from the tab reports (`tabModified`), so one call owns the fact. A tab that reported it stays kept until it reports it clean.
   - `keep:busy`: the surface reports work in progress through `context.tab.keep("busy", on)`. It ends when the surface is disposed.
   - `media`: the document region plays media. At each decision (a delay deadline, a pressure report or `core.tab.unload`) the core asks the region and awaits the reply of the public `requestMediaPlaybackState` of its web view; `playing` protects the tab. A reply that fails, for example because the region is gone, protects the tab with the reason `media-unknown` and is logged. Active camera or microphone capture is the separate reason `capture`, read from the public `cameraCaptureState` and `microphoneCaptureState` in the same decision step. Paused media in picture in picture is not covered, because WebKit reports no public picture in picture state; screen capture is not covered, because a region does not grant `getDisplayMedia`.
   - `form`: a frame of the document region has an editable element (form field or `contenteditable`) that received a trusted `input` event since that frame's document loaded. WebKit offers no public engine state for this, so a region script in the region content world, injected into every frame (`forMainFrameOnly` off), reports it. The native region keeps the flags in a map keyed by the frame identifier of the script message; a frame's `pagehide` clears its flag, a form `submit` clears it, and a main-frame navigation commit or reload clears the map. A registered `beforeunload` handler is not a protection: the content world cannot see the listeners of the page. A `form` flag lasts until one of those events, so an edited field that the person leaves keeps the tab loaded; the person releases it by navigating or with `core.tab.unload`.
   - `kept`: the person marked the tab to stay loaded with `core.tab.keep`; the mark is stored in the tab state store.
   - `off`: the setting is off.

   A region does not download: a navigation that the view cannot show fails or is cancelled, so no download protection exists. Download support would be a separate item with its own protection.
5. **Two triggers.**
   - `delay`: a tab hidden for the delay (default 2 hours, the order of mainstream defaults) without a protection is unloaded. One core scheduler holds the earliest deadline, computed from the monotonic time each tab was hidden, and re-arms on the existing events that change it (a tab shown or hidden, a protection change, a setting change). It uses a timer because elapsed time has no event source; the code and the specification state that reason. A tab that `media` or `media-unknown` protects at its deadline gets its next deadline one delay later, shown in `unloadAt`.
   - `pressure`: one native memory pressure source starts with the host, observes the normal, warn and critical levels, and numbers each report; it reports a level change only. While the level is warn or critical, the core unloads one hidden tab without a protection, waits for that unload to end, and repeats until a normal report or until no candidate remains. It calls the document region consumer of F196.29, which subscribes instead of owning a source, and the host sends one event `memory-pressure {level, seq}` to the page. Candidates go least recently shown first. `recent` does not protect under pressure; every other protection does. The least recently shown order keeps a tab that was just restored last in line. A report that finds no candidate is the event `page.tab.unload.skipped {trigger, seq, reasons}`.
6. **Unload, restart and hidden time.**

   An unload is one core operation in this order: (1) the core asks each document region of the tab for its `interactionState` through a declared host method addressed by the surface and the document name that `host.window` reports; (2) it marks the tab unloaded; (3) it requests a commit, so `dormant()` leaves the tab out; (4) the set that `disposeSurfacesExcept` receives leaves the tab out, and because the tab is marked unloaded the surface is released with the unload mode of `disposeSurface`, which keeps the tab reports (title, footer, directory, origin, modified and notice; a notice ends only when the tab is shown or closed, as the plugins specification states) and clears only the error, whose display ended with the instance and whose text the single error display already wrote to the log; `forgetTab` runs only when the tab closes; (5) it emits `page.tab.unloaded` after `host.place` replies.

   Each unload attempt has a generation. After every awaited step (the `interactionState` reply, the media reply) the core evaluates the protections again before step 2; a protection that appeared, or a show of the tab, ends the attempt with `page.tab.unload.skipped {trigger, seq, reasons}`, and `core.tab.unload` fails with those reasons.

   A tab that is mounted without being shown takes its mount time as its hidden time. Turning the setting on keeps each tab's hidden time and re-arms the scheduler.

   **Restart.** While `memorySaver` is on, a hidden tab whose plugin declares `surface.unload` starts unloaded at startup and is restored on its first show. While it is off, hidden tabs mount as they do now.

   `dormant()` leaves an unloaded tab out of the invisible surfaces it declares, so the host releases that surface at the next commit; the tab stays in the layout, and its state stays because the store is keyed by the tab identifiers of the layout.
7. **Visible and observable.**
   - The tab button carries `data-tab-state` with the state of the status (`loaded`, `unloaded` or `restoring`) and a dom name; protections are shown only through the reasons of the status.
   - Events in the core catalog, class `lifecycle`: `page.tab.unloaded {tab, plugin, trigger}` (info), `page.tab.restored {tab, plugin, history}` (info; `history` is false when no session history was captured), `page.tab.restore.failed {tab, plugin, reason}` (error, through the single error display), `page.tab.unload.skipped {trigger, seq, reasons}` (info), `page.tab.state.stored {tab, bytes}` (debug, every write of the tab's entry, mark and label included), `page.tab.keep.changed {tab, keep}` (info).
   - Reasons, one enumeration used by the status and the events: `shown`, `recent`, `keep:modified`, `keep:busy`, `media`, `media-unknown`, `capture`, `form`, `kept`, `off`, `undeclared`, `background`. `media`, `media-unknown` and `capture` are the result of the last decision, at the `checkedAt` of the tab; the other reasons change as their sources report.
   - Status `core.tab.memory`: `{enabled, delay, pressure: {level, seq}, tabs: [{tab, plugin, state: loaded|unloaded|restoring, reasons, hiddenAt, unloadAt, checkedAt}]}`, notified on each change; `core.surfaces` reports the state of each tab, and a request to an unloaded surface fails with `tab <id> is unloaded`.
8. **Command.** `core.tab.unload {tab}` unloads a hidden tab now. As the person's own decision it does not wait for `recent`, `media`, `media-unknown`, `capture` or `form`; it fails with the remaining protections (`shown`, `keep:modified`, `keep:busy`, `kept`, `off`, `undeclared`, `background`) and with -32602 for an unknown tab. `core.tab.keep {tab, keep}` sets or clears the person's mark (idempotent, one `page.tab.keep.changed` per change; -32602 for an unknown tab or a non-boolean; an error that names the tab and `undeclared` or `background` for a tab that can never be unloaded). The tab context menu item `tab-menu-keep`, bound through the binder, reads `kept` from the reasons of `core.tab.memory` and is absent for a tab that can never be unloaded.

### Setting

- `memorySaver` (boolean, common scope, default on), section 일반, label "메모리 절약", switch.
- `memorySaverDelay` (integer minutes 5 to 720, common scope, default 120), label "숨긴 뒤 내리기까지", slider. Another value is refused with `Invalid setting memorySaverDelay: <value>`. A change re-arms the scheduler.

One setting covers every plugin. A plugin adds no setting of its own; a site exception list, if a plugin needs one, is that plugin's setting and reaches the core as a keep reason.

### Scope and order

- The core contract covers every surface kind. Adoption starts with document tabs, whose unload ends a WebContent process.
- A DOM tab (editor, flowmark, shell) shares the main page process; its gain is measured first with a tracked benchmark (hidden DOM tabs of each plugin, main page footprint before and after unloading N of them). A DOM plugin adopts the declaration only when that benchmark shows a gain, and the plan records the numbers.
- The terminal keeps its background session (F192) and is not part of this item; releasing the image region of a hidden terminal is measured separately.
- What each plugin stores is specified in its own repository; the core lists its release as a checklist item.

### Browser history

Before an unloaded region closes, the native region returns the public `interactionState` of its web view, serialized session history that holds no document or process, through the host to the page. The page keeps it with the tab in memory, not in the store, and passes it to the region it creates on restore; a value that the web view refuses is a `page.tab.restore.failed` reason. When the read yields nothing, because the process already ended, the region is created at the stored address and `page.tab.restored` carries `history: false`. After a restart only the address that the plugin wrote is restored. The address moves from the browser's own `localStorage` key into `context.tab.state` in the same change.

### Stored format

Tab state is not stored in `projects.json`. A new store `tab-state.json` in the configuration folder, format 1 from its first release, holds per tab identifier an entry with three optional fields, `state: {format, value}`, `kept: true` and `label`, and stores an entry only while one of them is present. `label` is the last title the surface reported, written only for a tab whose plugin declares `surface.unload`, whatever the setting, with the same coalescing; a `null` report removes it. It is a display cache for a tab that is not mounted: the surface stays the owner of its title, the layout `title` stays the tab's name, and the first report after a restore replaces the cache. Footer and directory are not stored: a footer shows only for the shown tab, and a tab added from an unloaded tab gets `origin.directory: null` and starts at the project root as the plugins specification defines; `read()` is `null` when `state` is absent. Whether a tab is unloaded is not stored: rule 6 derives it. Writes of one tab are coalesced to at most one per second and flushed at quit, so a crash loses at most the last second of state. A tab without an entry reads `null`. An entry is removed only after the layout write that drops its tab is confirmed. At load the store is reconciled with the tab identifiers of `projects.json`, and each orphan entry it removes is an event. A reader accepts only the current format. `projects.json` keeps its format, because its contents do not change. A separate store also keeps the frequent state writes away from the whole layout file; plugin `data` is keyed per project and declared key, not per tab, so it is not the owner.

## Adopted and not adopted

- Adopted: unloading hidden tabs after a delay and under memory pressure; a required declaration per plugin; state written on each change with a format and a size limit; the protections above, read from the web view where it owns the fact; one tab per pressure report, least recently shown first; a single scheduler; restore at first show after a restart; the person's mark `kept` set with `core.tab.keep` and stored per tab; the reasons and protections as events and status; session history kept in memory with the public `interactionState`.
- Not adopted: a cap on the number of loaded hidden tabs in the first version (memory pressure answers the real memory limit; a cap is measured after the delay and pressure paths ship); unloading on hide at once; a save hook at unload; unloading undeclared tabs; persisting the full session history; per-plugin settings; unloading DOM tabs before a measured gain; a page script for media (the engine answers it); a short default delay chosen for a lower memory reading.

## Review

Eleven rounds of adversarial review (correctness, architecture, rules, the criteria standard approach, nothing hidden, production stability, developer convenience, structural completeness) and a source comparison with two established platforms produced the rules above. Each settled point and its reason:

- A required declaration per plugin, `false` listed as `undeclared`, forbidden beside `background`: a plugin cannot keep memory unnoticed, and a background session keeps its own path.
- One scheduler with a stated reason for its timer; the delay defaults to 2 hours (the order of mainstream defaults, not a value chosen for a lower reading) and memory pressure is the fast path.
- The pressure source reports level changes only, so the core keeps unloading one tab at a time while the level stays warn or critical; the normal level ends it and keeps the status current.
- State written on each change, synchronous in memory, stored within one second in a separate store with a format, a size limit and reconciliation; `projects.json` and the layout `title` (the tab's name) stay unchanged; a label cache shows the last title of a tab that is not mounted.
- Protections read where the fact is owned: unsaved changes from the existing tab report; busy work from the plugin; media and capture from the engine at each decision; form edits from a region script only, because WebKit has no public engine state for them. A failed media query is `media-unknown` and not `media`, because the status states facts (rejected: folding them together).
- The person's mark `kept` with `core.tab.keep` stays in the first version, because without it the only exemption is turning the feature off; both compared platforms ship it (rejected: deferring it).
- The unload is one operation in a stated order with a generation and a second evaluation after each awaited step; its dispose mode keeps the tab reports except the error; tabs never shown take their mount time.
- Not adopted: unloading on hide at once, a save hook at unload, a page script for media, persisting the full session history, a cap on loaded hidden tabs before it is measured, unloading DOM tabs before a measured gain, ignoring `beforeunload` as a protection (a content world cannot see page listeners).
