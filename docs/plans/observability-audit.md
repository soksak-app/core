# Observability audit plan

[한국어](observability-audit.ko.md)

Status: pending proposal. The canonical task checklist is [features](../features.md) (F160, F161, F158, F159). This proposal records the result of the audit of 2026-10-11 and the decisions that the items implement; when an item is closed, its content moves to the specification and this text is removed.

## Proposition

Everything that happens is recorded in the event log ([logging](../spec/logging.md)). Each result of a test, success or failure, maps to a place in the logs. No source needs to change afterwards only to observe. Recording causes no performance problem. A criterion may change when the situation requires it, with the evidence in the related document; it is never lowered because a test is hard to meet.

## Result of the audit

The audit read the sources of core, of the sidecars and plugins, and of the verification; it ran nothing. The proposition is false today.

- **The checks prove names, not coverage.** `make events-check` finds each declared name as text in a source, so a comment satisfies it; it does not find an emitted name that is not declared, the required fields, or a source without an event. `scripts/check-fallbacks.mjs` demands a reason comment and sees only some forms (not an Objective-C observer, monitor, KVO or timer, a delegate, `return NO`, a Go `go` statement without `recover`, or a dropped channel).
- **Test results do not map to the logs.** No run identifier, test name or offset reaches a log. The runner keeps output in memory and prints a failure only. The audit `check-events.mjs --logs` runs by hand and not in CI, `auditLog` does not report an `error` event or the files of the sidecars, and the offsets file is overwritten at the end of each check. Stall files, crash reports and the standard error have no event.
- **No identifier links a chain.** `native.input.key_down` is not in the catalog and no layer assigns the identifier of an input. Two counts of `cids` differ (none in the 969,368 events of 25 files; 33,693 occurrences in the four log folders), so the audit script of F160.8 recounts them before the item is closed. A page command, a host call and a sidecar request, a window, a project, a change of settings and a plugin operation are matched only by surface and time.
- **Sources are silent.** Of about 36 registrations of observers, monitors, KVO and timers in the native library 13 are recorded. The Go host has about 21 `go` statements and no `recover()`. Endpoint methods are recorded only while the performance trace is on. Buffers of pending replies and closes grow without a bound. Only the terminal sidecar writes events; the two Go sidecars and the seven plugins have no catalog, no event file and no `cids`.
- **The performance of recording is designed, not measured.** No benchmark result is recorded; the input latency is never compared with recording on and off; the first responder is recorded on each frame with a dictionary on the main thread; the hex of `pty_read` allocates for each byte; `page.call` serializes all arguments before it cuts them.
- **The volume hides the signals.** 31 files of the host and the terminal sidecar hold 970,468 events (345.2 MB). By bytes `page.call` is 45.4%, `sidecar.vt.request` 19.1%, `native.input.query` 18.1% and `native.record.info` 6.5%; a log of 139,068 events (47.8 MB) holds `error` 0.0%, `warn` 0.4%, `info` 4.8% and `debug` 94.8%. The peak rate is 9,715 events/s, inside the bound of the queue. Rotation at 100 MB in 5 generations holds 19 to 23 hours on average and about 7 hours at the highest load; no file has yet reached rotation (the largest holds 48 MB). The disk has 18 GiB free (96% used), so keeping every file needs a stated budget.

## Decisions

Each decision states the reason, because a later reader must be able to judge it again.

0. **Record by value: every input and boundary crossing per occurrence, nothing that another record already states.** The log must answer what failed and why, which operation changed which object, which input became which output, and what was lost, without a later change of source, so nothing is excluded because nobody asked its question yet. The rule: a log holds every input and every crossing of a layer, a process, a window or a sidecar, per occurrence with its real time, and every decision and every failure. It may drop a repeated content (delta encoding), a derived copy or a narrative copy of a stored fact. It must not drop an occurrence. Delivery, delay and loss are observed only from the time of each occurrence (`native.input.query` has 363,445 records 16 µs apart, and a count would lose them). Replay is not the principle, because a window server, a native layer, sidecars and a page cannot be replayed; the principle is the boundary. Minimality is a redundancy test and not a question test: a record is excluded only when a script shows that it is derivable from other stored records or narrates a stored fact, and the derivable share of a standard scenario stays under 50% after delta encoding. Only a state snapshot is stored on change with a count of the repeats (`native.input.source_changed`, 99.7% repeats). An event is accepted by a case: the incident or question, the events that answer it, and a test that answers it from a fixture log. The incident corpus is the sufficiency test (each incident must be answerable) and never the minimality test, because it holds only past questions. Sampling and a trigger-kept ring never apply to a crossing; a ring is allowed only for detail beneath a summary that is always stored. Every record carries a real microsecond `ts_us` and `mono_ns` on every layer (the sampled `page.call` records are rounded to 1 ms today), and an input event without `cids` fails the guard.

1. **Decide by value, set levels by meaning, and reduce the cost at the producers.** A discard by minimum level would also give up the diagnosis of the stalled start of the editor page, which needed exactly a `debug` event (`page.call ready-1` without `loadFile`). The queue holds the measured peak, so a discard in the writer saves no cost; the cost is in the producers (the serialization in `page.call`, the dictionary of the first responder on each frame, the allocation for each byte in the hex of `pty_read`). Each producer builds its fields behind one gate `enabled(class, level)` with a builder function. Levels are defined by meaning (`error` a failure, `warn` a loss or degradation, `info` a decision or lifecycle, `debug` a crossing or input), and the event line stores `class` (schema 2) so that the class and not an extra numbered level divides `debug`; no new level is added. `error`, `warn` and `info` go to `host-<boot>.jsonl` and `debug` to `host-<boot>.debug.jsonl`. The log stays JSON lines and canonical. A closed generation may be written as framed zstd, which keeps a file searchable by frame through its index. Retention is per run and not per file: a total bound (6 GiB), the pin of a run with an unclassified failure (`.keep`), and the event `log.pruned` (files, bytes, time range) in the next file so that no deletion is silent. The guarantee after `kill -9` is stated as the batch interval (100 ms) of events at most. The class `frame` is stored per occurrence as compact segments of time, sequence, size and a hash of the frame; the frame content is not stored, because the terminal state derives from the stored `pty_read` and resize inputs by replay and the hash verifies the replay (decision 0). Its segments count in the total bound and have no budget of their own (the measured record is about 40 bytes, 26,883 records are about 1 MB). No ring is added: the queue (8192 events, 16 MiB) and the interval of 100 ms stay, and a loss is counted by `log.dropped`. A reader accepts only the current schema and rejects a file of schema 1 with an error that names the file and what it found; no file is converted, and an explicit prune command removes it.
2. **The structure must find a new silent source.** A guard that compares names passes a new silent source. One rule set per language lists each source of occurrences without an event or a stated reason, with no baseline, and each rule set belongs to the item of the entrance it covers. Registration APIs are allowed only in the entrance file (an exact rule); return paths are an approximate rule. The reason marker is one form: `(default|silent): <reason>`. A command that every repository calls applies the rules (`soksak-events`).
3. **A test result is a range of the logs.** The application under test serves many runs, so the run identifier is carried by the events `host.test.start` and `host.test.end` (layer prefix, test name, result) and not by `log.open`. `scripts/test-evidence.mjs` is extended and no second manifest is made. A flush barrier (`diagnostics.log.flush`) ends each test, and a position is `(boot, seq)` across generations and the debug file. A stall file of a stopped host cannot write a marker, so the test evidence entry links it. Output and evidence of a failed run are kept until a record classifies them, and the audit of the logs runs after each run and in CI.
4. **One entrance for each kind of source.** Native registrations, goroutines, endpoint methods, calls and plugin operations are recorded at one entrance each, so that a new source is covered without a record at each site.
5. **What is recorded must be findable.** The JSON lines log is canonical and append-only; beside each file a segment index (`.idx`, with Bloom filters for event, surface, session, `cids` and run, and time ranges) is built incrementally. The host answers a query by time range, level, class, layer, event name, surface, session, `cids`, run and text with one page and a cursor. The debug view, `sok`, the judgment of each test (F160.16) and the audit use that one query; the page never loads a file (F157).
6. **A number closes a performance item.** The numbers of the benchmarks, the input latency with the gate on and off, the allocations, the bytes per minute of each tier and the hours of retention are recorded in the logs and compared with the budget; the budget changes only with its evidence.

## Verification

A guard shows its Red by failing on a source or an event that a test adds on purpose. A run is judged by its manifest, the markers and the audit of the logs, with no undeclared `error`. A source is observed in both applications. A performance item is closed by recorded numbers. A closed item is not reopened; a missing observation becomes a follow-up item.

## Adversarial review

The decisions above are reviewed by agents that argue against them and propose solutions, repeatedly, until no objection remains. The objections, the answers and the resulting changes are recorded here.

### Round 1

Four reviews: levels and the class `frame`; storage of the index; guard and test mapping; the definition of a right log. Their verdicts: objections remain. The answers are in the decisions above; the changes follow.

| Objection | Answer |
| --- | --- |
| The retention of about 7 hours, the peak of 1,500 events/s and "no `cids`" were stated wrongly. | Corrected in the audit: 19 to 23 hours on average, 9,715 events/s, and the count of `cids` is open until recounted. |
| "Keep every file" has no budget on a disk with 18 GiB free. | Retention per run with a total bound and the pin of unclassified failures (decision 1). |
| A guard without a baseline cannot close at its first item. | Rule sets per language, belonging to the item of the entrance; one reason marker (decision 2). |
| The run identifier in `log.open` is wrong when an application serves many runs. | `host.test.start` and `host.test.end`, extension of `scripts/test-evidence.mjs`, flush barrier, position `(boot, seq)` (decision 3). |
| A stopped host cannot write a marker. | The test evidence entry links the stall file. |
| Change-only storage loses delivery and delay of inputs; question-based minimality hides the evidence of the next incident; an incident corpus used for minimality is circular; sampling drops the rare failure. | Decision 0 rewritten: per occurrence for inputs and crossings, redundancy test, corpus only as sufficiency test, no sampling of crossings. |
| `ts_us` of `page.call` is rounded to 1 ms and `mono_ns` is missing on page and native events; an input has no `cids`. | Real microseconds and `mono_ns` on every layer; a guard fails an input without `cids`. |
| Measured on 970,468 events, 10.3% of the bytes are exact repeats, and about 51% is redundant content (repeated paths of `sidecar.vt.request`, arguments of `page.call`, nested state of `native.record.info`, repeats of `native.input.query`). | Delta encoding, a hash reference for large arguments, `root` and `owner` stored once per connection. The estimate of a result under 50% is a model; the item F160.20 measures it with a real writer. |

Incidents answered from the logs: 3 of 9 fully (editor start, sidecar restart, `loadFile` loss), 3 partly (page stop, input duplication, undeclared errors), 3 not (frontmost application, modal geometry, the 120 s wait of a Tauri test). The gaps are the chain of an input, the markers of tests, files outside the event contract (stall files, standard error such as the `installed.json` error) and geometry; they are inputs to F160.8, F160.12, F160.15 and F160.24.

Open objections: the producer cost of the delta writer at 16 µs input spacing (not measured); whether the content of `exposureReply` is derivable (not checked); no log evidence for the 120 s test wait.

Decisions taken by the rules and the measured facts, with no question to the person: a `frame` segment stores a hash and the replay derives the content; the segments have no budget of their own; the ring and the drain keep their bounds; a file of schema 1 is rejected and removed by the prune command (decision 1). Each is open to the next round of the review.
