# 캡처 연결 plugin

[English](capture-connector-plugins.md)

## 문제

연결 plugin은 embed protocol로 애플리케이션을 보이는데, 이것은 애플리케이션 안에 어댑터가 있어야 한다. 자기 배포에 어댑터가 없는 애플리케이션은 보일 수 없고, 다른 쪽 애플리케이션의 어댑터는 그쪽이 넣을 때만 생긴다. 그래서 대부분의 애플리케이션에는 surface로 들어오는 길이 없다.

## 방식

연결 plugin은 어댑터 없는 애플리케이션을, 그 애플리케이션의 창을 캡처하고 카드의 입력을 그 창에 보내는 방식으로 보인다. 애플리케이션은 자기 배포로 그대로 실행되고, plugin은 그 안에 아무것도 필요하지 않다. embed protocol은 복사 없이 그리고 입력을 정확히 받으므로, 어댑터를 가진 애플리케이션의 경로로 남는다.

- 캡처: 애플리케이션 sidecar가 ScreenCaptureKit으로 애플리케이션 창을 캡처하고, embed 경로처럼 그 frame을 카드의 image region에 준다.
- 입력: sidecar가 카드의 pointer, wheel, key 입력을 플랫폼의 접근성 API와 event API로 그 창에 보낸다.
- 창: 애플리케이션 창은 보이는 화면 밖에 있고 카드의 크기를 따른다.
- 권한: 화면 기록과 접근성. plugin 화면은 없는 권한을 그것을 이름하는 오류로 밝힌다.

## 관문

plugin 종류를 명세하기 전에 시제품이 embed 경로와 같은 관문을 어댑터 없는 애플리케이션에서 잰다: native pointer 이동에서 그것을 보이는 첫 캡처 frame까지의 지연과 재생 중 frame 간격. 60 Hz에서 지연 median이 50 ms 안에, frame 간격 p99가 34 ms 안에 있으면 이 방식을 채택한다. 그렇지 않으면 이 제안은 잰 값을 기록하고 닫힌다.

## 순서

1. 애플리케이션 sidecar의 시제품과 관문 검사. 측정값을 기록한다.
2. 관문을 통과하면: 캡처 경로의 명세, 그것을 고르는 manifest 필드, 권한을 위한 plugin 화면.
3. 캡처 경로로 예시 동영상 편집기의 연결 plugin.
