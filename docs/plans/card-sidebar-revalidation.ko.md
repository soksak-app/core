# 카드 사이드바 구현 및 재검증 계획

상태: 방향 승인, 구현과 실제 애플리케이션 인수 검증은 미완료. 단일 작업 체크리스트는 [기능](../features.ko.md)에 있다. 이 제안서는 미완료 작업을 설명하며, 반영한 계약은 명세에 둔다.

## 요구 모델

카드는 콘텐츠와 선택적인 상단·하단·좌측·우측 사이드바를 포함한다. 각 사이드바는 순서가 있는 섹션 세트를 표시한다. 플러그인은 섹션, 기본 세트, 기본 위치 지정을 제공한다. 코어는 고정된 네 방향 배치, 크기 조절, 접기, 저장, 네이티브 배치와 입력을 담당한다. 사용자가 임의로 정의하는 카드 그리드는 도입하지 않는다. 상단과 하단은 콘텐츠 영역의 전체 너비를 차지하고, 좌측과 우측은 중앙 양옆에 배치한다. 없는 위치는 공간을 예약하지 않으며 콘텐츠는 남은 영역을 채운다.

카드에 명시적으로 지정한 세트는 활성 탭의 플러그인이 바뀌어도 유지한다. 명시적 지정이 없으면 활성 플러그인의 기본값을 사용한다. 기본값에서 파생된 사이드바를 접거나 크기를 바꾸면 배치 상태만 별도로 저장하며 명시적 세트 지정은 생성하지 않는다. 명시적 지정을 해제하면 기본값이 드러난다.

선택적인 플러그인 `sidebars` 선언은 세트와 네 방향의 기본 세트 ID를 지정하는 `card` 매핑을 포함한다. 로컬 ID는 `<plugin>.<local>`로 정규화한다. 세트는 매니페스트를 통해 설치된 다른 플러그인의 선언된 섹션을 조합할 수 있다. 기존 애플리케이션·전역·프로젝트의 전체 목록 재정의를 적용하기 전에 기본값을 환경의 세트와 링크로 정규화한다. 조회 과정에서 재정의로 제거한 기본값을 다시 삽입하지 않는다.

섹션의 `module`은 공용 모듈 문자열 하나 또는 `horizontal`과 `vertical` 경로를 모두 포함하는 객체다. 코어는 상단·하단에 가로 모드, 좌측·우측과 창 사이드바에 세로 모드를 선택한다. 컨텍스트와 노출 상태는 방향을 포함한다. 방향이 바뀌면 기존 구현을 해제한 뒤 새 구현을 마운트한다. 잘못되거나 누락된 선언은 명시적 오류로 거부하며 대체 경로를 두지 않는다. 목록과 탭 배치는 유지하고 배열 방향과 남은 공간 할당은 코어가 담당한다.

명령은 방향 인자를 받는 `core.card.sidebar.set`, `core.card.sidebar.toggle`, `core.card.sidebar.size`로 통일한다. 별도의 패널 및 좌측 인셋 경로를 제거한다. 각 방향의 유효 세트, 크기, 접힘 상태, 방향과 측정 가능한 좌표를 노출한다.

포커스에 따라 이동하는 외부 flow/pin 배치와 특수 레일 식별자를 제거한다. 레일은 플러그인이 지정한 창 좌·우 사이드바와 연관 카드의 보더라인으로만 유지한다. 붙어 있으면 하나의 외곽선을 그리고 떨어져 있으면 각각의 외곽선을 그린다. 고정된 창 사이드바는 포커스나 활성 탭 변경만으로 위치·너비·표시 여부가 바뀌면 안 된다. 오래된 설정과 ID는 호환 경로 없이 거부한다. 정식 명세에 연관 관계와 인접 판정 기준을 정의한다. 보더라인 결합은 어느 쪽도 이동하거나 크기를 바꾸지 않는다.

## 실행 순서

1. 기존 미커밋 패치를 보존하고 분리한다. 네이티브 레지스트리 수명, Wails 픽스처 준비 상태, 합성기 배치 문제를 단일 체크리스트에 각각 등록한다. 최초 실패를 보존한다. 현재 합성기 테스트의 미선언 `inset` 입력은 실제 관측 계약으로 교체한다.
2. 네이티브 레지스트리 수명 결함을 소유 모듈의 수정 전 Red, 동일 테스트의 Green, 양쪽 재빌드 호스트의 신규 터미널 분할 관측으로 해결한다. Wails 준비 상태는 이 결함 때문이라고 단정하지 않고 별도로 진단한다.
3. V5-117-1을 구현한다. 카드 사이드바의 단일 모델, 플러그인 기본값, 독립 배치 상태, 통합 명령과 포커스 의존 외부 배치 제거 및 붙음·분리 상태의 레일 보더라인을 포함한다. 최종 모델을 기준으로 V5-116-4의 링크 기반 동작을 재검증한다.
4. V5-117-2를 구현한다. 방향별 선언, 검증, 스테이징, 선택, 수명주기, 컨텍스트와 실제 렌더링 출력을 포함한다.
5. V5-115-1의 좌표와 전체 제스처 녹화, V5-116-5의 계약 및 조합, V5-114-1의 실제 이벤트 주소창 포커스 재검증을 완료한다. 활성화 단계 검증에는 기존 승인 요구를 유지한다.

## 인수 증거

소유 모듈 테스트는 기본값, 명시적 지정 우선순위, 탭 변경, 독립적으로 저장한 접기·크기 상태, 잘못된 입력의 상태 보존, 두 모듈 선언 형태, 스테이징 거부, 해제 수명주기와 선언된 경계를 통한 플러그인 간 섹션 조합을 검증해야 한다.

양쪽 호스트를 재빌드하고 검증한 바이너리와 사이드카를 식별한다. 요청한 60 fps로 전체 제스처를 관측하고 사이드바·DOM 슬롯·네이티브 좌표의 기계 판정 검증을 도출한다. 누락 프레임이나 입력은 인수 실패다. 포커스와 탭 변경은 창 사이드바 좌표를 유지해야 하며 설정 변경은 별도로 검증한다. 붙음·분리 상태의 보더라인 경계를 측정하고 두 요소의 좌표가 바뀌지 않는지 확인한다. 실제 이벤트 포커스 검증은 브라우저 주소창 포커스 전환 0회와 대상 네이티브 응답자를 확인한다. 검증 녹화는 확인 후 제거한다.

이전 커밋과 구조 검사는 애플리케이션 성공을 입증하지 않는다. 모든 최초 실패를 보존하고 네이티브 단위 테스트 성공과 실제 애플리케이션 인수를 구분한다. 증거가 없는 항목은 미해결이다. 실제로 검증한 구현에 맞춰 명세, 대응 번역, 체크리스트 증거와 변경 이력을 갱신한다.
