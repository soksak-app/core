# Rendered document reference

This diagnostic contract is part of F696. It does not close the OCR consumer or platform verification gates. Renderer producer owners, host compilation, native capture owners, actual captures, and consumer conversions have separate evidence.

`diagnostics.capture.document-reference` accepts `{window, surface, document, requestId}`. `document` is the exact registered name, including `""` for a root. `requestId` is a positive JavaScript safe integer. Undeclared fields, including expected text and caller-supplied generation, are rejected. A missing attached document never selects the root instead.

The operation requires an active `frameIdentity: true` reference recording after the measured interval. The host resolves the actual live view generation and exact native document, selects that source through the existing capture identity lifecycle, and installs the document producer. Root-only identity capability remains a separate entry. Capture-stop owns pending start, freeze, and removal, including requests that time out.

The native boundary validates numeric carriers before reading them: `schemaVersion` is exactly the number 1, the echoed `requestId` equals the original positive safe integer, and `revision.value` is a positive safe integer. JSON null, objects, arrays, strings, booleans, fractions and out-of-range values are errors; booleans are not accepted as numbers through Foundation bridging. Invalid metadata completes once through the worker bridge and releases its exact provider lease before publishing a native snapshot. The native observation keeps its existing 10.0-second deadline through the central `sp_observe_timer` entrance (`document.reference.timeout`); completion invalidates and releases that timer.

The document renderer owns the public page provider `soksakRenderedReference`, version 1. It has `observe({requestId})`, `validate({requestId, revision})`, and `release({requestId})`. One request leases the producer until its exact owner releases it. Observation does not accept consumer criteria. Disposal, renderer replacement, a changed document revision, or changed geometry invalidates the observation. A released pending observation cannot later return success. The revision domain is a nonempty provider-owned string; the host carries it and its positive safe-integer counter unchanged to that same provider's validate method, without branching on renderer names.

DOM producers derive actual text and grapheme rectangles from the renderer-owned DOM root using browser Range and layout APIs. Their revision is `{kind:"dom-layout", value}` and source kind is `native-document`. Editor passes its actual CodeMirror `contentDOM`; automation does not discover editor internals through selectors. The controlled Browser document loads the canonical SDK provider itself. DOM metadata is not physical presentation or glyph-pixel proof.

HWP uses the Studio CanvasKit renderer. The actual draw collects its semantic glyph metadata and immutable PNG before releasing the native CanvasKit objects, with document generation and paint revision fenced across encoding. Its adapter reports `{kind:"canvaskit-paint", value:drawRevision}`, source kind `renderer-png`, and the actual encoded PNG. Visible-page selection must identify exactly one actual visible rendered page; zero or multiple visible pages are errors rather than an implicit choice of page zero. Studio dependency pin, delivery, and platform proof remain explicit gates.

After observation the native owner freezes the actual document identity producer, waits for the target WebKit update, and takes a standard snapshot of that exact native document. The source tuple comes from decoding a complete QR inside the native snapshot against the actual issued payload set. The provider revision and global native geometry must still match after snapshotting. The native PNG remains on failure, including QR decoding failure; producer data is never replaced with expected text or fabricated identity fields.

Artifacts belong to the returned private directory under the workspace capture directory. `native.png` is the actual native snapshot; `renderer.png`, when provided, is the renderer's actual PNG. The manifest records the request, producer metadata, source digest and pixel dimensions, global geometry, and decoded identity/QR ROI. The caller tracks the artifact directory for failure retention. Original recording evidence is immutable.

A consumer must join the reference to the actual recording by exact target, source generation, region, decoded tuple, digest, scale, and geometry. It must prove selected glyph and guard pixels against actual captured pixels, exclude every QR-overlapping selected cell, and retain the original failure when equality fails. QR identity, DOM text, renderer state, or a final ROI alone is insufficient. There is no OCR, tolerance, mask, or state-only fallback.

Go and Rust expose the same transaction boundary. A platform without its native implementation returns an explicit unsupported error. Such an error is not cross-platform completion; Linux, Windows, CI recording, and actual application proof must each be recorded before the corresponding gate closes.
