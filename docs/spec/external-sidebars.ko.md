# 외부 창 사이드바

[English](external-sidebars.md)

창 검증, 독립 설정 선택, 안정적인 워크벤치 카드, 저장 소유자/폭 상태, 실제 그린 경계선 묶음은 V5-117-1-3-2와 V5-117-1-3-3에서 구현한다. 기존 플러그인 left/right, null 상속, 위치 설정, 저장 레일 입력은 명시적으로 거부한다. 세 앱 환경은 창 링크를 사용한다. 완전한 녹화 실창 인수는 [기능](../features.ko.md)의 V5-117-1-3-4에서 미완료이며 구현 검사가 그 범위를 완료하지 않는다.

## 선언과 선택

플러그인은 `sidebars.window` 객체에서 `left`, `right`를 자신의 `sidebars.sets`에 있는 로컬 세트 ID로 지정할 수 있다. 각 변은 생략할 수 있다. 알 수 없는 변, 객체가 아닌 매핑, 없는 로컬 세트를 거부한다. 창 사이드바에는 표면이 필요하지 않으므로 섹션 전용 플러그인도 선언할 수 있다. 기존 `sidebars.card`는 카드 내부 네 변을 지정하며 표면을 요구한다. 창의 변과 카드의 변은 독립적이고 공존할 수 있다.

창 기본값을 `{place: "window-left" 또는 "window-right", plugin: "<plugin id>", set: "<plugin>.<local set>"}`로 정규화한다. 명시적 환경 사이드바 목록은 정규화된 기본값을 대체하고 저장 목록은 해당 유효 목록을 대체한다. 덮어쓰기가 출력을 대체해도 선언을 검증한다.

일반 창 링크는 `{place: "left" 또는 "right", plugin: null, set}`를 유지한다. 플러그인 창 링크는 `window-left` 또는 `window-right`, 등록된 플러그인 ID, 알려진 세트 ID만 사용한다. 링크가 없으면 해당 사이드바가 없다. `core.settings.link`는 두 종류 창 링크에 세트 ID 또는 링크를 제거하는 `off`를 받으며 `inherit`는 거부한다. 포커스 의존 일반 상속이나 플러그인 `set: null`은 없다. 기존 플러그인 `left`/`right` 형식과 모든 레일 링크를 명시적으로 거부한다. 카드 변 링크는 독립 계약을 유지한다.

일반 설정 페이지에는 좌우 표시 스위치와 일반 창 세트 선택이 있다. 각 플러그인 페이지에는 창 두 변의 선택이 있고 표면이 있으면 카드 네 변의 선택도 있으며 알려진 세트와 사용 안 함을 제공한다. `cardSidebar` 위치 설정과 flow/pin/inset/off 컨트롤을 제거한다. 카드 사이드바는 항상 카드 내부에 있으며 카드 변을 끄는 조작은 세트 선택으로 한다.

## 식별과 배치

구성된 창 사이드바 각각은 섹션을 담은 카드이며 레일 개체가 아니다. 일반 사이드바 카드 ID는 `left`, `right`이고 플러그인 사이드바 카드 ID는 `window:<plugin>:<side>`다. 이 ID는 내용 카드에 사용할 수 없다. 창 사이드바 카드는 표면 탭이 없고 세로 섹션 구현을 사용한다.

구성된 창 사이드바 카드는 포커스 카드, 활성 탭, 선언 플러그인의 탭 존재 여부와 독립적으로 존재한다. `left`/`right` 표시 스위치는 해당 변의 모든 창 사이드바를 숨기되 저장 폭, 섹션 선택, 연결 대상을 유지한다. 명시적인 링크 또는 표시 변경만 창 사이드바 열의 존재를 바꾼다. 전체화면은 기존 [전체화면 계약](example-model.ko.md#카드-전체-화면)에 따라 다른 카드를 잠시 숨기며 복귀하면 저장 배치를 돌려준다.

창 사이드바 카드는 선언한 가장자리의 고정된 전체 높이 열에 배치한다. 각 가장자리에서 일반 사이드바가 가장 바깥이고 그 안쪽으로 환경 플러그인 순서대로 플러그인 사이드바가 선다. 사이드바 폭은 저장 폭을 사용하고 새 사이드바는 선언된 초기 폭을 사용한다. 내용 카드는 남은 영역을 나눠 쓴다. 포커스로 위치·폭·표시·세트를 결정하지 않는다. 여러 플러그인이 같은 변을 선언해도 서로 대체하거나 조용히 버리지 않는다.

## 연결 대상과 레일 경계선

각 플러그인 창 사이드바는 공간의 `windowSidebars` 레코드에 사이드바 카드 ID를 키로 하여 `{width, owner}`를 보관한다. `width`는 유한한 양의 포인트 값이고 `owner`는 탭 ID 또는 null이며 일반 사이드바 레코드는 null을 사용한다. 처음 만들 때 저장 카드 순서와 탭 순서로 선언 플러그인의 첫 탭을 연결하며 없으면 null이다. 유효한 저장 소유자는 비활성이어도 유지한다. 연결 카드는 그 탭을 포함한 카드다. 포커스나 활성 탭 변경은 연결 대상을 바꿀 수 없다. 일반 사이드바에는 연결 대상이 없다.

소유 탭을 다른 카드로 이동하면 그 카드로 연결 대상을 바꾼다. 소유 탭을 닫으면 저장 순서로 선언 플러그인의 남은 첫 탭을 선택하고 없으면 null로 둔다. 연결 없는 사이드바에 해당 플러그인의 첫 탭을 추가하면 연결한다. 이 조작들은 구조적 탭 조작이며 외부 사이드바를 제거하거나 크기를 바꾸지 않는다. 연결 변경을 공간과 함께 저장한다. 잘못된 레코드, 알 수 없는 사이드바 ID, 잘못된 폭, 존재하지 않는 소유 탭, 다른 플러그인의 소유 탭을 거부한다. 잘못된 저장 데이터를 그럴듯한 소유자 선택으로 고치지 않는다. 오래된 레일 카드·폭·위치 설정은 마이그레이션이나 별칭 없이 거부한다.

창 섹션 컨텍스트는 연결 카드 ID와 소유 탭 ID를 `context.card`, `context.surface`로 사용하며 연결 없는 사이드바와 일반 사이드바는 둘 다 null이다. 다른 활성 탭을 선택해도 섹션 대상을 바꾸지 않는다. 선언된 상태 모듈의 기존 우선순위는 유지한다. 상태 등록이 없고 소유 표면을 사용할 수 없으면 포커스로 다른 표면을 선택하는 대신 null 상태와 명시적 명령 오류를 제공한다. 소유 탭이 없거나 연결 카드에서 비활성이면 `unavailable`을 공개한다. 전송 등록은 노출 레지스트리가 별도로 검사한다.

레일은 연결된 내용 카드와 외부 사이드바 카드를 묶는 경계선만 뜻한다. 준비 중 격자나 포커스 카드가 아닌 실제로 그린 사각형에서 외곽선을 계산한다. 같은 카드에 연결된 모든 외부 사이드바를 묶는다. 선언된 배치 간격을 사이에 두고 사각형이 붙으면 외곽선 하나를 그리고 다른 카드가 사이에 있어 떨어지면 각 연결되지 않은 대상에 별도 외곽선을 그린다. 연결 없는 사이드바는 일반 카드 경계선을 유지하며 레일 외곽선이 없다. 포커스 표시는 독립적이다.

`core.rail`은 합친 경로와 `groups` 배열을 공개하며 각 항목에 연결 카드 ID, 사이드바 카드 ID 목록, 경로, 외곽선 루프를 담는다. `core.sidebars`는 창/카드 위치, 선언 플러그인 또는 null, 연결 카드와 소유 탭 또는 null, 세트, 방향, 실제 그린 사각형을 공개한다. 이 선언 상태는 기하와 픽셀 검증에 필요하다.

## 인수

- 소유 plugin-api 검사로 구현 전 창 선언·정규화·기존 링크 거부·독립 카드/창 선택 Red를 만들고 구현 후 같은 검사의 Green을 확인한다.
- 소유 workbench 검사로 포커스/탭에 따른 열 변경 Red를 만든다. 선언된 소비자 경계에서 같은 변의 여러 플러그인, 저장 연결 유지, 구조적 탭 이동·제거, 폭 복원, 잘못된 저장 데이터, 붙음·분리 외곽선 루프를 검증한다.
- 양쪽 재빌드 호스트에서 포커스 변경과 다른 플러그인 탭 선택 전후 외부 사이드바와 내용 카드 기하를 동일하게 유지한다. 전체 네이티브 기록에서 실제 섹션 출력·연결 대상·단일 외곽선과 분리 외곽선을 좌표·픽셀로 측정한다.
- 전체화면과 복귀, 다시 불러오기 후 설정 저장, 완전한 포인터 입력·프레임 기록, 기록 정리를 측정한다. 기존 외부 검사의 34ms 지연·정렬 기준을 낮추지 않고 오래된 픽스처를 정리한다. 소유 검사 통과만으로 실창 인수나 릴리스 적용을 완료하지 않는다.
