# Host contract cases

[한국어](host-contract.ko.md)

The Wails host (Go), the Tauri host (Rust) and the mygo host (Go) implement one host contract ([native hosts](hosts.md)). This document lists the contract cases that the hosts must execute, so that a behavior tested in one host is tested in the others.

## Declaration

Each host test function declares the cases it executes on a line directly above the function, or above its test attributes in Rust:

```go
// contract: endpoint.transport.invalid-json-closes
func TestEndpointClosesOnInvalidJSON(t *testing.T) {
```

```rust
// contract: endpoint.transport.invalid-json-closes
#[test]
fn invalid_json_closes_connection() {
```

A test function may declare several cases, separated by commas. Every selected test function in the fifteen declaration paths declares at least one case: `packages/host/go/tests/`, `packages/host/go/src/*_test.go`, `packages/host/wailsv3/tests/`, `packages/host/wailsv3/src/*_test.go`, `packages/host/mygo/tests/`, `packages/host/mygo/src/*_test.go`, `packages/host/mygo/benchmark/`, `packages/sok/go/tests/`, `packages/sok/go/src/*_test.go`, `packages/host/rust/tests/`, `packages/host/rust/src/`, `packages/host/tauriv2/tests/`, `packages/host/tauriv2/src/`, `packages/sok/rust/tests/` and `packages/sok/rust/src/`. A test declares a case only when its assertions check the case's outcome. For Go, the declaration inventory is the union of `_test.go` files selected by `go list` for each configured host-contract run on the current `GOOS` and `GOARCH`; a file excluded from every configured run is not part of this platform's host-contract inventory. Shared contract text lives in `docs/spec/cases` (the manifest case table and the log-contract fixtures), which no package owns: a test reads it there, and `make check-boundaries` refuses a test of a core package that reads a path of another core package.

## Check

`make test-hosts` runs each host's tests in the default configuration and in the diagnostics configuration (Go tag `diagnostics`, Rust feature `diagnostics`) through the command supervisor and reads the reported results. The runs of the mygo host add the tag `mygo` to each tag set: `packages/host/go` and `packages/host/mygo` with `mygo` and `diagnostics mygo`, and `packages/sok/go` with `mygo`, `diagnostics mygo` and `diagnostics dev mygo`. It fails when:

- a case in scope for a host has no passing test in that host;
- a declared test ran in no configuration, or failed or was skipped in one;
- a test declares no case, an undefined case, or a case outside its host's scope;
- a declaration is not attached to a test function;
- a host run reports zero tests;
- a Rust leaf name (the last segment of a test's module path) appears twice among the tests of one crate in one run, whatever targets hold them, so that a declaration names one test;
- a declaration's attribute block holds an attribute other than `#[test]`, `#[tokio::test]`, `#[cfg(feature = "...")]` or `#[cfg(not(feature = "..."))]`. The block is the contiguous attribute and comment lines above and below the declaration, and the failure names the file, the line and the attribute.

Owner rule: a declared test takes its result only from the items of its own owner. The owner of a Go test is its package directory, and the owner of a Rust test is its crate directory (the nearest ancestor folder of the file that holds `Cargo.toml`). Results are keyed by run, owner and test name, and a host's results never count for a sok declaration, or the other way round. A Rust declaration matches the one test whose leaf name equals its name.

The scope column is `all`, or `<host>[, <host>] only: <reason>` for behavior that exists only in the named hosts. The hosts of the check are `wailsv3`, `tauriv2` and `mygo`, each of them runs every `all` case, and a scope names only these hosts. A host joins them together with its own contract run, because from then on every `all` case counts for it. A case that a language host library implements without the framework port is declared by a test of the library and counts for each host of its scope that links the library. Both Go hosts run the tests of the Go language host library and of the Go `sok`, so such a test may declare a case of either Go host, and only the hosts of the case count it; a case whose behavior passes through `Framework` or `Frontend` is declared by a test of each framework adapter of its scope ([host tree](hosts.md#host-tree)). No case that a language host library declares begins with a host name; the scope names the hosts. The check runs on macOS, the only platform that the hosts implement; Windows and Linux entry points return `not implemented` errors and have no cases. The unit tests of the check (`scripts/test/test-hosts.test.mjs`) inject each failure and run in `pnpm test`.

## Application menu

Both hosts build the application menu from one table, so a menu item present on one host and absent on the other is a defect. The `title` items take their titles from the selected language; `system` items keep the framework-provided title (the bundle declares the table's languages as localizations, so system-managed titles follow the same language). Keys use the `host.menu` report format. The supported languages are the table's language columns — `ko` and `en` today, extended by adding a column together with the workbench language declaration. The language is the 일반 setting `language`: `auto` follows the system language's primary tag matched against the supported set, and an unsupported system language falls back to the default language `en`; the page pushes the effective language to the host (`set_menu_language`) before first use and on every change, and before that push the host builds the menu from the system language with the same matching and fallback.

## Workbench cases

The main page of the Wails and Tauri hosts and the workbench of the mygo host each answer the view calls of project data, so the page test and the mygo test of one behavior declare one case with the line `// contract: <id>` directly above the test. The test inventory check (`scripts/check-tests.mjs`) fails when a case has no test on one side, when a test in `packages/workbench-mygo/tests/` declares a case that the table does not have, or when a declaration is not attached to a test.

| Layer | Code of these cases | Tests |
| --- | --- | --- |
| Main page (Wails, Tauri) | `packages/workbench/plugin-data.js`, `packages/workbench/projects.js` | `packages/workbench/test/` |
| Workbench of the mygo host | `packages/workbench-mygo/src/project_data.go` | `packages/workbench-mygo/tests/` |
| Go host, Rust host | None: a patch stores the `plugins` object that it carries, and neither host reads a key inside it; `workspace.projects.plugin-data-patched` covers that | None |
| SDK | `packages/plugin-api/view.js`: `runtime.data.change`, one for every host | `packages/plugin-api/test/view.test.mjs` |

The cases of this section:

| Case | Behavior |
| --- | --- |
