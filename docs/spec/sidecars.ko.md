# 사이드카

[English](sidecars.md)

사이드카는 셸 세션처럼 한 영역의 기능을 담은 네이티브 프로세스다. 플러그인은 네이티브 호스트를 통해 사이드카를 사용하고, 호스트는 메시지를 전달하되 본문을 해석하지 않는다. 사이드카 구현 하나를 Wails와 Tauri가 함께 사용한다.

## 선언과 시작

플러그인은 페이지가 사용하는 사이드카를 `plugin.json`에, 네이티브 애플리케이션은 실행하는 사이드카를 `environment.json`에 나열한다([플러그인](plugins.ko.md)). 호스트는 포함된 프런트엔드에서 `environment.json`을 읽는다. 페이지가 선언된 사이드카에 처음 요청을 보내면 애플리케이션 실행 파일과 같은 디렉터리의 `soksak-<이름>` 실행 파일로 사이드카를 시작한다. Makefile이 각 사이드카를 빌드해 그 디렉터리에 복사한다. 선언되지 않은 사이드카에 대한 요청과 호스트가 사이드카를 종료한 뒤의 요청은 실패한다.

## 메시지

메시지 하나는 한 줄의 JSON 객체다.

| 방향 | 메시지 |
| --- | --- |
| 호스트 → 사이드카 | 페이지 요청은 `{"surface": id, "root": 경로, "body": 값}`. `root`는 표면을 소유한 창의 프로젝트 디렉터리다 |
| 호스트 → 사이드카 | 표면이 제거되거나 그 창이 닫히면 `{"surface": id, "closed": true}` |
| 사이드카 → 호스트 | `{"surface": id, "body": 값}` |

호스트는 표면에 처음 요청을 보낸 창을 기록하고, 사이드카 메시지를 그 창에만 `sidecar-message` 이벤트 `{sidecar, surface, body}`로 전달한다. 다른 창이 같은 표면에 보낸 요청은 실패한다. 애플리케이션이 종료되면 호스트는 각 사이드카의 표준 입력을 닫고 프로세스 종료를 기다린다.

## 페이지 인터페이스

`page.sidecar(name)`은 `send(surface, body)`와 `on(surface, fn)`을 반환한다. `on`은 구독 등록 후 완료되는 promise를 반환한다. 페이지는 첫 요청 전에 구독한다.

## shell

`sidecars/shell`은 표면마다 셸 프로세스 하나를 표면의 프로젝트 디렉터리에서 실행한다. 셸은 `$SHELL`이며 설정되지 않았으면 `/bin/sh`(Windows는 `%COMSPEC%` 또는 `cmd.exe`)다. 대화형으로 실행하지 않는다.

| 본문 | 동작 |
| --- | --- |
| `{"op": "open"}` | 표면의 셸을 시작한다. 실행 중인 셸에 대한 요청은 아무것도 하지 않는다 |
| `{"op": "write", "data": 텍스트}` | 셸의 표준 입력에 `텍스트`를 기록한다 |

사이드카는 출력 줄마다 줄바꿈을 포함한 `{"text": 줄}`을, 실패한 요청마다 `{"error": 메시지}`를 보낸다. 닫힌 표면의 셸은 종료한다. 표준 입력이 닫히면 모든 셸을 종료하고 끝난다.

## 테스트

각 사이드카는 자기 디렉터리에서 프로토콜을 검사한다(`shell`은 `go test ./...`). 각 호스트는 fake 사이드카 실행 파일로 전달을 검사하고 실제 사이드카를 실행하지 않는다.
