# Logging

[한국어](logging.ko.md)

This document is the contract of the records that the application writes about itself: what an event is, which classes of events exist and how each is stored, how a writer behaves, which files hold the events, and how events are declared and checked. [Diagnostics](diagnostics.md) lists the failure points and the files of `logs/`; [debug](debug.md) shows the files. The work that brings the implementation to this contract is [the observability plan](../plans/observability.md), and the parts that are not implemented are marked in [features](../features.md).

## Principles

1. **One event contract.** Every record of every layer is one event of the structure below. There is no second format. Text that a person reads is made from events by a viewer; it is not stored.
2. **A producer never blocks.** The UI thread, the input path and the frame path do no disk access, no IPC, no lock wait and no call from a thread of one runtime into another runtime to record. A disabled event costs one branch; an enabled event costs one copy into a bounded queue.
3. **Loss is counted and stated.** No queue, rate limit, rotation or truncation drops silently. Each loss is recorded as a `log.dropped` event, and every bound is stated in this document.
4. **The input path is complete.** Events of the class `input`, and the PTY writes and reads of the class `io`, hold every value and every byte that the layer saw. The only bound on their size is the size bound of an event ([Bounds](#bounds)), which is far above the size of an input; the writer stores a larger event cut and marked `truncated`, because the queue refuses an event larger than its byte bound.
5. **Events are declared.** Every event has an entry in the catalog of the repository that emits it. Development and continuous integration reject an undeclared event. At run time an undeclared event is still written, with the marker `undeclared`, and counted, so a naming error never drops evidence.
6. **Events of one kind enter at one entrance.** Page-to-host calls, window and application events, registry commands, sidecar lifetime and the display of errors each have one entrance that records. A call site does not write its own record for them.
7. **Records state facts.** An event states what happened, with the values at that time. It does not state who asked for it or why a person did it.

## Event

An event is one JSON object on one line:

```json
{"ts_us":1791500000000000,"mono_ns":123456789012,"seq":812,"level":"info","layer":"native",
 "event":"native.input.key_down","window":"w1","surface":"tab-x","session":"s7","cids":["b3.1042"],
 "fields":{"keyCode":36,"characters":"\r"}}
```

| field | meaning |
| --- | --- |
| `ts_us` | The wall clock in microseconds since the epoch at the occurrence. It orders events across layers. Every line has it. |
| `mono_ns` | The system-wide monotonic clock in nanoseconds at the occurrence: `clock_gettime_nsec_np(CLOCK_UPTIME_RAW)` on macOS, which is `mach_absolute_time` in nanoseconds (`CLOCK_MONOTONIC` on Linux). It is comparable across processes of one boot, does not step, and does not advance while the machine sleeps. Every line has it, and the audit refuses a line without it. The page derives it from the clock of the host ([Writers](#writers)). |
| `seq` | An integer assigned by the writer of the process when it serializes the event. Stored events of one process have consecutive `seq`; a gap is explained by a `log.dropped` event that names the range of the missing `seq` and is itself stored after the range it names. |
| `level` | `error`, `warn`, `info`, `debug` or `trace`. |
| `layer` | `native`, `host`, `page`, `plugin`, `sidecar` or `sok`. |
| `event` | `<layer>.<subsystem>.<event>`, as the catalog declares it. The events of the writer itself are named `log.<event>` (`log.open`, `log.dropped`); their `layer` is the layer of the process that writes them. |
| `window`, `surface`, `session` | The identifiers of the object the event concerns, when it concerns one. |
| `cids` | The correlation identifiers of the inputs the event belongs to. It is omitted when there are none. |
| `fields` | The values of the event, as the catalog declares them. |
| `truncated` | Present only on an event whose fields text was over the size bound of an event: the size in bytes of that text before the cut. The `fields` of such an event hold only `head`, the first bytes of the text ([Bounds](#bounds)). |

The first line of every file is `log.open`. It holds the schema number (`schema`), `pid`, the role of the process (`role`), the identifier of the run (`boot`), the version of the writer and the policy in force. The schema number is 2: schema 2 adds `mono_ns` to every line. A reader that meets another schema number, a file of schema 1 included, rejects the file with an error that names the file and the number; no reader keeps code for an earlier schema.

A file that the writer rotates ends before the line that would take it past the bound. The new file starts with `log.open` and then `log.rotated` `{bytes, kept, removed}`: `bytes` is the size of the file that was closed, `kept` the number of generations that are kept, and `removed` the file name of the generation that the rotation removed, or `null` when none was removed. `seq` continues across the rotation, so a reader orders the generations by their first `seq`.

### Correlation identifier

A native input callback (a key event, a paste, a drop, a pointer report) receives one identifier `<boot>.<n>` from the layer that first sees it. The callbacks that it causes (`setMarkedText`, `insertText`, `commitThrough`) take the identifier of the callback that caused them. The identifier travels with the native report, the host relay and the page event; the plugin passes it with the send; the host puts it in the request envelope to the sidecar, so the body of the request stays the plugin's. A send that coalesces several inputs carries all of their identifiers, and the sidecar writes them in the events that the request causes, down to `pty_write`. A sidecar that does not know the envelope field ignores it.

The native library assigns the identifier of a key of an image region when the key arrives: `native.input.key_down` (the key code, the characters with and without the modifiers, the modifier flags, the repeat flag, the time of the key and the state of the input document), and every callback of the input method and every report to the page that the key causes takes the same identifier (`native.input.callback`, `native.input.report`). A callback of the input method that no key causes (a candidate chosen with the pointer, a change of the input source) is an input of its own and takes an identifier of its own. The report that is sent to the page carries the identifier as the member `cids` of its JSON. The host records the relay of such a report as `host.input.relay` (`surface`, `name`, `type`) with the same identifiers and passes the report on unchanged; the page records the call `sidecarSend` as `page.call` with the `cids` of the request, and the host records the request it queued as `host.sidecar.request` (`name`, `surface`, `bytes`) with the identifiers that the request line carries. The chain `input` of [Catalog](#catalog) joins these events, so the audit finds a key that stopped before the sidecar; the measure of the delay of one key between two layers is the difference of their `mono_ns`. Each sidecar repository writes the identifiers of the request in its own events, down to the write to the terminal, and extends the chain in its own catalog.

## Classes and policy

An event belongs to one class, which the catalog declares. The class decides how it is stored.

| class | examples | rate | storage |
| --- | --- | --- | --- |
| `lifecycle` | window, application, sidecar and session lifetime; settings, project, plugin and update changes | low | always stored |
| `input` | keys, input method callbacks, paste, clicks | human speed | always stored, complete: the typed text, ranges, flags and the state before and after |
| `call` | page-to-host calls, registry commands, endpoint methods: name, arguments, result, microseconds | medium | stored. An argument over the size limit that the catalog declares is stored up to the limit and marked `truncated`. An argument that the catalog marks as redacted (a token, the body of a document) is stored as its size and a hash. |
| `io` | sidecar messages, PTY reads and writes | medium to high | stored complete. The only bound is the rotation of the file, which is recorded when it happens. |
| `frame` | image frames, screens, pointer moves, wheel, layout | high | aggregated: one summary event per declared interval holding the count, the extremes, the last value and the total microseconds. While the category is switched on, every event is stored. |

The setting `diagnostics.log` selects the categories that are stored in detail. The host writes the effective policy to `<config-dir>/log-policy.json`. Every process watches the file through file system events and reloads it when it changes; no protocol operation carries the policy. A process that cannot read the policy stores `lifecycle`, `input`, `call` and `io`.

A large value, such as the cells of a screen, is not written into an event; its size and hash are. The value is stored while the `frame` category is switched on.

## Writers

A writer is the part of a process that turns events into lines of a file.

- A producer checks the policy first (one branch). It then builds the event as an owned message and pushes it with a non-blocking push to a queue bounded by count and by bytes. A full queue increments a loss counter. A field that is costly to build is passed as a closure, or guarded by `enabled(name)`.
- One writer thread per process assigns `seq`, serializes the JSON, writes batches (every 100 ms, when 64 KB are queued, or at once after an `error`) and rotates the file. An `error` wakes the writer and returns; the producer does not wait for the disk.
- The writer turns the loss counter into `log.dropped` events `{from_seq, to_seq, count, bytes, reason}`. When a write fails (disk full, input/output error), the writer counts the loss, shows it in a status, and records `log.dropped` when writing works again. A heartbeat detects a writer thread that ended; the process then reports a fatal error and ends.
- Every exit path flushes the queue with a deadline before the process ends: shutdown of the Go host, exit of the Rust host, `panic = abort`, `os.Exit`.
- The writer of the host takes events of the other layers of its process (the page batch, the native ring) with the clocks (`ts_us`, `mono_ns`), the correlation identifiers and the layer that they carry. The name of such an event must start with its layer; a layer outside the contract, fields that are not JSON, a `mono_ns` of 0 and an identifier that is empty or holds a quote, a backslash or a control character are refused with an error, and `seq` is still assigned by the writer. A host producer reads both clocks at the call (the monotonic clock through the platform operation `MonotonicNanos`, which reads `sp_mono_ns`, so the host and the native library share one clock), and the events that the writer itself creates (`log.open`, `log.rotated`, `log.dropped`) read them when they are created. A producer that emits an input event gives its identifiers (`EmitHostCids`, `emit_host_cids`).
- The native library has no writer. It owns a bounded lock-free ring in C; `sp_event` and `sp_event_cids` copy an event into the ring from any thread, and the writer thread of the host drains the ring by calling `sp_event_drain`. No producer thread calls into Go or Rust. Events written before the host writer exists wait in the ring. `sp_event_cids(level, name, cids, fields_json)` stores the wall clock in microseconds, the monotonic clock in nanoseconds (`sp_mono_ns`), the level, the name (1 to 255 bytes, under the layer `native`), the correlation identifiers (a list separated by commas, empty for none) and the fields as JSON text; `sp_event` is the call without identifiers. They refuse, and count, a missing or empty or longer name, a level outside the enumeration, missing fields, a missing list and a list with a quote, a backslash or a control character. The drain returns records of `ts_us` (8 bytes), `mono_ns` (8), the level (1 byte), the length of the name (1 byte), the length of the cids (2 bytes), the name, the cids and the fields, each behind a 4-byte length. The ring holds 4 MiB; a full ring refuses and counts the event, and the host writer records the count as `log.dropped` with the reason `the native ring was full`. The writer pulls the ring through the platform operation `PullNativeEvents` at its batch interval and when it flushes, up to 64 passes of 256 KiB per pull; no event source reaches the writer from the ring, because a native thread must not call into Go or Rust, so the pull polls. The writer stores a pulled record in the layer `native` with the clocks and the identifiers the library gave. It refuses a record whose name does not start with `native.`, whose level is not defined, whose fields are not a JSON object, whose `mono_ns` is 0, whose identifiers are empty or hold a quote, a backslash or a control character, or whose length does not fit the buffer, reports the refusal on the standard error, and counts the record in a `log.dropped` with the reason `a native record was refused`. A platform that cannot pull the ring fails the start of the host. The host gives the library the boot identifier of its run (`sp_event_set_boot`, through the platform operation `SetEventBoot`) before it starts the writer, so the identifiers that the library assigns (`sp_cid_new`, `<boot>.<n>`) are those of the files of the run.
- The page records through `context.log.<level>(event, fields)`. Events collect in an array and leave in one batch call to the host, on a timer of 100 ms, when a size bound is reached, and on `pagehide` and `visibilitychange`. The producer does not wait for the reply. `console.*`, global `error` events and `unhandledrejection` events enter the same entrance. The batch call is the host call `log` with the request `{action: "batch", events}`; the host validates the whole batch before it stores any event, stores every event in the layer `page` or `plugin` with the `ts_us`, the `mono_ns` and the `cids` the page gave, and rejects an event whose name does not start with `page.` or `plugin.`, a level outside the contract, a `ts_us` or a `mono_ns` that is not a positive integer, `cids` that are not an array of non-empty strings without a quote, a backslash or a control character, and `fields` that are not an object with an error that names `events[<index>]`. The page has no clock in microseconds: `Date.now()` has the resolution of a millisecond, so the page stores the reading of `performance.now()` for each event and converts it when the batch leaves. Before its first batch it sends the request `{action: "clock"}` five times, which the host answers with `{ts_us, mono_ns}` read at the call and stores no event for; it keeps the answer whose round trip on `performance.now()` was the shortest and takes the middle of that round trip as the moment of the answer. An event then has `ts_us` and `mono_ns` of the host at its reading, at the resolution of `performance.now()` and with an error of at most half the shortest round trip. A page event of a call that continues inputs (`page.call` of `sidecarSend`) carries the identifiers of the request in `cids`.
- A fatal signal handler writes a short line to a file descriptor that the process opened at start, with async-signal-safe calls only. A runtime fatal error of Go cannot be intercepted; its output goes to the crash file of the process, and the entrance `routine.Go` that starts every goroutine of the host recovers a panic, stores the `error` event `host.panic` and ends the process. The Rust host stores the same event from its panic hook, without waiting for the writer on the panicking thread, and a thread of its own flushes and ends the process ([hosts](hosts.md#process-lifecycle)).

- The command line tool `sok` has a writer of its own in each of its two packages (`event_log.go`, `event_log.rs`) with the layer and the role `sok`: the queue of [Bounds](#bounds), one writer goroutine or thread that assigns `seq`, writes a batch every 100 ms and at once after an `error`, records the refused events as `log.dropped`, and flushes with a deadline of 2 seconds before the tool ends. It reads the monotonic clock through the operation `MonotonicNanos` (`monotonic_nanos`) of its platform interface, which is `CLOCK_UPTIME_RAW` on macOS (the clock of `sp_mono_ns`) and `CLOCK_MONOTONIC` on Linux. A run stores at most `log.open`, `sok.command`, `sok.panic` and `log.dropped`, so the writer does not rotate the file. It is a separate implementation because the host writer is part of the host module and crate, which is bound to the host platform interface and routine entrance, and the host depends on the tool module and crate, so the tool importing the host writer would make a cycle; the contract is held by the tests of the tool against the golden files of `packages/log-contract/fixtures` (the cases `cli.log.*` of the [host contract](host-contract.md)), and the tool's writer has neither the native ring pull, the relay of other layers nor `cids`. Its goroutines and threads start through the entrance `Go` (`spawn_named`), which recovers a panic, stores `sok.panic` and ends the process ([command line](cli.md#event-log)).

Each repository that writes events carries its own small implementation of the writer, tested against the golden lines and the golden catalog in `packages/log-contract/fixtures`. No runtime code is shared between repositories, and no sidecar depends on a core release at run time.

## Bounds

Every buffer and every value that an event carries has a bound, and a producer cuts a value to its bound before it copies or serializes the value, so the cost of recording does not depend on the size of the value. A loss at a bound is never silent: it is counted and stored as an event of the catalog.

| Bound | Value | When it is reached |
| --- | --- | --- |
| Fields of an event | 1,048,576 bytes of JSON text | the writer stores the event with `fields` `{"head": <the first 4,096 bytes of the text, cut on a character boundary>}` and `truncated` set to the original size; the queue is charged for the stored size. The native ring never carries more than the 262,144 bytes of one pull. A producer of the host stops the serialization of the fields at this bound, so `truncated` is the size of the text when the writer measured it and, for a producer that stopped, the number of bytes it had written when it stopped, which is greater than the bound and less than the size of the value. |
| `args` and `error` of a call event (`page.call`, `host.endpoint.call`, `host.binding.call`) | 1,024 bytes, cut on a character boundary | the text is stored up to the bound and the event has `truncated: true`. The page cuts `args` while it serializes them and never serializes a whole value. |
| `text` of `page.console.<method>` | 8,192 bytes, cut on a character boundary | the text is built from the arguments up to the bound while they are serialized, and the event has `truncated: true`. |
| `fields` of an event of the page or of a plugin | 65,536 bytes of JSON text | the page serializes the fields only up to the bound and queues the event with `fields` `{"head": <the first 4,096 bytes of the text>, "truncated": true}`. Fields that JSON cannot serialize are an error of the caller. |
| `text` and `where` of a record (`page.record.<level>`, `host.record.<level>`, `sidecar.record.<level>`) | 8,192 bytes and 1,024 bytes, cut on a character boundary | the producer cuts them before it copies them, and the fields have `truncated: true`. |
| Queue of the page writer | 4,096 events and 4,194,304 bytes (the bytes of the fields and the name of each event) | the page counts the refused events and their bytes and stores `page.log.dropped` (`count`, `bytes`, `reason`) in front of the events that follow, one event for each bound that refused. |
| Queue of a host writer | 8,192 events and 16 MiB | the writer counts the refused events and stores `log.dropped`. |
| Queue of the writer of the command line tool | 1,024 events and 1 MiB | the writer counts the refused events and stores `log.dropped`. |
| Pending replies of a sidecar (written after the write queue of 256 lines drains) | 1,024 messages and 4,194,304 bytes | the reply is refused with the error `sidecar <name>: the pending replies reached <bound>, so a reply of surface <surface> is dropped`, and `host.buffer.dropped` is stored. |
| Pending closes of a sidecar | 1,024 messages and 4,194,304 bytes | the close is not sent, the surface is not listed as waiting for a reply, `host.buffer.dropped` is stored, and the sidecar keeps the session of the surface until it ends. |
| Expired requests of the relay (late replies) | 256 requests | the oldest request is forgotten, so a late reply to it is answered `exposure reply <id> has no matching request`, and `host.buffer.dropped` is stored. |
| Start buffer of the records of the host | 1,024 records and 4,194,304 bytes | the refused records are counted in the writer and stored as `log.dropped` once it exists. |
| Subscription changes of one topic of the endpoint that wait for the page | 256 changes | the change is refused and not applied, the client receives the error `-32000: the subscription changes of <name> are not keeping up: 256 changes are pending, so this change is refused`, and `host.buffer.dropped` is stored. The release of the subscriptions of a closed connection is not refused: it has one change for each topic that the connection held. |
| Output queue of an endpoint connection (Wails host) | 256 frames and 16,777,216 bytes | the frame is refused, `host.buffer.dropped` is stored, and the connection, which does not read, is closed. The Tauri host writes each frame to the socket while it holds the connection, so it has no queue. |

Every event `host.buffer.dropped` has `count` 1 and the size of the refused message, so a flood of refusals is a flood of events, which the queue of the writer bounds and counts in its turn.

## Files

A process run writes `logs/<role>-<boot>.jsonl` under the configuration directory. The host process also holds the events of the native library, the page and the plugins. Each writer rotates its own file at 100 MB and keeps 5 earlier generations (`.1` to `.5`); it never rotates another process's file. The only loss that rotation causes is the oldest generation, and the writer records the rotation.

Two raw files are not events: `logs/<role>-<boot>.stderr` holds the standard error of the process (output of the operating system and the frameworks), and `logs/<role>-<boot>.crash` holds the crash output of a runtime fatal error. The viewer lists them with the event files.

Files are created with mode `0600` in a folder with mode `0700` and are opened close-on-exec, so a child process does not inherit them.

The state files `logs/state-<time>.json` and the captures are not events; [debug](debug.md) writes them.

Beside each event file lies its index `<name>.idx` ([Index](#index)), which is derived from the file and is not an event file.

## Index

The event file is canonical. Beside each event file `logs/<name>` (`<role>-<boot>.jsonl`, `<role>-<boot>.debug.jsonl` and their generations `.1` to `.5`) the index `logs/<name>.idx` says which parts of the file can hold an event of a query, so a query reads those parts and never a whole file ([Query](#query)). The index is derived: removing it loses nothing, because it is built again from the file.

**Segments.** The lines of a file are grouped in segments of 4,096 consecutive lines counted from the first line; the last segment holds the lines after the last full one. A line is complete when a line feed ends it, and bytes after the last line feed are not indexed. The index keeps for each segment:

| member | value |
| --- | --- |
| `offset`, `length` | the byte offset of its first line and its size in bytes |
| `first_seq`, `last_seq`, `events` | the `seq` of its first and its last line, and its number of lines |
| `min_ts_us`, `max_ts_us` | the least and the greatest `ts_us` of its lines (the clocks of the layers differ by up to a batch interval, so `ts_us` does not grow with `seq`) |
| levels, layers, classes | one bit for each value that occurs: `error`, `warn`, `info`, `debug`, `trace`; `native`, `host`, `page`, `plugin`, `sidecar`, `sok`; `lifecycle`, `input`, `call`, `io`, `frame` (the member `class` of a line; no writer stores it before F160.7, so no bit of the classes is set until then) |
| Bloom filters | the five of the next table |

The Bloom filters of a segment are:

| filter | items inserted for each line | bytes | hashes |
| --- | --- | --- | --- |
| event | the event name and each prefix of it that ends before a dot (`native.input.key_down` inserts `native`, `native.input` and `native.input.key_down`) | 1,024 | 4 |
| surface | the member `surface` of the line, and the string member `surface` of its `fields` | 512 | 4 |
| session | the member `session` of the line, and the string member `session` of its `fields` | 512 | 4 |
| run | the string member `run` of its `fields` | 256 | 4 |
| cids | each of its `cids` | 16,384 | 5 |

A Bloom filter has `8 × bytes` bits. The hash of an item is FNV-1a 64 over its UTF-8 bytes (offset basis `0xcbf29ce484222325`, prime `0x100000001b3`); `a` is the hash and `b` is the hash rotated left by 32 bits with bit 0 set; bit `i` of an item, for `i` from 0 to the number of hashes minus 1, is `(a + i × b) mod 2^64` reduced by the mask `8 × bytes - 1`. A filter has no false negative. A segment that a filter admits is read and each of its lines is tested, so a false positive costs a read and never a wrong row. At 12,000 distinct identifiers in one segment (three for each line) the filter of `cids` admits a segment that has none with a probability under 1%, and the other filters admit one with a probability under 1% at their usual counts (400 names, 100 surfaces, 100 sessions).

**File.** All integers are little-endian. The file is two state blocks of 20,480 bytes, then the records of the full segments in order, each of 18,760 bytes. A record is 64 bytes of members, the five filters in the order of the table, and the checksum (FNV-1a 64 of the bytes before it). The members are `offset` (u64), `length` (u64), `first_seq` (u64), `last_seq` (u64), `events` (u32), 4 bytes of zero, `min_ts_us` (i64), `max_ts_us` (i64), the bits of the levels, of the layers and of the classes (one byte each) and 5 bytes of zero. A state block holds, in this order, the magic `SKIX`, the version 1 (u32), the lines of a segment 4,096 (u32), the length in bytes of the first line (u32), the generation of the block (u64), the FNV-1a 64 hash of the first line including its line feed, `indexed_bytes` (u64, the end of the last indexed line), `source_size` (u64) and `source_mtime_ns` (i64) as read when the file was indexed, `first_seq`, `last_seq` and the number of indexed lines (u64 each), the number of full segments (u32), whether a record of the last, partial segment follows (u32), that record, zero padding, and the checksum of the block (FNV-1a 64 of the bytes before it) in its last 8 bytes. An update writes the new full records first and then a block with the generation one higher into the block that the valid block does not occupy (block 0 for an even generation), so a process that ends in the middle of an update leaves a valid earlier block, and a record behind the full segments of the valid block is ignored and overwritten by the next update.

**Currency.** The index is current when `source_size` and `source_mtime_ns` equal the size and the modification time of the file. When the file is larger, its first line still has the recorded hash and its size is at least `indexed_bytes`, the index is older than the file, and the update indexes the lines after `indexed_bytes`, beginning at the partial segment. Any other difference (a smaller file, another first line, another modification time at the same size) means the file is not the one that was indexed, and the update indexes the whole file again. A missing index is built. These are explicit errors that name the file and what was found: an index of another version, a block or a record whose checksum does not match, a file shorter than its blocks and records, a first line that is not `log.open` with schema 2, and a line that breaks the event structure (`<file>:<line>: <reason>`); no code reads an index of another version, an update that fails keeps the earlier state of the index, and the person removes a damaged index after the error names it.

**Writers of the index.** The index follows the file by the events of the file and not by a timer. After the writer of a host wrote a batch ([Writers](#writers)), a goroutine or thread of the host that the notice of the write wakes indexes the lines that were appended; notices that arrive while it indexes become one more update. Every query also brings the index of each file it reads up to date before it uses it, so an index that the host did not write (a file of a sidecar, a configuration directory without a running host) is built and updated by `sok debug query` and by the query of a host. Updates of one index exclude each other across processes with an advisory lock on the index file (`flock`), and an update checks after it holds the lock that the opened files are still the files at their paths, so a rotation cannot mix two files. An update that finds the index current changes nothing, so an update is idempotent. The host stores the event `host.log.index_rebuilt` (`file`, `reason`, `lines`, `bytes`, `micros`) at the level `info` for each index that it builds from the whole file, and shows every other failure of an update once for each distinct text in the application log as an `error` record of the place `log index`. An incremental update stores no event, because the event would be a line that the next update indexes.

**Rotation.** When the writer rotates a file, it holds the lock of the index of that file, brings the index up to date, renames the generations and renames the index files with them (`<name>.idx` becomes `<name>.1.idx`, `<name>.1.idx` becomes `<name>.2.idx`, and the index of the removed generation is removed). The index of a closed generation is complete and is not built again.

**Golden fixtures.** `packages/log-contract/fixtures/query` holds event files, the SHA-256 of the index that both implementations must produce for each of them (with the modification time of the source set to 1,000,000,000 seconds), and the queries with their expected pages. The tests of the Go and of the Rust implementation build the index from the files, compare its SHA-256, and run the queries.

## Query

One implementation of the query for each language (the module `sok` for Go, the crate `soksak-sok-tauriv2` for Rust) reads the event files of `<config-dir>/logs/` through their indexes and answers one page. The two implementations give the same page, the same cursor and the same error text for the same files and the same parameters, and the golden fixtures check it.

**Files.** The event files of the query are the files of `logs/` named `<role>-<boot>.jsonl`, `<role>-<boot>.jsonl.<n>` (`n` from 1 to 5), `<role>-<boot>.debug.jsonl` and `<role>-<boot>.debug.jsonl.<n>`, with `role` a lowercase word and `boot` the rest of the name; the files `.stderr`, `.crash` and `.idx`, the state files and the captures are not event files. A *process* is a role with a boot (`host-1791500000-4242`), and the files of one process (the file, its generations and its debug file) share one `seq` space ([Event](#event)). A *channel* is a set of files: `other` the files that are not debug files, `debug` the debug files, `all` both. The writers store `error`, `warn` and `info` in the file and `debug` in the debug file once F160.7 is done; until then they store every level in the file, and the query reads the files that exist.

**Parameters.** The parameters of the endpoint method `log.query` and of the host call `logQuery` are one object, and a member that is not in the table is refused. A member that is not given does not restrict.

| member | meaning |
| --- | --- |
| `channel` | `other` (default), `debug` or `all` |
| `level` | the least severe level shown (`error`, `warn`, `info`, `debug` or `trace`; default `trace`); a line of that level or of a more severe one passes |
| `class` | one class: `lifecycle`, `input`, `call`, `io` or `frame` |
| `layer` | one layer: `native`, `host`, `page`, `plugin`, `sidecar` or `sok` |
| `event` | the exact event name |
| `event_prefix` | an event name or the first part of one that ends before a dot: `native.input` passes `native.input` and each name that starts with `native.input.`. A prefix that ends with a dot is refused. `event` and `event_prefix` are not given together |
| `surface`, `session` | the whole identifier: the member of the line, or, when the line has none, the string member of the same name in its `fields` (the host writer stores them there) |
| `cid` | one correlation identifier, which the `cids` of the line contain |
| `run` | a run identifier: the range of time from the earliest `host.test.start` to the latest `host.test.end` whose `fields.run` is that identifier in the files of the channel (to the end of the files when a start has no end), applied to every file by `ts_us` as the [audit](#checking) places the events of other processes; it combines with `from_us` and `to_us` by intersection. A run that has no `host.test.start` is the error `log query run "<run>" has no host.test.start in the channel` |
| `text` | the line, as its JSON text is in the file, contains the text; ASCII letters compare without case |
| `from_us`, `to_us` | inclusive bounds of `ts_us`, non-negative integers; `from_us` is not later than `to_us` |
| `order` | `asc` (default, oldest first) or `desc` (newest first) |
| `limit` | the number of rows of the page, an integer from 1 to 5,000 (default 500) |
| `after` | the cursor `{ts_us, role, boot, seq}` of the last row of the page before: the page holds the rows after it in the order (before it for `desc`) |
| `since` | an object from the name of a process (`<role>-<boot>`) to a `seq`: the rows of that process with a `seq` not greater than it are left out; the rows of a process that it does not name are not restricted |

The error text of a refused parameter is `log query <member> <reason>`: `log query has no parameter <name>`, `log query channel "<value>" is not one of other, debug, all`, `log query level "<value>" is not one of error, warn, info, debug, trace`, `log query class "<value>" is not one of lifecycle, input, call, io, frame`, `log query layer "<value>" is not one of native, host, page, plugin, sidecar, sok`, `log query <member> must be a non-empty string, found <value>`, `log query <member> must be a non-negative integer, found <value>`, `log query from_us is later than to_us: <from_us> <to_us>`, `log query limit must be an integer from 1 to 5000, found <value>`, `log query order "<value>" is not one of asc, desc`, `log query after must be {ts_us, role, boot, seq}, found <value>`, `log query since must map process names to integers, found <value>`, `log query takes event or event_prefix, not both` and `log query event_prefix "<value>" must not end with a dot`; a value is shown as JSON.

**Order and cursor.** The rows are ordered by `ts_us`, then `role`, then `boot`, then `seq`, which is the key of a row. The channels are merged by this key, so the debug file and the file of a process interleave by time and by `seq`. The cursor of a row is its key. A page holds the `limit` rows that follow the cursor in the order, or fewer when the files end or the line text of the rows would pass 8,388,608 bytes (the first row is always taken). `next` is the cursor of the last row of the page when a row follows it, and `null` otherwise.

**Answer.** `{rows, next, tail, scanned}`:

- `rows` holds the objects `{role, boot, file, offset, event}`: the process, the file that holds the line (`logs/...`, relative to the configuration directory), the byte offset of the line, and the line as the event object of the file;
- `next` is the cursor to pass as `after`, or `null`;
- `tail` maps each process of the channel to the greatest `seq` that its indexes cover when the query read them; a client that follows the files starts with it as `since` ([debug](debug.md#timeline));
- `scanned` is `{files, segments, read, lines, rebuilt}`: the files of the channel, their segments, the segments whose lines were read, the lines parsed, and the indexes built from the whole file during the query.

**Evaluation.** For each file the query brings the index up to date, then keeps the segments that can hold a row: the range of time overlaps the bounds and the cursor, the bits of the levels (the level and the more severe ones), the layers and the classes contain the value, and the filters of the event name or prefix, the surface, the session and the cid admit it. It reads the kept segments in the order of `min_ts_us` (of `max_ts_us` descending for `desc`), tests each line of a segment completely, and keeps the `limit + 1` rows of the least key (the greatest for `desc`) found so far. It stops when the next segment cannot hold a row that precedes the kept rows, so the cost of a page depends on the number of segments that can hold a row and not on the size of the files. A query with only `text` reads every segment of the channel. A line that breaks the event structure is the error `<file>:<line>: <reason>`.

**Consumers.** The debug view calls `logQuery` ([debug](debug.md#timeline)), `sok debug query` runs the same implementation in the process of the tool without a connection to the application ([command line](cli.md#commands)), and clients of the endpoint call `log.query` ([endpoint](endpoint.md#log-query)); a host answers `log.query` and `logQuery` with the implementation of its language. A script outside the hosts may read the files: `scripts/audit-run.mjs` and `scripts/check-events.mjs` judge every line of every file (structure, consecutive `seq`, chains), which is a pass over all lines and not a search, so no index shortens it; a script that looks for a subset of lines (the range of a test, a chain of `cids`) uses `sok debug query`.

**Measured.** The times of a log of 1,000,000 events are in [features](../features.md) (F160.24); the benchmark `log_query_benchmark` of each implementation builds that log and prints the time of the build of the index and of each kind of query.

## Catalog

Each repository that emits events declares them in `events.json` (this repository: [events.json](events.json), which owns the layers `native`, `host` and `page`; a name with a placeholder such as `page.record.<level>` declares a family; `level` is one level or a list of levels, a field name that ends with `?` is optional, a type such as `string|null` accepts each of its parts, and the layer `sidecar` holds only `sidecar.record.<level>`, the lines of the standard error of a sidecar that the host stores; `make events-check` reads the emit sites of the sources and fails on an emitted name that is not declared, on a declared event that no site emits, and on a level or a field of a literal site that the declaration does not allow; a site gives its name as a literal (a template of the page is a family), a comment `events: <names>` above a site that builds its name lists the declared names it builds, and `events: forwarded` states that the site passes on the name of its caller; `node scripts/check-events.mjs --logs <config-dir>…` audits the event files of every layer that the window checks left, see [Checking](#checking)): for each event the name, the layer, the class, the level, the required fields with their types, the arguments to redact, the size limit of arguments, and a description. The repository checks its own sources against its catalog, as it checks its own sources in every other check. This repository owns the schema of the catalog and the events of the layers `native`, `host` and `sok` and of the page. A plugin or a sidecar names the file of its catalog in its manifest (`events`, a path inside the package like `executable`), the release packs that file, and the viewer reads the catalogs of the installed manifests; this repository does not name them.

An event that is one input of a chain is declared with `"cids": "required"`, and the audit refuses a line of it without a non-empty `cids` of strings (the guard of the input chain). The catalog also declares the chains an input kind must leave, as the ordered list of events from the first layer to the last (`chains`). This catalog declares `input`: `native.input.key_down`, `host.input.relay`, `page.call` (the call `sidecarSend` that carries the identifiers), `host.sidecar.request`. The events of a sidecar that the request causes (for example `sidecar.vt.pty_write`) are declared by the catalog of the sidecar repository, which extends the chain there. An audit of a log requires every declared chain of an input to be complete: each identifier that appears in the first event of a chain must appear in every later event of it, across the files of all layers.

### Entrances

These entrances record without a call site writing the record:

- the host calls of the main page: the wrapper that both runtimes put around `host.call` (`settlingCalls`) emits the event `page.call` with the fields `name`, `args` (the JSON of the arguments, cut at 1024 bytes while it is serialized, with `truncated: true`), `micros`, `ok` and, for a refused call, `error`. It is at the level `debug`, and `warn` for a refused call. The calls `log` and `performance` are not recorded, because a recorded `log` call would record itself, `logQuery` is not recorded, because the debug view asks in answer to the event that the writer announced, and `overlayUpdate` and `overlayPlace` are not recorded, because they draw and place a native modal and are of the class `frame`, which is stored as aggregates; a view that follows the event files draws for every row it appends, so recorded draws would feed it;
- the host calls of a surface document: the runtime `page` object of each application sends every call through `surfaceCalls` (`packages/workbench/surface-calls.js`), which emits the same event `page.call` with the same name and arguments in both runtimes (the arguments are those of the call as the Wails runtime passes them). The events go through the batcher of the document, so the calls of one turn travel to the host in one call `log`, and the `report` of the document is queued behind the same batcher so that the records and the calls of the document keep their order. The call `log` is not recorded. A failed relay is written to the console of the document, which has no other place to report it;
- window events: every event that a host registers for a window is the event `host.window.event` with the `window` and the `kind`. A host emits the kinds its framework reports (Wails reports `show`, `hide`, `focus`, `lost_focus`, `web_process_ended` and `navigation_committed`, Tauri reports `occlusion_changed`), so the kinds a host stores are a subset of the list in [host contract](host-contract.md);
- application events: every event that a host registers for the application is the event `host.app.event` with the `kind`; a host stores the kinds its framework reports (Wails reports `started`, `activated`, `deactivated`, `exit_requested` and `exit`, Tauri reports `started`, `exit_requested` and `exit`);
- endpoint methods: every request of a client of the [endpoint](endpoint.md) is the event `host.endpoint.call` with the fields `name` (the method), `args` (the params as received, `null` when the request has none, cut to 1024 bytes on a character boundary before they are copied, with `truncated: true` when cut), `micros` (from the receipt of the request to its result), `ok` and, for a failed request, `error` (the code and the message that the client receives, `<code>: <message>`, cut the same way). It is at the level `debug`, and `warn` for a failed request, whether or not the performance trace is on. A subscription change (`status.watch`, `status.unwatch`) is recorded when its reply is written, and the event is stored before the reply is written;
- host calls on the host side: every call of the main page and of a document of a surface to the host is the event `host.binding.call` with the fields `name` (the snake case name of the call, the name of the Tauri command), `args` (the JSON array of the arguments in the order of the call, each value serialized only up to the bound, cut to 1024 bytes on a character boundary, with `truncated: true` when cut), `micros` (from the receipt of the call to its result), `ok` and, for a failed call, `error` (the text that the page receives, cut the same way). It is at the level `debug`, and `warn` for a failed call, whether or not the performance trace is on, and it is stored by the host, so it survives a page that stops. A call that ends without a result (a command that panics, or an argument that the framework rejects in the Tauri host) is a failed call with the error `the call ended without a result`. The Wails host passes the calls of the main page through the one bound method `Bindings.Call` and the calls of the documents of surfaces through `invokeNative`; the Tauri host defines every command inside the `bindings!` macro ([hosts](hosts.md)). The call `log` is recorded like every other call;
- bounded buffers: a buffer of the host that is full refuses the newest message, returns an error to its caller where it has one, and stores the event `host.buffer.dropped` (`buffer`, `count`, `bytes`, `reason`) at the level `warn`; the bounds are in [Bounds](#bounds);
- registry commands: the page answers every request `command.run` through one function that emits the event `page.command` with the fields `name`, `micros`, `ok` and, for a failed command, `error` (level `debug`, and `warn` for a failed command), whether or not the performance trace is on;
- native activity: the native library records the notifications of the application (`native.app.activated`, `native.app.deactivated`, `native.app.hidden`, `native.app.unhidden`), of its windows (`native.window.key`, `native.window.resign_key`, `native.window.main`, `native.window.resign_main`, `native.window.miniaturized`, `native.window.deminiaturized` with the window number and the class of the first responder, and `native.window.occlusion` with `visible`) of the input source (`native.input.source_changed`), and each change of the first responder of a window (`native.window.first_responder` with the window number and the classes `from` and `to`; recorded when the window next updates, by comparing the first responder with the one at its earlier update; AppKit passes through the window and the field editor of a text field, so one focus move can be several events) at the level `info`; each query of the input method that an image region answers is `native.input.query` at the level `debug` with the `call` (`markedRange`, `selectedRange`, `hasMarkedText`, `firstRectForCharacterRange` or `characterIndexForPoint`), its arguments, the `answer` and the `focus` of the region; the host installs the observers when it starts its writer;
- native registrations: every observer, monitor, key-value observer, run loop observer, dispatch source, Apple event handler and delegate of the native library is registered through the one entrance `observe.m` (`native/darwin/src`), which stores `native.observe.registered` (`source`, `kind`, `target`, `mode`, `registrations`) at the level `info` for each registration and `native.observe.failed` (`source`, `kind`, `reason`) at the level `error` for a refused one, and counts every delivery by the name of its `source`. A source has one of three modes: `record` stores `native.observe.delivered` (`source`, `count`) at the level `debug` for each delivery, `stored` only counts because the receiver stores an event of its own for each occurrence, and `count` stores `native.observe.counted` (`source`, `count`, `total`, `micros`) at the level `debug` at most once per second, with the exact number of deliveries since the earlier summary, for a delivery at the rate of a frame or a device; `sp_observe_flush` stores the count after the last summary. The call that registers needs no gate: a delivery costs one atomic add, and a `record` delivery formats a bounded buffer on the stack and allocates nothing. A native call that fails stores `sp_log_error` or `sp_log_info`, which are emit sites of `native.record.error` and `native.record.info` for the census, and a process that does not end within the wait of `sp_process_when_exited` stores `native.process.exit_timeout` (`pid`, `seconds`) at the level `warn`;
- sidecar lifetime: a sidecar process of standard input and output is the event `host.sidecar.start` (`name`, `pid`) when the host starts it and `host.sidecar.exit` (`name`, `pid`, `status`, `stopping`) when it ends, and the connection to a persistent service is `host.sidecar.connect` (`name`, `pid`, `spawned`) and `host.sidecar.disconnect` (`name`, `pid`, `stopping`, `violation`), all at the level `info`;
- allowed removal: a window that ends while it is asked whether a project may be removed allows the removal, which is the event `host.project.removal_allowed` (`window`, `project`) for each such request, at the level `info`;
- settings change: each change of a settings file is the event `host.workspace.settings` (`scope`, `set`, `removed`), at the level `info`; `set` and `removed` hold the keys, never the values;
- notification center: each state, posted notice and activated notice is the event `host.notification.event` (`type`, `authorization`, `window`, `surface`), at the level `info`, and each failure is an `error` record of the place `notification`;
- process queries: a `ps` query of the WebKit children that fails is an `error` record of the place `webkit children`; the answer of `ps` that a process does not exist (status 1 and no output) is not a failure;
- application update: the host starts the detached `sok app update` before the final flush of its event log and stores the event `host.update.start` (`pid` of the command, `command` line) at the level `info`; a start that fails is an `error` record. `sok` writes its own event file `logs/sok-<boot>.jsonl` in the configuration folder it targets, with `sok.command` (its result, exit status and error text) and `sok.panic` ([command line](cli.md#event-log)). The detached command keeps the standard error of the host, so its message is also in `logs/host-<boot>.stderr`; its exit status has no reader besides `sok.command`, because the host that could read it has ended before the command replaces the bundle. A command that fails restores and starts the earlier bundle, whose run begins with `log.open`;
- the start of a document of the main page: the first module the page loads emits the event `page.start` with the fields `time_origin` (the origin of the clock of the document, `performance.timeOrigin`) and `url`, so a reload, which starts a new document with a new clock, is a marked boundary in the timeline;
- the display of an error that a person sees, which emits the `error` event.

Sources that no entrance covers, such as the end of a task, are listed by a lint of the sources for events without a declaration or a reason comment. The lint is not proof. Coverage is judged at run time: a window check drives each declared source through declared commands and native input and requires its declared events.

### Test marks

A window check marks each test in the event log of the application under test, so a test is a range of positions in the log. The diagnostic method `diagnostics.test.mark` ([endpoint](endpoint.md)) stores the event `host.test.start` (`name`, `run`) when the test starts and `host.test.end` (`name`, `run`, `result` of `pass`, `fail` or `skip`) when it ends, both of the layer `host`, the class `lifecycle` and the level `info`, and replies after a flush with `{boot, seq}`: the `boot` of the event file and the `seq` of the marker line. A position is `(boot, seq)`. The run identifier travels in these events and not in `log.open`, because one application serves many runs. The window-check library marks the start when a check opens its session and the end after the cleanups and the error audit of the check, with `fail` when the body or a cleanup failed, and appends `{run, app, config, name, kind, boot, seq, ts_us}` (`config` is the configuration folder of the application) to `marks.jsonl` in the run folder (`SOKSAK_RUN_FOLDER`) for each mark, a call of `expectError` appends `{run, app, config, name, kind: "expect_error", pattern, flags, ts_us}` for the running test, and a call of `expectEvent(name)` appends `{run, app, config, name, kind: "expect_event", event, ts_us}`. It marks only while `SOKSAK_RUN_ID` is set, which the test runner sets ([examples](../operations/examples.md#window-checks)).

## Checking

`soksak-log-check` (the package `@soksak/log-contract`, `packages/log-contract`) validates logs against the schema and the catalog: the line structure, declared events, consecutive `seq` with gaps explained by `log.dropped`, the declared chains of each input kind, and no `error` besides those a test declares. The unit tests and window checks leave their logs; the gate validates every log that remains, and logs of a failed run are kept until they are classified.

The audit of a run, `node scripts/audit-run.mjs <run folder>`, runs at the end of `pnpm verify:windows` and of the activation tier (`scripts/node-tests.mjs` with `--script verify` or `--script verify:<tier>`), also when a test failed. It reads `marks.jsonl` of the run folder, takes the configuration folders from the `config` of the marks, and audits every event file of every layer in them (`host-`, `vt-`, `files-`, `shell-` and `sok-` files, their generations `.1` to `.5` and their debug files) against the catalog: the line structure, undeclared events (the layer `sidecar` is audited because the catalog lists it), consecutive `seq` for each process across its generations and its debug file, the declared chains over the files of the folder together, and every `error` event. The range of a test is the lines of the application log between its `host.test.start` and `host.test.end` marks by `(boot, seq)`; the events of another process are placed in it by `ts_us`. An `error` is declared when every test whose range holds it declares a pattern (`expect_error`) that matches its text; any other `error`, also one outside every test, is a finding, and so is a start mark without an end mark. A test that declared an event (`expect_event`) with `expectEvent` and whose range holds no event of that name is a finding at its end mark that names the missing event. The audit writes `judgment.json` in the run folder, one row for each test and application: `{name, app, result, boot, from, to, errors, expected, missing}`, where `from` and `to` are `{seq, file, line}` of the start and the end mark (`to` is null without an end mark), `errors` lists the `error` events of the range with `{file, line, text, declared}`, `expected` lists each declared event with the number found in the range, `missing` lists the declared events with none, and `result` is `pass` only when the test has an end mark, `missing` is empty and every error is declared. A finding is a line `<file>:<line>: <message>` on the standard error, and the exit status is 1 when there is one or when the run left no `marks.jsonl`. `node scripts/check-events.mjs --logs <config-dir>…` audits configuration folders without marks and reports every `error` event. The workflow `ci.yml` runs no window check, so it runs the tests of the audit with the fault fixtures (`pnpm test`); the audit of a real run belongs to the workflow `window-checks.yml`, which runs `pnpm verify:windows` and then this audit on a self-hosted runner with a signed-in desktop and keeps the run folder of a failed job ([continuous integration](../operations/examples.md#continuous-integration)), and to the window-check run on the development computer.

### Census

A source of occurrences is a place where a record could be lost without a trace: an empty catch, a discarded result, a goroutine, a registered observer, a delegate, an error return. The census finds each of them by rules of its language and requires either an event stored in the same function or a reason marker. The marker has one form, `(default|silent): <reason>` (`default:` states why a default is part of the contract, `silent:` states why nothing is recorded), on the line of the source, inside the span of the match, or in the comment lines directly above it; the reason has at least ten characters. A comment that opens with another form of the word (`Default:`, `Silent:`, `fallback:`, another separator, another language) is an error that names the file and the line. There is no baseline: a source without either fails as `<file>:<line>: <rule> has neither an event nor a stated reason`.

`soksak-events [--census <file>] [--catalog <file>] [--list] [repository]` (the package `@soksak/plugin-api`, `packages/plugin-api/events-check.js`) applies the rules in `packages/plugin-api/census-rules.json`, and every repository calls it. A rule has an `id`, a `language`, a `pattern` that is matched in the code without comments, a `requires` of `event-or-reason` or `entrance` (the source is allowed only in the entrance files of the repository and no event or marker accepts it elsewhere), and a description. The rules are: `js.empty-catch`, `js.swallowing-catch`, `go.go-statement`, `go.recover`, `rs.ok-discard`, `rs.unwrap-or`, `rs.dropped-send`, `m.registration` (observer, monitor, KVO, event tap, run loop source, dispatch source and timer registration), `m.delegate` and `m.error-return` (`return NO;`). The event of a source is an emit site of the catalog entrances (`sitesOf`); the function is the innermost named function of Go and Rust, the innermost function-like block of JavaScript and the outermost block of Objective-C. The return-path rules are approximate and the registration rules are exact.

The declaration file of a repository (`--census`) holds `exclude` (a pattern of the paths that the census leaves out), `entrances` (rule id to the patterns of the entrance files) and `pending` (rule id to the checklist item that creates the entrance and enables the rule). A pending rule is not enforced, and the command prints it with its item and the count of findings that wait for it (`--list` prints each finding), so a disabled rule is never silent. A rule id that no rule has, an unknown key or a pending value that is no checklist id is an error. `--catalog` also checks the emit sites of the sources against the catalog at that path in both directions ([Catalog](#catalog)). `make census-check` runs the command in this repository, with `scripts/census.json`, and `pnpm test` runs it in `scripts/test/census.test.mjs`; `scripts/check-fallbacks.mjs` uses the same marker and rejects the other forms.

An input is checked against an independent receiver: the logged `pty_write` bytes equal the bytes that a stand-in for the shell wrote to a file.

## Privacy

Typed text is stored in `logs/` on this computer. It leaves the computer only when a person hands a file over. The actions that save a file or a selection warn that the file can hold what was typed. Arguments that the catalog marks as redacted are stored as a size and a hash.

## Limits

- Wall clocks step and can differ between a sleeping and a waking machine; `mono_ns` orders events of processes of one boot, and `cids` order the layers of one input. The page derives both clocks from the host once, so its `ts_us` drifts from the wall clock of the host when the wall clock steps after the page started, and its resolution is that of `performance.now()`, which WebKit coarsens; the error of a page value is at most half the shortest round trip of the clock request.
- A signal handler may call only async-signal-safe functions, so it writes a short line prepared at start. The `info` events of the last batch interval (up to 100 ms) can be lost in a crash; an `error` is handed to the writer at once but is lost if the process dies before the writer runs.
- The page cannot write files, so it records through the host with batched calls. A batch not yet sent when the page process ends is lost (up to the flush interval).
- Rotation sheds the oldest generation when a flood of PTY output fills the files. The writer records each rotation.
- The input method answers only in the key window of the active application, so a check of composed input needs a run in which the application is active.
