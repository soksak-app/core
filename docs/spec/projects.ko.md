# 프로젝트·설정·창

[English](projects.md)

이 명세는 앱의 프로젝트 등록 목록, 영구 설정, 프로젝트 창을 정의한다. [기능 상태](../features.ko.md)에 구현과 검증을 구분해 기록한다.

## 프로젝트 식별

프로젝트 하나는 존재하는 디렉터리 하나에 대응한다. 네이티브 호스트는 현재 사용자의 `~`를 확장하고 절대 경로와 심볼릭 링크를 해석하며 디렉터리인지 확인한 뒤 파일시스템 식별자를 반환한다. 프로젝트 등록 목록은 같은 식별자와 같은 정규 경로의 중복을 거절한다. 같은 디렉터리를 다시 열면 기존 프로젝트와 창을 선택하며 프로젝트를 추가하지 않는다. 프로젝트 이름은 변경할 수 있으며 식별 기준으로 사용하지 않는다.

앱 시작과 새 창 동작은 프로젝트를 선택하지 않은 일반 앱 창에서 프로젝트 라이브러리를 표시한다. 첫 프로젝트를 생성하거나 열면 같은 OS 창의 라이브러리를 작업 화면으로 교체한다. 라이브러리는 화면이며 별도 창 유형이나 임시 프로젝트가 아니다. 기존 작업 화면을 다시 로드하면 해당 창의 선택한 프로젝트를 유지한다. 디렉터리가 없으면 오류를 표시하고 저장된 프로젝트 데이터를 삭제하지 않으며 프로젝트 선택은 계속 사용할 수 있다.

라이브러리는 저장된 프로젝트, 배치 미리보기, 폴더 경로, 스페이스 수, 고정 프로젝트, 최근 열기 시각, 실제 프로젝트 열림 상태를 표시한다. 검색은 이름과 경로를 대상으로 하며 전체·열림·고정·Git 루트 프로젝트를 필터링한다. 미리보기는 렌더러가 저장한 카드 사각형, 고정 폭 사이드바, 간격, 레일 외곽선을 종횡비를 유지해 축소한다. 정규화된 분할 비율만으로는 표시 좌표를 계산할 수 없다. 배치를 렌더링할 때 미리보기를 저장한다. 미리보기는 콘텐츠 웹뷰나 셸을 생성하지 않는다. 새 프로젝트는 선택한 부모 폴더에 이름을 지정한 디렉터리를 생성한다. 폴더 열기는 기존 디렉터리를 등록한다. Git Clone은 새 디렉터리에 저장소를 복제한 뒤 등록한다. 폴더 선택 취소와 작업 실패 후에도 현재 화면을 사용할 수 있다. 브라우저 예제는 프로젝트 선택과 브라우저 창을 지원하지만 네이티브 디렉터리 생성·복제는 지원하지 않는다.

제목 표시줄의 프로젝트 목록 버튼과 프로젝트 추가는 현재 작업을 유지하면서 같은 창에 라이브러리를 표시한다. 프로젝트 선택이나 작업 화면 복귀로 작업 화면을 복원한다. 새 창은 항상 프로젝트 미선택 창을 생성한다. macOS에서 모든 창을 닫아도 이 동작을 사용할 수 있도록 앱을 유지한다. 라이브러리 푸터, Command/Ctrl+Shift+N, macOS Dock 메뉴는 같은 동작을 실행한다. 선택한 프로젝트가 없는 창의 라이브러리는 공통 설정을 사용한다.

## 설정

적용할 설정은 기본값, 공통 설정, 현재 프로젝트의 명시적 덮어쓰기 순서로 결정한다. 설정은 공통 범위와 프로젝트 폴더 범위를 제공한다. 프로젝트 값을 제거하면 공통값을 다시 상속한다. 공통값을 변경하면 해당 값을 덮어쓰지 않은 모든 열린 프로젝트에 반영한다.

프로젝트 열기 방식은 공통 설정에만 있다. `tabs`는 현재 창에서 프로젝트를 열고, `windows`는 현재 창이 이미 프로젝트를 관리할 때 다른 프로젝트를 별도의 최상위 OS 창에서 연다. 프로젝트 미선택 창의 첫 프로젝트는 항상 같은 창에서 연다. 프로젝트 폴더 설정에서 이 값을 덮어쓸 수 없다. 이미 열린 프로젝트를 선택하면 기존 창을 사용한다. 열기 방식 변경은 이후 프로젝트 열기에 적용하며 실행 중인 창과 셸을 닫지 않는다.

프로젝트 창은 독립 OS 창이다. 설정과 추가·분할 메뉴는 [네이티브 모달](native-modals.ko.md)에 정의한 창 내부 네이티브 웹뷰를 유지한다. 각 프로젝트 창은 활성 프로젝트, 표면, 모달, 테마, 입력 상태, 셸 구독을 관리한다. 한 창의 배치 준비, 다시 로드, 설정, 닫기가 다른 창의 네이티브 상태를 변경하면 안 된다.

## 저장

프로젝트 순서, 공통 설정, 폴더별 덮어쓰기, 스페이스, 활성 스페이스, 카드·탭 상태, 포커스 카드, 숨긴 사이드바를 포함한 사이드바·레일 너비, 프로젝트 창 크기·위치를 저장한다. 창의 프로젝트 소유 관계와 실행 중인 셸 프로세스는 런타임 상태다. 프로젝트 창을 닫아도 저장된 프로젝트와 화면 설정을 유지한다.

네이티브 호스트는 앱 설정 디렉터리의 `settings.json`에서 공통 설정을 읽고 프로젝트 디렉터리 내부의 `.soksak/settings.json`에서 프로젝트 덮어쓰기를 읽는다. 설정 파일이 없으면 덮어쓰기가 없는 상태다. 프로젝트 파일에는 명시적으로 변경한 값만 저장하며 키를 제거하면 상속을 복원한다. 공통 전용 키인 `projectOpening`은 프로젝트 설정에서 허용하지 않는다.

기본 앱 설정 디렉터리는 다음과 같다.

| 호스트 | macOS | Windows | Linux |
| --- | --- | --- | --- |
| Wails | `~/Library/Application Support/com.soksak.wailsv3` | `%AppData%/com.soksak.wailsv3` | `$XDG_CONFIG_HOME/com.soksak.wailsv3`, 미설정 시 `~/.config/com.soksak.wailsv3` |
| Tauri | `~/Library/Application Support/dev.soksak.example` | `%AppData%/dev.soksak.example` | `$XDG_CONFIG_HOME/dev.soksak.example`, 미설정 시 `~/.config/dev.soksak.example` |

`--config-dir PATH`로 앱 설정 디렉터리를 변경한다. 프로젝트 덮어쓰기 경로는 각 프로젝트 내부를 유지한다. 설정 UI는 공통·프로젝트 범위 선택과 개별 덮어쓰기를 제거하는 **공통값 사용**을 제공한다. 프로젝트 탭을 드래그해 순서를 변경하며 이 순서를 라이브러리의 기본 순서로 사용한다. 탭의 ×는 등록 목록에서 프로젝트를 제거하고 폴더와 설정 파일은 유지한다. OS 창의 닫기 버튼은 등록된 프로젝트를 유지한다.

앱 설정 디렉터리의 `projects.json`에는 정렬된 프로젝트 목록과 프로젝트 화면 상태를 저장한다. Wails와 Tauri는 각각의 앱 설정 디렉터리를 사용한다. 네이티브 호스트는 변경을 직렬화하고 대상 파일을 다시 읽은 뒤 수정하며 같은 디렉터리에 임시 파일을 작성하고 쓰기를 완료한 후 대상 파일을 교체한다. 교체가 성공한 뒤 열린 창에 변경을 알린다. 다시 로드하거나 프로젝트를 선택하면 설정 파일을 다시 읽는다. 저장 실패를 화면에 표시하며 기본값으로 초기화하거나 저장된 데이터를 조용히 덮어쓰지 않는다. 준비된 프로젝트 창을 닫을 때 대기 중인 저장을 완료한 뒤 네이티브 자원을 제거한다. 앱 종료 시 준비된 모든 창에 같은 저장을 요청한 뒤 종료한다.

브라우저 예제는 브라우저 창과 IndexedDB 저장소를 사용하며 네이티브 폴더에 설정을 작성하지 않는다. 입력한 경로만으로 네이티브 파일시스템 식별자를 확인할 수 없으므로 디렉터리 식별과 네이티브 창 위치에는 네이티브 호스트가 필요하다.

## 인수 기준

- 같은 폴더의 경로 표기와 심볼릭 링크는 프로젝트 하나를 선택한다. 여러 창의 동시 열기에도 적용한다.
- 프로젝트 생성·이름 변경·제거·순서·고정·최근 열기 시각이 앱 재시작 후 유지되며 시작 시 프로젝트를 실행하지 않고 라이브러리를 표시한다.
- 공통 설정과 명시적 폴더별 덮어쓰기가 다시 로드·재시작 후 유지된다. 덮어쓰기를 제거하면 상속이 복원된다. 폴더별 설정에는 열기 방식이 없다.
- 앱 시작과 새 창은 콘텐츠 네이티브 표면이나 셸 없이 라이브러리를 표시한다. 두 열기 방식 모두 첫 프로젝트 생성·열기는 해당 OS 창을 재사용한다. 이미 프로젝트가 있는 창에서 다른 프로젝트를 열면 공통 열기 방식을 적용한다. 이미 열린 프로젝트는 기존 창을 선택한다.
- 선택한 프로젝트의 배치, 탭, 사이드바 너비, 테마 설정, 일반 창 좌표를 복원한다. 창을 닫아도 저장된 데이터를 유지한다.
- 두 창이 독립적으로 렌더링하고 입력을 수신한다. 설정 효과, 네이티브 표면, 셸, 제거 처리는 해당 창에만 적용한다.
- 두 네이티브 호스트에서 기존 표면 배치·소수점 렌더링·모달 검사를 계속 통과한다. 운영체제별 네이티브 동작을 구분해 기록한다.
