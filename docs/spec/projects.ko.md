# 프로젝트·설정·창

[English](projects.md)

독립 창 선언·배치·연결·레일 경계선 계약은 [외부 창 사이드바](external-sidebars.ko.md)에 정의한다. 카드 내부 변 계약은 독립적으로 유지한다.

이 명세는 앱의 프로젝트 등록 목록, 영구 설정, 프로젝트 창을 정의한다. [기능 상태](../features.ko.md)에 구현과 검증을 구분해 기록한다.

## 프로젝트 식별

프로젝트 하나는 존재하는 디렉터리 하나에 대응한다. 네이티브 호스트는 현재 사용자의 `~`를 확장하고 절대 경로와 심볼릭 링크를 해석하며 디렉터리인지 확인한 뒤 파일시스템 식별자를 반환한다. 프로젝트 등록 목록은 같은 식별자와 같은 정규 경로의 중복을 거절한다. 같은 디렉터리를 다시 열면 기존 프로젝트와 창을 선택하며 프로젝트를 추가하지 않는다. 프로젝트 이름은 변경할 수 있으며 식별 기준으로 사용하지 않는다.

앱 시작과 새 창 동작은 프로젝트를 선택하지 않은 일반 앱 창에서 프로젝트 라이브러리를 표시한다. 첫 프로젝트를 생성하거나 열면 같은 OS 창의 라이브러리를 작업 화면으로 교체한다. 라이브러리는 화면이며 별도 창 유형이나 임시 프로젝트가 아니다. 기존 작업 화면을 다시 로드하면 해당 창의 선택한 프로젝트를 유지한다. 디렉터리가 없으면 오류를 표시하고 저장된 프로젝트 데이터를 삭제하지 않으며 프로젝트 선택은 계속 사용할 수 있다.

라이브러리에는 머리줄 앞의 탭(`core.library.page`)으로 고르는 두 페이지, 프로젝트와 플러그인이 있다. 이 명세는 프로젝트를 정하고, [plugin 화면](installation.ko.md#plugin-화면)이 플러그인을 정한다. 프로젝트 페이지는 저장된 프로젝트, 배치 미리보기, 폴더 경로, 스페이스 수, 고정 프로젝트, 최근 열기 시각, 실제 프로젝트 열림 상태를 표시한다. 검색은 이름과 경로를 대상으로 한다. 프로젝트 격자는 콘텐츠의 전체 너비를 사용한다. 라이브러리에는 탐색 사이드바, 분류 필터, 별도 폴더 열기 동작, Git Clone 동작이 없다. 새 프로젝트는 선택한 부모 폴더에 이름을 지정한 디렉터리를 생성한다. 폴더 선택 취소와 작업 실패 후에도 현재 화면을 사용할 수 있다. 브라우저 예제는 입력한 폴더 경로를 등록하고 프로젝트 선택과 브라우저 창을 지원하지만 네이티브 디렉터리 생성은 지원하지 않는다.

배치 미리보기는 활성 스페이스에 저장된 카드 격자를 도식으로 표시한다. 카드 순서, 격자 범위, 분할 방향을 유지하며 간격과 행 높이를 일정하게 하고 사이드바 열을 좁게 표시한다. 콘텐츠 열은 남은 너비를 균등하게 사용한다. 테마 기반 색상, 둥근 모서리, 작은 콘텐츠 기호로 카드를 구분한다. 창 크기, 드래그한 분할 비율, 고정 픽셀 너비, 레일 외곽선은 미리보기 비율에 적용하지 않는다. 작업 화면을 열거나 렌더링 좌표를 저장하지 않고 저장된 배치 상태에서 미리보기를 생성한다. 콘텐츠 웹뷰나 셸을 생성하지 않는다.

제목 표시줄의 프로젝트 목록 버튼과 프로젝트 추가는 현재 작업을 유지하면서 같은 창에 라이브러리를 표시한다. 프로젝트 선택이나 작업 화면 복귀로 작업 화면을 복원한다. 새 창은 항상 프로젝트 미선택 창을 생성한다. macOS에서 모든 창을 닫아도 이 동작을 사용할 수 있도록 앱을 유지한다. 라이브러리 푸터, Command/Ctrl+Shift+N, macOS Dock 메뉴는 같은 동작을 실행한다. 라이브러리는 프로젝트 작업 화면에서 돌아온 경우에도 항상 공통 설정을 사용한다. 작업 화면으로 복귀하면 해당 프로젝트의 덮어쓰기를 다시 적용한다.

프로젝트에서 연 터미널이나 셸 표면은, 디렉터리를 알린 표면에서 쪼갠 경우가 아니면 프로젝트의 정규 루트에서 시작한다([탭 알림](plugins.ko.md#탭-알림)).

## 공통 외관

라이브러리와 프로젝트 작업 화면은 `app.css`의 글꼴, 색상, 테두리, 모서리, 간격 정의를 함께 사용한다. `library.css`는 라이브러리 배치와 컴포넌트 위치를 정의한다. 별도의 글자 크기 체계나 고정 테마 색상·모서리 반경을 정의하지 않는다.

설정한 글꼴과 기본 크기는 두 화면에 적용한다. 기본 크기 13px에서 프로젝트 이름·컨트롤은 12px, 보조 콘텐츠는 11px, 메타데이터·상태 문구는 10px을 사용한다. 이 크기들은 기본 크기에 비례한다. 본문과 컨트롤은 같은 행간과 일반 자간을 사용하고, 섹션 제목은 하나의 자간 값을 공유한다. 화면 제목은 별도의 큰 크기 대신 기본 크기를 사용한다.

라이브러리 컨트롤, 폼, 프로젝트 카드, 푸터는 작업 화면의 조밀한 간격과 테마 기반 테두리·모서리를 사용한다. 글꼴, 크기, 테마, 모서리 설정을 변경하면 두 화면에 같은 정의를 적용한다.

## 설정

라이브러리는 기본값과 공통 설정만 적용한다. 프로젝트 작업 화면은 해당 프로젝트의 명시적 덮어쓰기를 추가로 적용한다. 설정 대상으로 선택한 프로젝트가 적용값, 기본 저장 대상, 제공할 범위를 결정한다. 라이브러리는 창의 프로젝트와 저장된 덮어쓰기를 유지하면서 이 선택을 해제한다. 작업 화면 선택 시 설정 대상 프로젝트를 다시 지정한다.

모든 설정 절의 컨트롤 위에 전역·프로젝트 범위를 선택하는 가로 탭을 표시한다([설정 창](settings.ko.md)). 왼쪽 탐색에는 설정 분류만 표시한다. 라이브러리에는 전역만 제공하고 프로젝트 작업 화면에는 전역과 프로젝트를 제공한다. 라이브러리로 돌아오면 프로젝트에 저장된 덮어쓰기를 변경하지 않고 편집 범위를 전역으로 전환한다. 다른 분류를 선택해도 해당 컨트롤에 적용할 범위를 유지한다. 프로젝트 값을 제거하면 공통값을 다시 상속한다. 공통값을 변경하면 해당 값을 덮어쓰지 않은 모든 열린 프로젝트에 반영한다.

프로젝트 열기 방식은 공통 설정에만 있다. `tabs`는 현재 창에서 프로젝트를 열고, `windows`는 현재 창이 이미 프로젝트를 관리할 때 다른 프로젝트를 별도의 최상위 OS 창에서 연다. 프로젝트 미선택 창의 첫 프로젝트는 항상 같은 창에서 연다. 프로젝트 폴더 설정에서 이 값을 덮어쓸 수 없으며, 프로젝트 범위에서 이 키로 `core.settings.set`을 요청하면 -32602(잘못된 매개변수)로 실패하고 아무것도 바꾸지 않는다. 이미 열린 프로젝트를 선택하면 기존 창을 사용한다. 열기 방식 변경은 이후 프로젝트 열기에 적용하며 실행 중인 창과 셸을 닫지 않는다.

프로젝트 창은 독립 OS 창이다. 설정과 추가·분할 메뉴는 [네이티브 모달](native-modals.ko.md)에 정의한 창 내부 네이티브 웹뷰를 유지한다. 각 프로젝트 창은 활성 프로젝트, 표면, 모달, 테마, 입력 상태, 셸 구독을 관리한다. 한 창의 배치 준비, 다시 로드, 설정, 닫기가 다른 창의 네이티브 상태를 변경하면 안 된다.

## 저장

프로젝트 순서, 공통 설정, 폴더별 덮어쓰기, 스페이스, 활성 스페이스, 카드·탭 상태, 포커스 카드, 숨긴 사이드바를 포함한 사이드바·레일 너비, 사이드바마다 고른 탭과 접은 섹션, 프로젝트 창 크기·위치를 저장한다. 창의 프로젝트 소유 관계와 실행 중인 셸 프로세스는 런타임 상태다. 프로젝트 창을 닫아도 저장된 프로젝트와 화면 설정을 유지한다.

네이티브 호스트는 앱 설정 디렉터리의 `settings.json`에서 공통 설정을 읽고 프로젝트 디렉터리 내부의 `.soksak/settings.json`에서 프로젝트 덮어쓰기를 읽는다. 설정 파일이 없으면 덮어쓰기가 없는 상태다. 프로젝트 파일에는 명시적으로 변경한 값만 저장하며 키를 제거하면 상속을 복원한다. 공통 전용 키인 `projectOpening`은 프로젝트 설정에서 허용하지 않는다.

기본 앱 설정 디렉터리는 다음과 같다.

| 호스트 | macOS | Windows | Linux |
| --- | --- | --- | --- |
| Wails | `~/Library/Application Support/app.soksak.wails` | `%AppData%/app.soksak.wails` | `$XDG_CONFIG_HOME/app.soksak.wails`, 미설정 시 `~/.config/app.soksak.wails` |
| Tauri | `~/Library/Application Support/app.soksak.tauri` | `%AppData%/app.soksak.tauri` | `$XDG_CONFIG_HOME/app.soksak.tauri`, 미설정 시 `~/.config/app.soksak.tauri` |

디렉터리 이름은 애플리케이션 식별자다. 디버그 대상이 만드는 진단 빌드는 `.dev`를 붙이므로(`app.soksak.wails.dev`, `app.soksak.tauri.dev`) 개발 빌드는 release 애플리케이션의 데이터를 읽거나 쓰지 않는다. 각 언어의 command line package가 식별자를 가지며(`packages/sok/<app>/src/identity.*`), host는 그것을 쓴다.

0.0.2까지의 버전은 release 디렉터리 이름을 `com.soksak.wails`와 `com.soksak.tauri`로 썼다. `--config-dir` 없이 시작한 release host는 이전 디렉터리만 있으면 디렉터리를 준비하기 전에 이전 디렉터리를 현재 이름으로 바꾸고, 애플리케이션 로그에 두 경로를 적는다(`configuration directory moved from <former> to <current>`). 둘 다 있으면 host는 시작하지 않고 시작할 때 받은 표준 오류에 `<former> and <current> both exist; move or remove <former>`를 보고한다. 이전 디렉터리의 `process.lock`이 실행 중인 프로세스를 가리키면 이전 애플리케이션이 아직 그 디렉터리를 쓰는 것이다. host는 시작하지 않고 `<former> is in use by process <pid>; quit that application first`를 보고한다. 끝난 프로세스의 lock은 디렉터리와 함께 옮겨지고, 끝난 프로세스의 [endpoint](endpoint.ko.md) lock처럼 교체된다. `--config-dir` 없는 release `sok`은 디렉터리를 옮기거나 만들지 않는다. 이전 디렉터리가 있는 동안 `<former> has not been moved; start the application once to move it to <current>`로 실패하거나, 둘 다 있을 때의 오류로 실패한다. 진단 빌드는 이전 디렉터리를 쓰지 않는다.

`--config-dir PATH`로 앱 설정 디렉터리를 변경한다. 호스트는 빈 경로를 거부하고, 경로에서 없는 디렉터리를 권한 0700(소유자 전용)으로 만들며, 이미 있는 디렉터리의 권한은 유지하고, 정규 경로를 쓴다. 프로젝트 덮어쓰기 경로는 각 프로젝트 내부를 유지한다. 전역 편집은 공통 설정 파일을, 프로젝트 편집은 선택한 프로젝트의 설정 파일을 변경한다. **전역값 사용**으로 개별 덮어쓰기를 제거한다. 프로젝트 탭을 드래그해 순서를 변경하며 이 순서를 라이브러리의 기본 순서로 사용한다. 탭의 ×는 등록 목록에서 프로젝트를 제거하고 폴더와 설정 파일은 유지한다. OS 창의 닫기 버튼은 등록된 프로젝트를 유지한다.

앱 설정 디렉터리의 `projects.json`에는 정렬된 프로젝트 목록, 프로젝트 화면 상태, `plugins` 아래의 프로젝트별 플러그인 데이터([프로젝트 데이터](plugins.ko.md#프로젝트-데이터))를 저장한다. Wails와 Tauri는 각각의 앱 설정 디렉터리를 사용한다. 네이티브 호스트는 변경을 직렬화하고 대상 파일을 다시 읽은 뒤 수정하며 같은 디렉터리에 임시 파일을 작성하고 쓰기를 완료한 후 대상 파일을 교체한다. 교체가 성공한 뒤 열린 창에 변경을 알린다. 다시 로드하거나 프로젝트를 선택하면 설정 파일을 다시 읽는다. 저장 실패를 화면에 표시하며 기본값으로 초기화하거나 저장된 데이터를 조용히 덮어쓰지 않는다. 준비된 프로젝트 창을 닫을 때 대기 중인 저장을 완료한 뒤 네이티브 자원을 제거한다. main page 다시 읽기는 준비된 페이지에 대기 중인 저장을 완료하게 한(`core.projects.flush`) 뒤 페이지를 바꾼다. 앱 종료 시 준비된 모든 창에 같은 저장을 요청한 뒤 종료한다.

스페이스를 열 때 표시 배치를 교체하기 전에 내용 탭·활성 탭·고정 사이드바 ID·`{width}` 레코드를 검증한다. 이전 창 사이드바 형식으로 저장된 배치는 저장소를 읽을 때 한 번 변환된다. `edgeWidth` 폭은 `windowSidebars`의 `{width}` 레코드가 되고, 레일 카드가 더는 없으므로 `railWidth`는 버리고, 카드의 `panels`는 그 카드의 `sidebars`가 되며, inset `sidebar`는 카드가 왼쪽을 지정하지 않았으면 왼쪽 사이드바의 크기와 접힘이 되고, 내용 카드 ID로 저장한 사이드바 선택은 `<card>:left` 선택이 없으면 그 이름으로 옮기며, 변환한 스페이스를 저장하고 애플리케이션 로그에 프로젝트와 각 변경을 남긴다. 불러오지 않은 플러그인의 탭은 placeholder 카드로 연다([플러그인](plugins.ko.md#불러오지-않은-플러그인)). 빈 내용 탭, 저장 소유자 필드, 플러그인별 사이드바 ID, 오래된 레일 카드, 두 형식을 함께 가진 배치는 이유와 함께 명시적으로 실패하며, 라이브러리 미리보기가 그 이유를 보인다. 저장 사이드바 설정은 미등록 섹션이나 잘못된 연결이면 실패한다([설정 창](settings.ko.md#저장되는-세트와-연결)). 라이브러리 미리보기는 각 프로젝트의 활성 스페이스에 같은 검증을 적용한다. 저장 배치가 실패한 프로젝트는 미리보기 대신 그 오류를 보이고 `core.library`의 `previewErrors`로 보고한다. 명시적 null 폭·섹션 선택 레코드는 잘못된 값이며 선택 필드가 없을 때만 선언된 빈 레코드 기본값을 사용한다.

스페이스의 배치는 `sidebars`를 저장한다. 사이드바 ID(`left`, `right`, 카드 내부 사이드바의 `카드id:변`)마다 `{tab, folded}`이며 `tabs` 세트에서 고른 섹션 ID 또는 null과 `list` 세트에서 접은 섹션 ID다. 선택은 스페이스마다 둔다. 오버라이드는 동일한 고정 사이드바의 내용을 바꾸며 식별자를 바꾸지 않는다. 선택을 바꾸면 다른 배치 변경처럼 저장된 스페이스가 바뀐다. `sidebars`가 없는 배치에는 저장된 선택이 없고 저장 섹션 선택은 해당 섹션이 선택 세트에 있을 때만 적용된다.

브라우저 예제는 브라우저 창과 IndexedDB 저장소를 사용하며 네이티브 폴더에 설정을 작성하지 않는다. 입력한 경로만으로 네이티브 파일시스템 식별자를 확인할 수 없으므로 디렉터리 식별과 네이티브 창 위치에는 네이티브 호스트가 필요하다.

## 인수 기준

- 같은 폴더의 경로 표기와 심볼릭 링크는 프로젝트 하나를 선택한다. 여러 창의 동시 열기에도 적용한다.
- 프로젝트 생성·이름 변경·제거·순서·고정·최근 열기 시각이 앱 재시작 후 유지되며 시작 시 프로젝트를 실행하지 않고 라이브러리를 표시한다.
- 프로젝트 덮어쓰기가 있는 작업 화면에서 돌아온 경우에도 라이브러리는 항상 공통 설정을 적용하고 편집한다. 작업 화면으로 복귀하면 프로젝트 덮어쓰기를 복원하고 두 편집 범위를 제공한다.
- 공통 설정과 명시적 폴더별 덮어쓰기가 다시 로드·재시작 후 유지된다. 덮어쓰기를 제거하면 상속이 복원된다. 폴더별 설정에는 열기 방식이 없다.
- 앱 시작과 새 창은 콘텐츠 네이티브 표면이나 셸 없이 라이브러리를 표시한다. 두 열기 방식 모두 첫 프로젝트 생성·열기는 해당 OS 창을 재사용한다. 이미 프로젝트가 있는 창에서 다른 프로젝트를 열면 공통 열기 방식을 적용한다. 이미 열린 프로젝트는 기존 창을 선택한다.
- 선택한 프로젝트의 배치, 탭, 사이드바 너비, 테마 설정, 일반 창 좌표를 복원한다. 창을 닫아도 저장된 데이터를 유지한다.
- 등록되지 않은 플러그인을 가리키는 저장된 스페이스는 검증 오류로 열리지 않고, 라이브러리 미리보기도 같은 오류를 보인다. 저장 기록은 바뀌지 않는다.
- host가 폴더를 읽을 수 없는 프로젝트는 library card의 폴더 경로 아래에 이유를 보이고, `core.library`는 host의 문구를 `folderErrors`에 보고한다. 두 host는 [`workspace.folder.messages`](host-contract.md)의 문구를 쓴다. card는 선언된 문구(폴더 없음, 읽기 권한 없음, 파일)를 경로 없는 이유로 보이고, 그 밖의 문구는 그대로 보인다. library는 보일 때마다, 그리고 registry가 바뀔 때마다 host에 다시 묻는다. card의 열기 버튼은 비활성화되며, 명령으로 그 프로젝트를 열면 host의 문구로 실패한다. 기록은 사용자가 card의 제거 버튼(`core.library.remove`)으로 지울 때까지 library에 남는다. 제거는 프로젝트 탭 닫기처럼 기록과 스페이스를 지우며 폴더는 바꾸지 않는다.
- 두 창이 독립적으로 렌더링하고 입력을 수신한다. 설정 효과, 네이티브 표면, 셸, 제거 처리는 해당 창에만 적용한다.
- 두 네이티브 호스트에서 기존 표면 배치·소수점 렌더링·모달 검사를 계속 통과한다. 운영체제별 네이티브 동작을 구분해 기록한다.
