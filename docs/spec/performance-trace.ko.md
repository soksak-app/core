# 성능 트레이스

[English](performance-trace.md)

성능 트레이스는 애플리케이션이 시간과 메모리를 무엇에 쓰는지 기록하는 영구 장치다. 모든 빌드에 있고 사용 후 제거되지 않는다. 스위치는 선언된 설정 `diagnostics.performance`([설정](settings.md))이고, false 인 동안 어떤 계층도 기록 일을 하지 않는다 — 파일이 만들어지지 않고 포맷팅이 돌지 않는다.

## 출력

이벤트는 구성 디렉터리의 `logs/performance.ndjson` 에 덧붙는다. 모든 줄이 하나의 이벤트 객체로 최소한 `ts`(밀리초를 포함한 ISO-8601), `pid`(기록한 프로세스), `layer`(`page`, `host`, `vt-core`, `files`, `shell`, `sampler`), `event` 를 담고 나머지 필드는 이벤트마다 다르다. 한 파일이 모든 계층을 담으므로 한 타임라인에서 앱 전체를 읽는다. 파일은 10 MB 에서 `performance.ndjson.1` 로 로테이션하며 이전 세대 하나만 남긴다; 로테이션과 파일은 트레이스의 소유물이므로 스위치가 꺼진 재시작에도 옛 로그는 남는다. 각 프로세스 시작은 `session_start` 이벤트로 표시하고 기록자의 역할을 담는다.

## 생산자

모든 계층이 생산자다; 트레이스는 어느 한 계층으로 정의되지 않는다.

- **페이지** — 모든 `core.*` 와 플러그인 명령의 이름·시간·결과 등급; exposure 감시 통지량; 레이아웃 큐의 대기와 대체; 그리드 렌더; 카드·탭 조작; 표면 마운트 생명주기; 컴포지터 게시와 클립 갱신; screen 이벤트 처리시간; 설정·프로젝트·재로딩 마커; JS 힙; 값을 담은 사용자 행위 마커(창 리사이즈는 크기를, 탭 전환은 id 를 담는다). 페이지는 파일시스템이 없으므로 자기 줄은 덧붙이는 호스트 명령으로 중계한다.
- **호스트**(양호스트 패리티 짝) — 모든 엔드포인트 메서드의 이름·시간·결과 등급; 값을 담은 창 이벤트(크기·이동·포커스·가림·배율); 기하를 담은 표면 생명주기(생성·파괴·배치·가시성); 표시 장벽 대기시간을 포함한 문서·이미지·합성 연산; 어긋난 값 그대로를 담은 프로토콜 거부; 뜨는 모든 pid 와 역할을 적는 프로세스 등록부; 사이드카 기동·종료.
- **사이드카**(`vt-core`, `files`, `shell`) — 요청 처리의 연산·시간·결과. `vt-core` 는 프레임을 그린 이유(`output`, `blink`, `resize`, `metrics`, `selection`)와 그리기·전송·consumed 대기 시간을 각각의 필드로, 래스터 크기를 담은 프레임 이벤트; PTY 읽기 바이트 수와 앞뒤 격자를 담은 PTY 재조정; 세션 생명주기를 더한다.
- **샘플러** — 5초마다 등록부가 이름 붙인 모든 프로세스의 상주 크기, 메모리 판독이 스스로 귀명되도록.

## 플래그 전달

페이지와 각 호스트는 이미 읽는 설정에서 `diagnostics.performance` 를 읽는다. 자기 기록을 켠 호스트는 각 사이드카의 서비스 디렉터리에 `performance` 플래그 파일을 쓴다; 사이드카는 기동과 세션 열 때마다 플래그를 확인하므로 호스트와 사이드카 사이의 프로토콜은 바뀌지 않는다.

## 읽기

파일은 NDJSON 이라 도구로 곧바로 답한다: 대기 터미널의 프레임 이유(`select(.event=="frame") | group_by(.reason)`), 붕괴를 지나는 끌기가 만든 래스터 값(`select(.event=="configure")`), 탭 전환이 웹뷰를 재생성했는가(`select(.event=="surface")`), 사용자 행위 주변에서 메모리가 무엇을 했는가(`select(.event=="action")`).
