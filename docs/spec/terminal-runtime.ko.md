# 터미널 런타임

[English](terminal-runtime.md)

이 계약은 승인된 터미널 런타임을 정의한다. 구현과 검증은 [기능 상태](../features.ko.md)에서 추적하며, 계약 승인이 구현 완료를 뜻하지 않는다.

## 소유권과 프로세스 수

앱 설정 디렉터리마다 영속 터미널 서비스 하나가 PTY, VT 상태, 스크롤백, 렌더링을 소유한다. PTY 관리, 에뮬레이션, 렌더링, 클라이언트 전송은 같은 프로세스의 별도 모듈이며 별도 실행 파일이 아니다. 독립 세션은 각각 PTY 장치와 셸 프로세스를 소유한다. PTY 장치는 프로세스가 아니다. 독립 터미널 3개는 앱 호스트 외에 서비스 하나와 셸 3개를 요구한다. WebKit 프로세스와 셸이 실행한 프로그램은 별도로 센다.

표면 연결은 세션이 아니다. 표면 키에 대한 첫 열기는 레지스트리 actor 하나를 생성하고 셸 시작 전에 안정적인 세션 식별자를 배정하며, 같은 생성 식별자의 반복 요청은 같은 결과를 반환한다. 대체 표면 연결은 PTY를 생성하지 않는다. 활성 연결이 입력과 크기 변경 권한을 소유하고 오래된 연결에는 명시적 오류를 반환한다. 연결된 표면이 없으면 세션의 터미널 크기를 유지한다.

세션은 터미널 설정 `terminal.shell`이 가리키는 셸을 시작한다. 기본값 `login`은 계정의 사용자 데이터베이스 항목에 있는 로그인 셸이고, 그 밖의 값은 실행할 수 있는 파일의 절대 경로여야 한다. 셸은 로그인 셸로 시작한다. `argv[0]`은 `-`와 파일 이름이고 `SHELL`은 셸 경로다. 터미널 페이지는 이 값을 `open` 요청의 `shell`로 보내고, 워크벤치는 백그라운드 세션에 플러그인의 `background.settings`를 통해 보낸다. 값이 없거나, 상대 경로이거나, 파일이 없거나 실행할 수 없거나, 계정에 로그인 셸이 없으면 명시적 오류이며 다른 셸을 대신 시작하지 않는다. 설정을 바꾸면 그 뒤에 여는 세션에 적용된다.

`open` 요청은 셸이 시작할 디렉터리로, 있는 디렉터리의 절대 경로인 `directory`를 가질 수 있다. 다른 값은 명시적 오류이며 다른 디렉터리를 대신 쓰지 않는다. 없으면 셸은 계정의 홈 디렉터리에서 시작한다. 터미널 페이지는 표면의 `origin.directory`([탭 알림](plugins.ko.md#탭-알림))가 `null`이 아니면 그것을 보내므로, 터미널에서 쪼갠 터미널은 그 터미널이 마지막으로 알린 디렉터리에서 시작한다.

사이드카는 zsh와 bash를 OSC 133 표시를 보내는 셸 통합과 함께 시작하며, 사용자의 파일은 바꾸지 않는다. 통합 스크립트는 사이드카에 포함되어 있고, 세션을 시작하기 전에 `<임시 디렉터리>/soksak-shell-<내용 해시>/`(모드 0700)에 기록된다. zsh에는 `ZDOTDIR`를 그 디렉터리로 지정하고 기존 `ZDOTDIR`는 `SOKSAK_ZSH_ZDOTDIR`에 보관한다. 그 디렉터리의 `.zshenv`는 원래 `ZDOTDIR`를 되돌리고, 사용자의 `.zshenv`를 읽고, 대화형 셸이면 훅을 설치한다. zsh는 나머지 시작 파일을 되돌린 디렉터리에서 읽는다. bash에는 스크립트 경로를 담은 `SOKSAK_BASH_INTEGRATION`과, 첫 항목이 현재 `DEBUG` 트랩을 기록한 뒤 그 스크립트를 읽는 `PROMPT_COMMAND`를 내보낸다. bash 3.2에서 `source`로 읽는 파일은 `DEBUG` 트랩을 보지 못하기 때문이다. 시작 파일이 `;`로 앞이나 뒤에 항목을 더할 수 있도록 항목 뒤에 구분자를 두지 않는다. 셸은 시작 파일을 그대로 읽고, 첫 프롬프트에서 스크립트가 `PROMPT_COMMAND`에서 자기 항목을 지우고(다른 항목 사이의 항목은 `:`가 된다), 두 변수의 내보내기를 멈추고, 사용자 항목의 앞과 뒤에 자기 훅을 둔다. bash 3.2는 `sh`로 실행될 때만 `ENV`를 읽고 셸은 `argv[0]`이 `-bash`인 로그인 셸이어야 하므로, 사이드카는 bash를 `ENV`와 POSIX 모드로 시작하지 않는다. 사용자의 시작 파일이 `PROMPT_COMMAND`를 바꿔 쓰면 스크립트는 실행되지 않고, 세션은 통합이 없는 셸처럼 동작한다. 다른 셸은 통합 없이 시작한다.

훅은 각 프롬프트 전에 `133;A`, 명령 실행 전에 `133;C`, 다음 프롬프트 전에 `133;D;<상태>`를 보낸다. 각 프롬프트 전에는 작업 디렉터리도 `7;file://<호스트 이름><경로>`로 알리며, 경로는 예약되지 않은 문자와 `/` 밖의 문자를 퍼센트 인코딩한다. zsh는 `preexec` 훅에서 `C`를 보낸다. bash 3.2에는 그런 훅이 없으므로 `DEBUG` 트랩이 프롬프트 뒤 첫 명령에서 `C`를 보낸다. 빈 입력 행은 명령 없이 `PROMPT_COMMAND`를 실행하므로, `PROMPT_COMMAND`의 첫 항목이 대기를 취소한다. 스크립트가 자신을 설치하는 프롬프트에서는 자기 항목 뒤의 항목이 트랩이 생긴 뒤에 실행되므로, 그 프롬프트에서 그 항목들 중 하나와 텍스트가 같은 명령은 알리지 않는다. 트랩은 `$_`를 마지막 인수로 넘겨 다음 명령의 `$_`를 유지한다. 시작 파일이 `DEBUG` 트랩을 설정했으면, `C` 없는 `A`는 크기 변경 때 명령 출력을 지우므로 스크립트는 그 트랩을 바꾸지 않고 표시도 보내지 않는다.

서비스 엔드포인트는 설정 디렉터리로 범위를 제한하고 인증, 버전, 단일 인스턴스 잠금을 갖춘다. 테스트 설정은 다른 설정의 서비스를 탐색하지 않는다. 세션 상태와 입력 큐는 격리한다. 바쁜 세션이 읽기, 쓰기, 해석, 렌더링 중 전역 잠금을 점유해서는 안 된다.

## 종료와 복구

### 서비스 전송

사이드카 선언은 `transport: "persistent"`를 선택한다. 이 필드가 없는 사이드카는 해당 도메인의 stdio 전송을 사용한다. 호스트는 선언한 실행 파일을 `--service-dir <config-dir>/services/<executable-name>`으로 시작한다. 서비스는 해당 디렉터리의 독점 잠금을 얻은 뒤 리스너를 생성한다. Unix 소켓 경로 제한을 지키도록 접근 제한된 짧은 임시 디렉터리에 소켓을 만들고 `{protocol: 1, pid, socket, token}`의 `endpoint.json`을 원자적으로 게시한다. 디렉터리 권한은 0700, 토큰을 담은 파일은 0600이다. stdout 준비 줄은 리스너가 준비된 뒤에만 해당 엔드포인트를 담는다. 서비스는 엔드포인트를 게시하기 전에 기본 터미널 글꼴을 읽고, 호스트는 시간 제한 없이 준비 줄을 기다린다. 따라서 서비스 프로세스의 첫 CoreText 호출은 그 프로세스의 첫 터미널만 늦춘다. 이 비용은 서비스 프로세스마다 한 번 생기고 서비스가 앱 재시작보다 오래 살아 있으므로 받아들인다.

첫 줄 단위 JSON 메시지는 `{operation: "hello", protocol: 1, token, client}`다. 서비스는 `{operation: "hello", protocol: 1, ok: true}` 또는 `{operation: "hello", ok: false, error}`로 답한다. 인증 후 표면 메시지는 선언된 사이드카 봉투를 유지한다. `{operation: "close-owner", request}`는 인증한 클라이언트의 세션을 종료하고 정리 뒤 `{operation: "closed-owner", request, ok: true}` 또는 `ok: false`와 `error`로 답한다. `{operation: "shutdown", request}`는 소유자 닫기 이후에만 수락하고 `{operation: "shutdown", request, ok: true}`로 답하며, 클라이언트 연결이 모두 종료된 뒤 서비스를 종료하도록 허용한다. 소켓 EOF는 세션을 보존한다. 엔드포인트 파일만으로 해당 PID를 종료하지 않으며 프로토콜·인증 실패 시 경쟁 서비스를 시작하지 않는다.

표면 숨김, 라이브러리 이동, 앱 연결 단절은 세션을 보존한다. 터미널의 명시적 닫기는 해당 세션을 종료한다. 정상 창 닫기는 그 창 소유 세션을, 정상 앱 종료는 모든 소유 세션을 종료한다. 관리 대상 작업 종료, 자식 회수, PTY 핸들 해제, 출력 완료 또는 실패 보고, 연결 작업 제거 후에만 종료 완료다. 종료 오류를 성공으로 바꾸지 않는다.

앱 충돌과 명시적 업데이트 재시작은 서비스를 유지한다. 재연결은 같은 세션, 셸 프로세스, VT 상태, 스크롤백을 복원하며 새 앱 프로세스의 네이티브 이미지는 새로 만들고 프로세스 사이에서 재사용하지 않는다. 서비스는 연결이 없어도 출력을 읽고 해석한다. EOF는 연결 단절이며 세션 종료 명령이 아니다. 종료 의도를 응답 전에 기록하여 중단된 닫기가 의도적으로 종료한 세션을 복원하지 않게 한다.

명시적 shutdown 요청이 있고 클라이언트가 모두 없어야 서비스를 종료한다. 프로젝트 레이아웃이 표면을 가지고 있는 동안 세션은 복구할 수 있다. `{operation: "retain", request, surfaces: [{surface, root}]}`은 인증된 클라이언트의 세션 가운데 root와 표면이 목록에 없는 세션을 모두 닫고, 닫은 수와 함께 `{operation: "retained", request, ok: true, closed}`로, 또는 `ok: false`와 `error`로 답한다. 페이지는 시작할 때와 프로젝트를 지우거나 공간을 닫은 뒤, 모든 프로젝트의 모든 공간 레이아웃의 표면을 프로젝트 root와 함께 보낸다. 호스트는 이 앱 프로세스가 보낸 모든 표면을 더하고, 실행 중이거나 엔드포인트를 게시한 각 영속 서비스에 요청을 전달한다. 따라서 충돌이나 실패한 페이지가 닫힘 알림 없이 남긴, 어떤 레이아웃도 갖지 않은 표면의 세션은 앱이 다시 시작할 때 끝난다. 서비스 장애와 OS 재시작은 실행 프로세스 복구 범위 밖이며 새 셸 생성은 복구 증거가 아니다. 공유 서비스는 하나의 프로세스 장애 범위다. 세션 격리가 프로세스 수준 충돌 격리를 의미하지 않는다.

앱 업데이트는 프로토콜 버전이 일치할 때만 실행 중 서비스에 재연결한다. 불일치는 명시적 실패이며 두 번째 서비스 시작, 기존 작업 종료, 호환 경로 사용으로 처리하지 않는다. 서비스 자체 교체는 세션 종료까지 기다린다.

## 터미널 입력과 표시

터미널을 한 번 클릭하면 선언된 `terminal.focus` 명령을 통해 네이티브 그림 영역으로 키보드 소유권을 옮긴다. 네이티브 터미널 입력 뒤 다음 합성 포인터를 전달하기 전에 host가 대상 문서 웹뷰를 응답자로 복원하므로 네이티브 그림 응답자가 다음 클릭을 가로막지 않는다. DOM 앵커는 포인터의 기본 DOM 포커스 동작을 막아 같은 클릭 중 WebKit이 소유권을 되찾지 않게 한다. 카드 선택은 여전히 이벤트를 받는다. 두 번째 클릭, 지연 재포커스, 테스트 전용 포커스 명령은 필요하지 않다. 포커스 요청 오류는 관측 가능해야 한다. 모달 포커스 복원과 그림 포커스 통지는 현재 AppKit/Tauri 콜백이 끝난 뒤로 미뤄야 하며 WebView 이벤트 경로에 동기 재진입해서는 안 된다.

엔진, PTY, 표시 래스터는 적용된 크기가 같아야 한다. 폭을 좁히면 기본 화면의 자동 줄바꿈 행을 재배치하고, 넓히면 같은 논리적 행을 합친다. 명시적 개행은 유지한다. 대체 화면 앱은 터미널 제어 배치 의미를 유지한다. 디바이더 이동은 글꼴 메트릭을 바꾸거나 래스터 기하를 애니메이션하지 않는다.

엔진은 OSC 133 표시로 셸 상태를 유지한다. `A`와 `B`는 표시의 `redraw` 매개변수(없으면 `1`, 또는 `0`, `last`; `1`과 `last`는 같게 동작한다; 다른 값은 거부한다)와 함께 프롬프트 상태를 정하고, `C`와 `D`는 출력 상태를 정한다. `A`는 커서가 0열에 있지 않으면 먼저 커서를 다음 행의 시작으로 옮긴다. 프롬프트 상태에서 `redraw`가 `0`이 아닐 때 기본 화면의 크기가 바뀌면, 엔진은 재배치하고, 커서가 있는 논리적 행의 첫 행부터 화면 끝까지의 행을 지우고, 재배치 전에 커서가 논리적 행의 첫 행에서 떨어져 있던 행 수만큼 그 첫 행 아래에 있는 행의 0열로 커서를 옮긴다. 그 행이 화면 아래를 넘으면 화면을 위로 올린다. zsh와 bash(readline)는 `SIGWINCH` 뒤 마지막으로 그린 폭에서의 커서 행 수만큼 올라가 프롬프트를 다시 그리므로 첫 행에서 다시 시작하고, 지운 행에는 이전 폭의 행이 남지 않는다. 셸이 다시 그리기 전에 크기가 다시 바뀌면 셸은 더 이상 현재가 아닌 폭으로 그릴 수 있다. 이때 프롬프트 위의 행을 덮어쓸 수 있다. 현재 크기와 같은 크기로의 변경은 PTY가 `SIGWINCH`를 보내지 않으므로 아무것도 바꾸지 않는다. 통합이 없는 셸은 표시를 보내지 않으며, 크기 변경 뒤 셸 자신의 다시 그리기가 이전 폭의 행을 남길 수 있다.

화면 지우기 2(`ESC[2J`)는 현재 배경색으로 화면의 모든 칸을 지우고 기록과 커서를 그대로 둔다. 그래서 기록(`ESC[3J`)을 지운 뒤 화면을 지우는 `clear` 뒤에는 되돌려 볼 기록도 스크롤바도 없다. 화면 지우기 1(`ESC[1J`)은 커서 위의 모든 행과 커서 행의 처음부터 커서 칸까지 지운다. 엔진의 격자 라이브러리는 `ESC[2J`에서 보이는 행을 기록으로 올리고, 커서가 둘째 행이면 `ESC[1J`에서 첫 행을 남기므로, 엔진은 두 시퀀스를 라이브러리에 넘기지 않고 출력 안의 그 위치에서 직접 적용한다.

사이드카는 래스터를 그리는 것과 페이지의 `screen` 이벤트를 함께 보내며, 호스트가 앞 래스터에 `consumed`로 답한 뒤에만 그렇게 한다. 호스트가 래스터를 가진 동안 화면을 바꾸는 출력, 스크롤, 입력은 그리거나 보내지 않고 변경만 표시한다. 호스트가 답하면 사이드카는 현재 화면을 한 번 그리고 그 `screen` 이벤트 하나를 보낸다. 따라서 출력이 몰리면 출력 조각마다가 아니라 호스트의 답마다 래스터 하나와 `screen` 이벤트 하나가 생긴다. 그래서 페이지가 출력보다 뒤처지지 않는다. 페이지 `screen` 이벤트의 셀은 글자가 있으면 `ch`, `width`, 링크이면 `link`를 가지며, `bold`, `italic`, `underline`, `inverse`는 켜져 있을 때만 가진다. 색은 래스터가 그리므로 싣지 않는다.

터미널 래스터는 유효한 애플리케이션 외관을 따른다. 표면 페이지는 애플리케이션 외관이 바뀔 때 `{ "mode": "dark" }` 또는 `{ "mode": "light" }`를 담은 `theme`를 터미널 사이드카에 보낸다. 사이드카는 다른 모드를 명시적으로 거부한다. 선택한 모드는 기본 전경·배경·커서와 인덱스 ANSI 색상을 이후 및 기존 화면 셀에 적용하며 PTY, 세션, 텍스트, 커서 위치, 셀 메트릭을 다시 만들지 않는다. 모드는 이미지 표면 속성이며 다음 완전한 프레임에 적용된다. 전송 중인 래스터는 변경하지 않는다.

터미널 탭은 프로그램 제목을 보인다. 페이지는 OSC 0이나 OSC 2 제목을 `tab.title`로 알리고 제목 초기화에서 지운다. 터미널 설정 `terminal.title`은 `program`(기본값)이나 `name`을 고른다. `name`이면 페이지는 제목을 알리지 않고 보이던 제목을 지우며, 다시 `program`으로 바꾸면 프로그램이 마지막으로 정한 제목을 보인다. `tab.title`이 거부한 제목은 세션 오류다. OSC 8 하이퍼링크 안의 셀은 화면에서 URI를 `link`로 가지며, 래스터는 SGR 4 글자처럼 밑줄을 긋는다. 링크 셀 위의 포인터는 손 모양이다. 링크 셀을 Command와 함께 클릭하면 그 URI로 선언된 명령 `terminal.link.open`을 실행해 `runtime.links.open`([링크 열기](plugins.ko.md#링크-열기))으로 열며, 그 클릭은 선택을 시작하지 않는다. Command 없는 클릭은 선택 동작을 유지한다. 호스트가 거부한 URI는 입력 세션 오류다. 페이지는 OSC 9 알림마다 `tab.notify`에 넘기며, 거부된 알림은 세션 오류다. 애플리케이션은 애플리케이션 번들 밖의 실행 파일로 실행되고 macOS 알림 센터는 번들을 요구하므로(센터를 요청하면 잡히지 않는 예외로 프로세스가 끝난다), 알림은 탭 알림으로만 보인다. 페이지는 OSC 7 이벤트마다 디렉터리를 `tab.directory`로 기록한다. 사이드카의 `directory` 이벤트는 URI와 `path`를 가지며, `path`는 스킴이 `file`이나 `kitty-shell-cwd`이고 호스트가 비었거나 `localhost`이거나 이 컴퓨터의 호스트 이름이면 퍼센트 디코딩한 절대 경로이고, 다른 컴퓨터의 디렉터리이면 `null`이며 이때 기록한 디렉터리를 지운다. 다른 스킴이나 상대 경로, 디코딩할 수 없는 경로의 URI는 엔진 오류로 거부한다.

커서 상태는 위치·표시 여부·모양·깜빡임 정책·색상을 포함한다. 커서 정책은 명시적으로 관리한다. 모양은 `block`·`underline`·`beam`, 깜빡임은 `Never`·`Off`·`On`·`Always`, 간격은 양의 밀리초(기본 750), 유휴 제한 시간은 0 이상 밀리초(기본 5000, 0은 제한 없음), 비포커스 모양은 `hollow`·`solid`·`underline`·`beam`·`unchanged`다. 기본은 포커스 시 채워진 block과 `Off`, 비포커스 시 steady hollow block이다. `Never`와 `Always`는 프로그램 깜빡임 요청보다 우선하고 `Off`와 `On`은 프로그램 요청을 허용한다. 프로그램 커서 모양은 설정 기본값보다 우선한다. 프로그램 가시성은 권위 값이다. 터미널 모듈은 사이드카가 `cursor` 연산에 답한 뒤에 그 정책을 `terminal.cursor`에 보고한다. 사이드카는 그 정책으로 그린 프레임을 표시한 뒤에 답한다. `terminal.cursor`는 `drawn`도 알린다. 이는 프로그램의 요청과 초점 규칙을 적용해 사이드카가 그린 모양(`block`, `underline`, `beam`, `hollowBlock`, `hidden`)과 깜빡임 요청이다. 사이드카가 표시하는 모든 래스터는 그 래스터가 그린 화면의 screen 이벤트를 함께 싣는다. 그래서 초점 변경이나 다른 다시 그리기가 위치, 초점, `drawn`을 픽셀과 함께 바꾼다. 렌더링은 커서 픽셀만 바꾸며 페이드·크기 애니메이션을 사용하지 않고 PTY나 셀 메트릭을 재생성하지 않는다. 커서는 그 위치에 표시된 조합 문자열을 포함해 그 위치 글자의 표시 폭만큼 덮는다. 넓은 글자는 두 칸 커서가 덮으며 커서는 마지막 열을 넘지 않는다. 글리프 폭이 두 칸보다 좁은 넓은 글자(대체 글꼴로 그리는 한글 등)는 제 크기로 두 칸 안에서 가로 가운데에 그리고, 칸만큼 넓거나 더 넓은 글리프는 첫 칸에서 시작한다.

정책은 터미널 플러그인의 `plugin.json`에 선언하고, 애플리케이션의 초기값은 `environment.json`에서 받으며, 이후 유효한 공통/프로젝트 설정을 따른다. 워크벤치는 저장 전에 선언 규칙으로 각 값을 검증하고 잘못된 값이면 부분 patch를 적용하지 않고 명시적인 오류를 보고한다. 마운트된 터미널 표면에는 유효한 플러그인 내부 설정을 전달하며, 터미널 표면은 시작 시와 유효 설정이 바뀔 때마다 완전한 정책을 사이드카로 보낸다.

터미널 프로그램의 클립보드 접근은 사용자가 명시적으로 붙여넣는 동작과 별개다. 선언된 `clipboard.program` 설정은 `deny` 또는 `allow`이며 기본값은 `deny`다. 거부 시 OSC 클립보드 저장/조회 요청은 관측 가능한 정책 오류를 내고 호스트 클립보드에 쓰지 않으며 대기 중인 조회 callback도 남기지 않는다. 허용 시에도 선언된 텍스트 클립보드 대상만 처리하고, 지원하지 않는 selection 대상과 부재/비텍스트 값은 명시적 오류로 남긴다. 사용자 `terminal.paste` 명령에는 이 프로그램 권한을 적용하지 않는다.

네이티브 IME가 조합 문자를 소유한다. 조합 중에는 preedit를 표시하고 미완성 음절을 PTY에 쓰지 않는다. 확정 문자는 일반 입력과 같은 순서 보장 큐에서 정확히 한 번 전달한다. 캐럿 좌표가 후보창 위치를 정한다. 지원하지 않는 네이티브 텍스트 값과 입력 실패는 명시적 오류다.

네이티브 입력 어댑터는 Unicode 범위 검사가 아니라 텍스트 입력 클라이언트의 marked-text callback으로 조합과 확정을 구분한다. 유일한 예외는 아래에 적은 macOS 한국어 입력기의 확정 시점이다. 모든 `insert` callback은 바이트 단위로 순서대로 전달하며, 플러그인은 문자 스크립트나 코드 포인트를 근거로 조용히 버리거나 바꾸면 안 된다. 각 플랫폼 어댑터는 OS 텍스트 입력 수명주기를 사용하고 확정 callback을 정확히 한 번 노출해야 한다. 빈 `compose` callback은 조합 중 텍스트를 지우거나 취소하며, 이전 marked 문자열을 확정하지 않는다. PTY 확정 입력은 `insert` callback만 만든다. 플랫폼이 marked text를 입력으로 받아들이면(macOS의 `unmarkText`) 어댑터는 그 문자열을 `insert` 하나로 보고한다.

입력기는 marked text 대신 이전에 넣은 문자열을 고쳐 쓸 수 있다. 예를 들어 macOS 한국어 입력기는 `ㅎ`을 넣은 뒤 교체 범위로 `하`, `한`으로 바꾸며, 조합 중인 음절의 문서 위치를 기억한다. 따라서 선택된 입력 소스가 자판이 아니라 입력기인 동안 플랫폼 어댑터는 입력기가 넣은 문자열을 입력 문서에 두고 교체를 그곳에 적용하며, 입력기가 아직 고칠 수 있는 부분을 조합 문자열로 보고한다. 가장 최근 insert의 시작보다 앞의 문자열은 `insert` 하나로 확정하고, 위치가 바뀌지 않도록 확정한 문자열도 입력 문서에 남긴다. macOS 한국어 입력기는 한글 자모와 음절만 조합하며, 이 교체 방식에서는 조합이 끝났다는 콜백을 보내지 않는다. 음절 뒤의 Space나 숫자는 음절을 자기 자신으로 교체한 뒤 공백이나 숫자를 넣는 순서로 도착하며, 이는 새 음절의 첫 자모와 같은 순서다. 따라서 이 입력기가 선택된 동안 어댑터는 확정 위치 뒤의 문자열에 한글이 없으면 즉시 확정한다. 이 규칙은 확정 시점만 정하며 입력을 버리거나 바꾸지 않는다. 다른 입력기는 일반 규칙을 따른다. 확정되지 않은 입력기 문자열이 있는 동안 Control이나 Option이 없는 특수 키는 먼저 입력기로 가므로, 텍스트 뷰처럼 Backspace가 조합을 편집한다(`한`이 `하`가 됨). 입력기가 키를 처리하지 않으면 AppKit이 클라이언트에 그 키의 명령을 요청하고, 어댑터는 남은 문자열을 확정한 뒤 명령 대신 원래 키를 보고한다. 그 밖의 특수 키, 명령, 포커스 해제, 입력 소스 전환, 영역 닫기 전에는 남은 문자열을 확정하고 입력기의 조합을 끝낸 뒤 문서를 비운다. 자판에서 온 문자열은 즉시 확정한다. 이미 확정한 문자열에 대한 교체는 명시적 오류로 보고한다. 어댑터는 텍스트 저장소를 입력 문서로 쓰는 AppKit 텍스트 뷰다. 터미널이 선언하지 않은 텍스트 편집을 모두 끈다: 자동 치환, 대체, 맞춤법과 문법 검사, 감지, 완성, 텍스트 검사 종류, 실행 취소, 서식 있는 텍스트, 그림, 찾기 막대, 글꼴 패널, 눈금자. 서비스 메뉴는 입력 문서를 읽거나 바꿀 수 없으며, 포인터, 메뉴, 끌기 입력은 이 뷰를 대상으로 하지 않는다. 자기 문서를 가진 일반 뷰도 같은 한국어 결과를 냈지만 입력 클라이언트로 쓰면 영역이 닫힌 뒤 해제된 메모리를 계속 썼으므로(F8-9-1) 텍스트 뷰를 유지한다.

터미널 플러그인은 네이티브 callback과 같은 순서 보장 사이드카 경로로 현재 preedit를 설정하는 `terminal.compose.update` 명령을 `diagnostics.json`([진단 선언](plugins.ko.md#진단-선언))에 선언하므로, 이 명령은 진단 빌드에만 있다. 이 명령은 OS 입력기가 만드는 preedit를 주입한다. 문자열 `text`, 선택적 `selectedRange` 및 `replacementRange`(`null` 또는 음이 아닌 정수 `{location, length}`), 선택적 boolean `attributed`를 받는다. 생략한 범위는 `null`, 생략한 `attributed`는 `false`이며 빈 문자열은 preedit를 지운다. 이 명령은 PTY 바이트를 쓰지 않는다. 기존 `terminal.compose` status가 적용된 preedit를 보고하고, 이전 이미지 전송이 소비된 다음 네이티브 이미지가 각 갱신을 표시한다. 이 명령은 preedit 렌더링과 순서를 검증하며 실제 OS IME 검증을 대체하지 않는다.

터미널 플러그인은 명시적으로 시작하는 제한 크기 IME 진단 trace도 `diagnostics.json`에 선언한 `terminal.ime.trace` 명령과 status로 제공한다. 활성화 중 네이티브 `key`·`compose`·`insert` callback과 각 입력에 대응하는 순서 보장 터미널 입력 작업 및 텍스트를 기록한다. trace 용량에 도달하면 이벤트를 조용히 버리지 않고 trace를 명시적 실패 상태로 만든다. 중지하면 기록과 초과 상태를 반환한다. 기본은 비활성화이며, trace는 진단 증거일 뿐 네이티브 픽셀 조합 검증을 대체하지 않는다.

선택, 클립보드, 붙여넣기, 파일 드롭, 이미지 붙여넣기, 터미널 출력 이미지 표시는 서로 다른 동작이다. 붙여넣은 이미지는 소유 파일로 저장하고 자동 실행 없이 경로를 입력한다. 선언된 `terminal.paste` 명령만 텍스트 붙여넣기 진입점이다. 포커스된 터미널 영역에서 Edit > Paste(Command+V)와 Paste and Match Style은 `paste` 동작을 보고하고, 이 동작은 명령 레지스트리로 `terminal.paste`를 실행한다. Edit > Copy(Command+C)는 `copy` 동작을 보고하고, 이 동작은 `copy` 요청을 보내는 `terminal.copy`를 실행한다. 사이드카는 현재 선택 텍스트를 담은 `copy` 이벤트로 답하고 터미널 모듈은 이를 `userInitiated: true`로 클립보드에 쓴다. 선택이 없으면 `copied: false`로 답하고 클립보드는 바뀌지 않는다. 영역은 페이스트보드 내용을 입력기 문서에 넣지 않으며, 잘라내기, 전체 선택, 삭제는 영역에서 꺼져 있다. 이 명령은 범위가 지정된 클립보드 capability를 `userInitiated: true`로 사용해 텍스트를 읽고, 클립보드가 없거나 텍스트가 아니면 명시적으로 거부하며, 실패를 빈 입력으로 바꾸지 않는다. 사이드카에는 하나의 `paste` 동작만 보내며, bracketed paste 모드에서는 제공된 UTF-8 payload를 바이트 단위로 보존하고 종료 시퀀스가 입력 안에 있으면 삭제하지 않고 거부한다. 전체 payload를 한 번 쓴 뒤에만 응답을 확인한다. 입력을 조용히 정제, 폐기, 재정렬하지 않는다. 터미널 프로토콜 지원은 시퀀스와 참조 판본별로 기록하며 파서가 수락해도 미구현 동작을 지원으로 세지 않는다.

터미널 위의 휠 입력은 스크롤 제스처다. 터미널 페이지는 자기 뷰의 DOM 휠 이동량을 정수 줄로 바꾸며, 픽셀 이동량은 칸 높이로 누적하고, `{operation: "scroll", lines, col, row}`를 보낸다. 양수 `lines`는 오래된 출력 쪽으로 움직이고, `col`과 `row`는 포인터가 있는 칸이다. 사이드카는 터미널 모드에 맞는 첫 규칙을 적용한다. 마우스 보고(모드 1000, 1002, 1003)가 켜져 있으면 포인터 칸에서 줄마다 휠 버튼 이벤트 하나(오래된 출력 쪽 버튼 64, 새 출력 쪽 65)를 현재 마우스 인코딩(SGR 1006, UTF-8 1005, 기본)으로 쓴다. 그렇지 않고 대체 화면에서 대체 스크롤(모드 1007)이 켜져 있으면 현재 커서 키 모드로 줄마다 위쪽 또는 아래쪽 커서 키 하나를 쓴다. 그 밖에는 기본 화면의 뷰포트를 보관된 기록 범위 안에서 `lines`만큼 스크롤백으로 움직인다. screen 이벤트는 뷰포트를 보이고, 커서 행이 뷰포트 밖이면 커서를 숨긴 것으로 보고한다. 키 입력, 텍스트 입력, 붙여넣기는 바이트를 쓰기 전에 뷰포트를 가장 새 출력으로 되돌린다. `terminal.session`은 `scrollback: {offset, history}`로 뷰포트가 가장 새 출력보다 위에 있는 줄 수와 보관된 기록 줄 수를 보고한다. 선택 좌표는 제스처가 일어날 때의 뷰포트 좌표다.

터미널이 기록을 보관하는 동안(`scrollback.history`가 0보다 큼) 터미널 페이지는 뷰 오른쪽 가장자리의 선언된 DOM overlay `scrollbar`에 네이티브 이미지 위로 스크롤바를 보이며, 가장 새 출력에서는 손잡이가 트랙 맨 아래에 있다. 호스트가 overlay 아래의 네이티브 그림을 잘라내므로 트랙은 screen 이벤트가 `background`로 보고하는 터미널의 현재 기본 배경색(OSC 11로 바뀐 값 포함)으로 칠한다. 손잡이 높이는 트랙 높이에 `rows / (rows + history)`를 곱한 값이며 최소 16포인트이고, 손잡이 위쪽은 트랙의 `(history - offset) / (rows + history)` 위치다. 손잡이 위의 포인터는 펼친 손이고, 손잡이를 끄는 동안은 쥔 손이다. 손잡이를 끌면 포인터 아래의 오프셋으로 선언된 명령 `terminal.scrollback.set`이 실행되고, 이 명령은 `{operation: "viewport", offset}`을 보낸다. 사이드카는 기본 뷰포트를 보관된 기록 범위 안에서 그 오프셋으로 옮기고, 프로그램에는 아무것도 쓰지 않으며, screen 이벤트로 답한다. 기록이 없으면 스크롤바를 숨긴다. 네 플러그인 설정이 스크롤바를 정한다. `terminal.scrollbar.track`은 `terminal`(터미널의 현재 기본 배경색, 기본값) 또는 색이고, `terminal.scrollbar.thumb`은 손잡이 색(기본 `#8f98a080`)이며, `terminal.scrollbar.width`는 4에서 24 사이의 트랙 폭(포인트, 기본 10)이고, `terminal.scrollbar.shape`는 `rounded`(기본) 또는 `square`다. 색은 `#rrggbb` 또는 `#rrggbbaa`이며, 그 밖의 값은 입력 오류로 보고하고 적용하지 않는다. 설정을 바꾸면 보이는 스크롤바에 바로 적용한다.

터미널 선택은 DOM 텍스트 선택이 아니라 네이티브 영역의 제스처다. 네이티브 영역은 CSS 로컬 좌표와 modifier 상태를 포함한 왼쪽 버튼 누름·이동·해제를 보고하고, 사이드카가 이 좌표를 적용된 셀 그리드로 변환해 선택 상태를 소유한다. 이동은 왼쪽 버튼을 누른 채 움직인 포인터다. 창이 키 창이 될 때 WebKit이 보고하는 포인터 위치처럼 버튼 없는 이동은 선택을 시작하거나 바꾸지 않는다. 영역은 마지막 완전한 열과 행 뒤로 한 칸보다 작게 더 뻗는다. 뷰 안에서 누른 뒤에는 페이지가 뷰 밖의 끌기 점을 뷰 안의 가장 가까운 점으로 옮긴다. 줄의 처음이나 끝으로 끄는 동작은 뷰 가장자리를 지나기 때문이다. 뷰 밖의 누름은 선택을 시작하지 않는다. 어느 방향의 끌기든 선택은 누른 칸과 포인터 아래 칸을 포함하며, 그려진 선택은 텍스트가 복사되는 칸과 정확히 같다. 그 여백의 점은 가장 가까운 칸에 대응하고, 영역 밖의 점은 잘못된 좌표다. 일반 드래그는 simple 선택을 만들고 렌더링 선택 픽셀을 갱신하며, 해제 시 선택 텍스트를 담은 명시적 사용자 선택 복사 event를 한 번 낸다. 터미널 모듈은 `clipboard.program` 정책과 무관하게 범위가 지정된 클립보드 capability에 `userInitiated: true`로 기록한다. 빈 칸 위를 끈 경우처럼 글자를 담지 않은 선택의 해제는 선택을 지우고 클립보드를 바꾸지 않으며 `copied: false`인 `selection.end`를 낸다. 이는 정상 제스처이며 오류가 아니다. 클릭처럼 움직이지 않은 누름과 뗌은 누른 칸에서 빈 선택을 시작하고 끝내므로, 클릭은 이전 선택을 지운다. `terminal.session`은 왼쪽 버튼 제스처가 진행 중이면 `selecting`을 보고하고, 사이드카가 복사나 `selection.end`로 답한 해제의 수를 `selectionReleases`로 센다. 클립보드 capability 부재, 잘못된 좌표, 텍스트 없는 복사 event, 기록 실패는 명시적 오류다. 선택 입력을 PTY로 보내지 않으며 DOM fallback도 사용하지 않는다.

페이지는 왼쪽 버튼의 모든 누름, 누른 채 움직임, 뗌과, 다른 칸으로 들어가는 버튼 없는 움직임도 `mouse` 연산 `{phase, x, y, pressed, shift, alt, ctrl}`로 보낸다. 프로그램이 마우스 보고를 켰으면 Shift 없는 누름은 보고 제스처를 시작한다. 사이드카는 누름과 뗌, 그리고 ?1002나 ?1003이면 누른 채 다른 칸으로 들어가는 움직임을 쓰며, 그 제스처의 선택 연산은 아무것도 선택하지 않고 평소처럼 답한다. ?1003이면 다른 칸으로 들어가는 버튼 없는 움직임도 알린다. 보고는 기본 인코딩, ?1005면 UTF-8 좌표, ?1006이면 SGR을 쓰고 Alt(8)와 Control(16) 비트를 싣는다. 기본 인코딩이 나타낼 수 없는 좌표는 명시적 오류다. 마우스 보고가 켜져 있어도 Shift를 누른 누름은 글자를 선택한다. 영역은 왼쪽 버튼만 알린다. 프로그램이 초점 보고(?1004)를 켰으면, 사이드카는 영역이 네이티브 초점을 얻을 때 `ESC[I`를, 잃을 때 `ESC[O`를 변경마다 한 번 쓴다.

## 세션 오류

`terminal.session.error`는 표면에서 가장 최근에 해소되지 않은 오류다. 플러그인은 출처마다 마지막 오류를 두며, 한 출처의 이벤트는 다른 출처의 오류를 지우지 않는다. 스냅샷 출처의 오류는 같은 종류의 다음 유효한 이벤트가 해소한다. 다른 출처의 오류는 이후 어떤 이벤트도 실패한 연산의 성공을 보이지 않으므로 표면이 닫힐 때까지 남는다.

| 출처 | 오류 | 해소하는 이벤트 |
| --- | --- | --- |
| `state` | 잘못된 `state` 이벤트 | 다음 유효한 `state` 이벤트 |
| `session` | 잘못된 영속 `session` 이벤트 | 다음 유효한 `session` 이벤트 |
| `theme` | 잘못된 테마 확인 | 다음 유효한 `theme` 이벤트 |
| `screen` | `screen` 이벤트의 잘못된 커서 | 유효한 커서를 가진 다음 `screen` 이벤트 |
| `trace` | IME trace 용량 초과(진단 빌드) | 새 trace 시작 |
| `sidecar` | 사이드카 `error` 이벤트 또는 오류 응답. 응답은 거부한 연산을 적지 않는다 | 해소되지 않음 |
| `native image` | 네이티브 이미지 영역의 `error` 이벤트 | 해소되지 않음 |
| `input` | 실패한 입력, 붙여넣기, 클립보드, 선택 연산과 잘못된 일회성 사이드카 이벤트 | 해소되지 않음 |
| `key` | 수정자가 불린이 아닌 네이티브 키 이벤트 | 해소되지 않음 |
| `cursor` | 사이드카의 잘못된 커서 위치 | 해소되지 않음 |

`sidecar`와 `native image` 출처는 카드가 표시하는 표면 오류도 보고한다. 둘 다 해소되지 않으므로 카드 표시기와 `terminal.session.error`는 표면이 닫힐 때까지 그 오류를 표시한다.

## 검증

- 각 수정 전에 실패 기준선을 기록하고 수정 후 같은 단언을 실행한다.
- 생성, 정상 종료, 충돌, 재연결에서 서비스 프로세스, 셸 식별자, PTY 디스크립터, 연결, 출력 시퀀스를 측정한다.
- 양쪽 네이티브 호스트에서 터미널 3개 이상을 사용한다. 빠른 디바이더 제스처 전체, 글리프 메트릭 유지, 네이티브 클리핑, 영역 채움, 복원된 영역을 캡처한다.
- 확정 문자열 주입뿐 아니라 실제 네이티브 키보드와 IME 입력을 관측한다. 의미 상태와 표시 픽셀은 독립 검증한다.
- loading, ready, error를 구분한다. Ready는 세션 생성뿐 아니라 실제 최초 네이티브 표시를 포함한다.
