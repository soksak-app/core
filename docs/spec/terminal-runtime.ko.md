# 터미널 런타임

[English](terminal-runtime.md)

이 계약은 승인된 터미널 런타임을 정의한다. 구현과 검증은 [기능 상태](../features.ko.md)에서 추적하며, 계약 승인이 구현 완료를 뜻하지 않는다.

## 소유권과 프로세스 수

앱 설정 디렉터리마다 영속 터미널 서비스 하나가 PTY, VT 상태, 스크롤백, 렌더링을 소유한다. PTY 관리, 에뮬레이션, 렌더링, 클라이언트 전송은 같은 프로세스의 별도 모듈이며 별도 실행 파일이 아니다. 독립 세션은 각각 PTY 장치와 셸 프로세스를 소유한다. PTY 장치는 프로세스가 아니다. 독립 터미널 3개는 앱 호스트 외에 서비스 하나와 셸 3개를 요구한다. WebKit 프로세스와 셸이 실행한 프로그램은 별도로 센다.

표면 연결은 세션이 아니다. 표면 키에 대한 첫 열기는 레지스트리 actor 하나를 생성하고 셸 시작 전에 안정적인 세션 식별자를 배정하며, 같은 생성 식별자의 반복 요청은 같은 결과를 반환한다. 대체 표면 연결은 PTY를 생성하지 않는다. 활성 연결이 입력과 크기 변경 권한을 소유하고 오래된 연결에는 명시적 오류를 반환한다. 연결된 표면이 없으면 세션의 터미널 크기를 유지한다.

서비스 엔드포인트는 설정 디렉터리로 범위를 제한하고 인증, 버전, 단일 인스턴스 잠금을 갖춘다. 테스트 설정은 다른 설정의 서비스를 탐색하지 않는다. 세션 상태와 입력 큐는 격리한다. 바쁜 세션이 읽기, 쓰기, 해석, 렌더링 중 전역 잠금을 점유해서는 안 된다.

## 종료와 복구

### 서비스 전송

사이드카 선언은 `transport: "persistent"`를 선택한다. 이 필드가 없는 사이드카는 해당 도메인의 stdio 전송을 사용한다. 호스트는 선언한 실행 파일을 `--service-dir <config-dir>/services/<executable-name>`으로 시작한다. 서비스는 해당 디렉터리의 독점 잠금을 얻은 뒤 리스너를 생성한다. Unix 소켓 경로 제한을 지키도록 접근 제한된 짧은 임시 디렉터리에 소켓을 만들고 `{protocol: 1, pid, socket, token}`의 `endpoint.json`을 원자적으로 게시한다. 디렉터리 권한은 0700, 토큰을 담은 파일은 0600이다. stdout 준비 줄은 리스너가 준비된 뒤에만 해당 엔드포인트를 담는다.

첫 줄 단위 JSON 메시지는 `{operation: "hello", protocol: 1, token, client}`다. 서비스는 `{operation: "hello", protocol: 1, ok: true}` 또는 `{operation: "hello", ok: false, error}`로 답한다. 인증 후 표면 메시지는 선언된 사이드카 봉투를 유지한다. `{operation: "close-owner", request}`는 인증한 클라이언트의 세션을 종료하고 정리 뒤 `{operation: "closed-owner", request, ok: true}` 또는 `ok: false`와 `error`로 답한다. `{operation: "shutdown", request}`는 소유자 닫기 이후에만 수락하고 `{operation: "shutdown", request, ok: true}`로 답하며, 클라이언트 연결이 모두 종료된 뒤 서비스를 종료하도록 허용한다. 소켓 EOF는 세션을 보존한다. 엔드포인트 파일만으로 해당 PID를 종료하지 않으며 프로토콜·인증 실패 시 경쟁 서비스를 시작하지 않는다.

표면 숨김, 라이브러리 이동, 앱 연결 단절은 세션을 보존한다. 터미널의 명시적 닫기는 해당 세션을 종료한다. 정상 창 닫기는 그 창 소유 세션을, 정상 앱 종료는 모든 소유 세션을 종료한다. 관리 대상 작업 종료, 자식 회수, PTY 핸들 해제, 출력 완료 또는 실패 보고, 연결 작업 제거 후에만 종료 완료다. 종료 오류를 성공으로 바꾸지 않는다.

앱 충돌과 명시적 업데이트 재시작은 서비스를 유지한다. 재연결은 같은 세션, 셸 프로세스, VT 상태, 스크롤백을 복원하며 새 앱 프로세스의 네이티브 이미지는 새로 만들고 프로세스 사이에서 재사용하지 않는다. 서비스는 연결이 없어도 출력을 읽고 해석한다. EOF는 연결 단절이며 세션 종료 명령이 아니다. 종료 의도를 응답 전에 기록하여 중단된 닫기가 의도적으로 종료한 세션을 복원하지 않게 한다.

명시적 shutdown 요청이 있고 클라이언트가 모두 없어야 서비스를 종료한다. 복구 가능한 세션은 조회하고 명시적으로 종료할 수 있다. 서비스 장애와 OS 재시작은 실행 프로세스 복구 범위 밖이며 새 셸 생성은 복구 증거가 아니다. 공유 서비스는 하나의 프로세스 장애 범위다. 세션 격리가 프로세스 수준 충돌 격리를 의미하지 않는다.

앱 업데이트는 프로토콜 버전이 일치할 때만 실행 중 서비스에 재연결한다. 불일치는 명시적 실패이며 두 번째 서비스 시작, 기존 작업 종료, 호환 경로 사용으로 처리하지 않는다. 서비스 자체 교체는 세션 종료까지 기다린다.

## 터미널 입력과 표시

터미널을 한 번 클릭하면 선언된 `terminal.focus` 명령을 통해 네이티브 그림 영역으로 키보드 소유권을 옮긴다. 네이티브 터미널 입력 뒤 다음 합성 포인터를 전달하기 전에 host가 대상 문서 웹뷰를 응답자로 복원하므로 네이티브 그림 응답자가 다음 클릭을 가로막지 않는다. DOM 앵커는 포인터의 기본 DOM 포커스 동작을 막아 같은 클릭 중 WebKit이 소유권을 되찾지 않게 한다. 카드 선택은 여전히 이벤트를 받는다. 두 번째 클릭, 지연 재포커스, 테스트 전용 포커스 명령은 필요하지 않다. 포커스 요청 오류는 관측 가능해야 한다. 모달 포커스 복원과 그림 포커스 통지는 현재 AppKit/Tauri 콜백이 끝난 뒤로 미뤄야 하며 WebView 이벤트 경로에 동기 재진입해서는 안 된다.

엔진, PTY, 표시 래스터는 적용된 크기가 같아야 한다. 폭을 좁히면 기본 화면의 자동 줄바꿈 행을 재배치하고, 넓히면 같은 논리적 행을 합친다. 명시적 개행은 유지한다. 대체 화면 앱은 터미널 제어 배치 의미를 유지한다. 디바이더 이동은 글꼴 메트릭을 바꾸거나 래스터 기하를 애니메이션하지 않는다.

터미널 래스터는 유효한 애플리케이션 외관을 따른다. 표면 페이지는 애플리케이션 외관이 바뀔 때 `{ "mode": "dark" }` 또는 `{ "mode": "light" }`를 담은 `theme`를 터미널 사이드카에 보낸다. 사이드카는 다른 모드를 명시적으로 거부한다. 선택한 모드는 기본 전경·배경·커서와 인덱스 ANSI 색상을 이후 및 기존 화면 셀에 적용하며 PTY, 세션, 텍스트, 커서 위치, 셀 메트릭을 다시 만들지 않는다. 모드는 이미지 표면 속성이며 다음 완전한 프레임에 적용된다. 전송 중인 래스터는 변경하지 않는다.

커서 상태는 위치·표시 여부·모양·깜빡임 정책·색상을 포함한다. 커서 정책은 명시적으로 관리한다. 모양은 `block`·`underline`·`beam`, 깜빡임은 `Never`·`Off`·`On`·`Always`, 간격은 양의 밀리초(기본 750), 유휴 제한 시간은 0 이상 밀리초(기본 5000, 0은 제한 없음), 비포커스 모양은 `hollow`·`solid`·`underline`·`beam`·`unchanged`다. 기본은 포커스 시 채워진 block과 `Off`, 비포커스 시 steady hollow block이다. `Never`와 `Always`는 프로그램 깜빡임 요청보다 우선하고 `Off`와 `On`은 프로그램 요청을 허용한다. 프로그램 커서 모양은 설정 기본값보다 우선한다. 프로그램 가시성은 권위 값이다. 렌더링은 커서 픽셀만 바꾸며 페이드·크기 애니메이션을 사용하지 않고 PTY나 셀 메트릭을 재생성하지 않는다.

정책은 터미널 플러그인의 `plugin.json`에 선언하고, 애플리케이션의 초기값은 `environment.json`에서 받으며, 이후 유효한 공통/프로젝트 설정을 따른다. 워크벤치는 저장 전에 선언 규칙으로 각 값을 검증하고 잘못된 값이면 부분 patch를 적용하지 않고 명시적인 오류를 보고한다. 마운트된 터미널 표면에는 유효한 플러그인 내부 설정을 전달하며, 터미널 표면은 시작 시와 유효 설정이 바뀔 때마다 완전한 정책을 사이드카로 보낸다.

터미널 프로그램의 클립보드 접근은 사용자가 명시적으로 붙여넣는 동작과 별개다. 선언된 `clipboard.program` 설정은 `deny` 또는 `allow`이며 기본값은 `deny`다. 거부 시 OSC 클립보드 저장/조회 요청은 관측 가능한 정책 오류를 내고 호스트 클립보드에 쓰지 않으며 대기 중인 조회 callback도 남기지 않는다. 허용 시에도 선언된 텍스트 클립보드 대상만 처리하고, 지원하지 않는 selection 대상과 부재/비텍스트 값은 명시적 오류로 남긴다. 사용자 `terminal.paste` 명령에는 이 프로그램 권한을 적용하지 않는다.

네이티브 IME가 조합 문자를 소유한다. 조합 중에는 preedit를 표시하고 미완성 음절을 PTY에 쓰지 않는다. 확정 문자는 일반 입력과 같은 순서 보장 큐에서 정확히 한 번 전달한다. 캐럿 좌표가 후보창 위치를 정한다. 지원하지 않는 네이티브 텍스트 값과 입력 실패는 명시적 오류다.

선택, 클립보드, 붙여넣기, 파일 드롭, 이미지 붙여넣기, 터미널 출력 이미지 표시는 서로 다른 동작이다. 붙여넣은 이미지는 소유 파일로 저장하고 자동 실행 없이 경로를 입력한다. 선언된 `terminal.paste` 명령만 텍스트 붙여넣기 진입점이다. 이 명령은 범위가 지정된 클립보드 capability를 `userInitiated: true`로 사용해 텍스트를 읽고, 클립보드가 없거나 텍스트가 아니면 명시적으로 거부하며, 실패를 빈 입력으로 바꾸지 않는다. 사이드카에는 하나의 `paste` 동작만 보내며, bracketed paste 모드에서는 제공된 UTF-8 payload를 바이트 단위로 보존하고 종료 시퀀스가 입력 안에 있으면 삭제하지 않고 거부한다. 전체 payload를 한 번 쓴 뒤에만 응답을 확인한다. 입력을 조용히 정제, 폐기, 재정렬하지 않는다. 터미널 프로토콜 지원은 시퀀스와 참조 판본별로 기록하며 파서가 수락해도 미구현 동작을 지원으로 세지 않는다.

터미널 선택은 DOM 텍스트 선택이 아니라 네이티브 영역의 제스처다. 네이티브 영역은 CSS 로컬 좌표와 modifier 상태를 포함한 왼쪽 버튼 누름·이동·해제를 보고하고, 사이드카가 이 좌표를 적용된 셀 그리드로 변환해 선택 상태를 소유한다. 일반 드래그는 simple 선택을 만들고 렌더링 선택 픽셀을 갱신하며, 해제 시 선택 텍스트를 담은 명시적 사용자 선택 복사 event를 한 번 낸다. 터미널 모듈은 `clipboard.program` 정책과 무관하게 범위가 지정된 클립보드 capability에 `userInitiated: true`로 기록한다. 클립보드 capability 부재, 잘못된 좌표, 빈 선택, 기록 실패는 명시적 오류다. 선택 입력을 PTY로 보내지 않으며 DOM fallback도 사용하지 않는다.

## 검증

- 각 수정 전에 실패 기준선을 기록하고 수정 후 같은 단언을 실행한다.
- 생성, 정상 종료, 충돌, 재연결에서 서비스 프로세스, 셸 식별자, PTY 디스크립터, 연결, 출력 시퀀스를 측정한다.
- 양쪽 네이티브 호스트에서 터미널 3개 이상을 사용한다. 빠른 디바이더 제스처 전체, 글리프 메트릭 유지, 네이티브 클리핑, 영역 채움, 복원된 영역을 캡처한다.
- 확정 문자열 주입뿐 아니라 실제 네이티브 키보드와 IME 입력을 관측한다. 의미 상태와 표시 픽셀은 독립 검증한다.
- loading, ready, error를 구분한다. Ready는 세션 생성뿐 아니라 실제 최초 네이티브 표시를 포함한다.
