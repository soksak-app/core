# 예제 모델

[English](example-model.md)

예제 애플리케이션은 프로젝트, 스페이스, 탭을 관리한다. 배치 라이브러리는 카드 좌표를 관리한다.

| 객체 | 내용 |
| --- | --- |
| 프로젝트 | 루트 경로, 이름, 색상, 스페이스 |
| 스페이스 | 카드 배치, 포커스 카드, 레일 너비, 탭 |
| 카드 | 배치 슬롯, 선택적 픽셀 크기, 탭 |
| 탭 | 플러그인, 제목 |

[프로젝트 계약](projects.ko.md)에 디렉터리 식별, 영구 저장, 설정 상속, 시작 프로젝트, 프로젝트 창을 정의한다. 스페이스 전환 시 현재 애플리케이션 상태를 기록하고 `Soksak.replace()`로 선택한 스페이스를 복원한다.

추가·분할 버튼은 새 탭의 플러그인을 선택한다. 카드 중앙에 탭을 드롭하면 해당 카드에 추가하고, 카드 변에 드롭하면 인접 공간을 생성한다. 카드의 유일한 탭을 이동하면 카드를 이동한다.

플러그인은 표면을 플러그인 패키지 안의 문서인 `{page}`로 선언하고 사이드바 섹션을 선언한다. 페이지는 문서 영역에 웹 문서를 표시한다. 선언 파일은 [플러그인 명세](plugins.ko.md)에 정의한다. 설정은 섹션 세트와 왼쪽 사이드바·플러그인 카드 왼쪽 사이드바·오른쪽 사이드바의 세트 할당을 저장한다.

설정 `cardSidebar`("카드 사이드바 위치")은 플러그인 사이드바의 위치를 정한다. 기본값은 `inset`이고, 컨트롤은 카드 안(`inset`), 포커스 카드 옆(`flow`), 고정(`pin`), 없음(`off`)을 이 순서로 보여 준다. `flow`는 그 플러그인의 포커스된 카드 옆에 고정 열로 끼워 넣고(스페이스에서 폭을 바꾸기 전까지 `sidebarWidth` 폭) 포커스를 따라 옮기며, `pin`은 열을 서 있던 자리에 두고, `off`는 숨긴다. `inset`에서는 활성 탭의 플러그인에 연결된 세트가 있는 모든 카드 안에서 사이드바가 표면 왼쪽에 서므로, 어느 카드의 크기도 바뀌지 않고 열도 끼워 넣지 않는다. 카드의 내용 행은 틈 없이 사이드바와 표면 자리로 나뉘고, 6포인트 경계선이 사이드바의 오른쪽 테두리 위에 놓여 두 동작을 받는다. 3포인트보다 많이 끌면(`core.card.sidebar.size {card, width}`, `sidebarMinWidth`–`sidebarMaxWidth`) 사이드바 폭이 바뀌고 누름이 되지 않는다. 누르면 곧바로 `core.card.sidebar.toggle {card}`를 실행한다. 두 번 누름 동작은 없고, 펼친 사이드바는 저장된 폭을 유지한다. 접힌 사이드바는 내용을 숨기고 경계선만 남기며, 경계선은 2포인트 `--muted` 선으로 그리고 누르면 펴진다. 모두 카드 크기를 유지하며 표면은 자기 자리를 따른다. 저장된 폭이 없는 카드는 사이드바를 `sidebarWidth`로 연다. [설정 창](settings.ko.md#배치-값)이 이 값을 정의한다(기본값 120, 480, 190포인트). 폭과 접힘 상태는 스페이스에 카드마다 저장되고, `core.grid`는 카드마다 `sidebar: {width, collapsed}` 또는 `null`로 알린다.

카드는 사방에 지정된 패널도 가진다(V5-115): 각 변 최대 하나(`top`, `bottom`, `left`, `right` — 총 넷). 패널은 지정이지 파생이 아니다: `core.card.panel.set {card, side, set}` 이 그 카드의 그 변에 세트를 지정하고 `off` 로 해지하며, 카드의 활성 탭이 다른 플러그인으로 바뀌어도 지정은 유지된다 — 활성 탭을 따르는 inset 사이드바와의 차이는 그것이 전부다. 나머지는 같은 취급이다: 공유 세트·섹션 체계가 지정된 세트를 그리고, `core.card.panel.toggle {card, side}` 로 접고 `core.card.panel.size {card, side, size}` 로 크기를 정한다(좌우는 폭, 상하는 높이, 같은 120–480 상한과 190 기본), 3포인트 넘는 끌기는 크기이고 누름은 접기다. 상하 패널은 카드 전체 폭을 가지고, 좌우 패널은 inset 사이드바와 표면 자리를 담은 중앙 칸의 양옆에 서며 그 칸 안의 inset 사이드바는 자기 동작을 유지한다. 패널이 어떻게 바뀌어도 카드의 크기는 그대로이고 표면은 줄어든 자리를 따른다. 해석되지 않는 세트 id 는 패널만 숨기고 지정은 남긴다 — 아무 것도 조용히 지워지지 않는다. 크기와 접힘은 지정 옆에 저장되고 `core.grid` 가 지정된 변을 `panels: {변: {set, size, collapsed}}` 로 보고한다.

브라우저 애플리케이션은 네이티브 표면을 모사한다. 브라우저 검사는 네이티브 합성을 검증하지 않는다. 네이티브 인수에는 [검증 절차](../operations/examples.ko.md)의 호스트 검사가 필요하다.

`plane.js`는 카드·탭 동작, `compositor.js`는 표면 사각형 측정·예측, `host.js`는 네이티브 요청, 각 애플리케이션의 `runtime/index.js`는 해당 런타임의 전송, `environment.js`는 애플리케이션의 플러그인과 기본값 로드를 담당한다. `settings-ui.js`는 설정 DOM을 관리하고 `card.js`는 `overlay.html`과 공통으로 사용하는 입력을 처리한다.
