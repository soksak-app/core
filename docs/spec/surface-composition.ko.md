# 표면 합성

[English](surface-composition.md)

이 명세는 표면 페이지와 네이티브 콘텐츠 사이의 소유 경계를 정의한다. DOM 전용 표면과 혼합 표면의 기준 명세다. 바깥 표면의 배치는 [네이티브 표면 배치](native-surfaces.ko.md)가 정의한다.

## 모델

창마다 앱 DOM 웹뷰 하나를 둔다. 표면마다 논리적 `SurfaceHost` 하나가 네이티브 콘텐츠를 클리핑하고 이동하고 숨기고 어둡게 하고 닫는다. 플러그인 DOM은 해당 창의 DOM 평면 안에 마운트한다. 단일 DOM 구현은 진행 중이며 [기능 상태](../features.ko.md)가 검증을 별도로 기록한다.

```text
창 합성기
├─ NativePlane
│  └─ 논리 표면별 SurfaceHost
│     ├─ 문서 영역
│     ├─ 그림 영역
│     └─ 그 밖의 선언된 네이티브 영역 종류
└─ DOMPlane: 투명한 앱 웹뷰 하나
   ├─ 워크벤치와 마운트한 플러그인 DOM
   ├─ 위치만 제공하고 그리지 않는 네이티브 앵커
   └─ 선언된 DOM 오버레이, 메뉴, 대화 상자
```

DOM 전용 표면은 공유 DOM 평면에 콘텐츠를 그리고 네이티브 영역이 없다. 혼합 표면은 네이티브 앵커를 투명하게 둔다. 페이지 컨트롤러는 각 네이티브 앵커의 투명도를 0으로 강제해 그 자손과 가상 요소까지 투명하게 만들고, 마운트한 표면 루트부터 그 앵커까지 모든 조상에서 배경 그림·배경색·박스 그림자를 제거한다. 루트 밖의 투명도는 워크벤치가 소유한다. 네이티브 앵커와 선언한 오버레이의 포인터 적중 검사를 강제하고, 오버레이 페인트를 선언한 오버레이 요소의 박스 안으로 제한하며, 플러그인 코드가 이 속성을 바꾸면 계속 원래 규칙으로 복구한다. 앵커는 배치와 DOM 적중 검사에는 참여하지만 위치만 제공한다. 선언한 플러그인 오버레이와 워크벤치 메뉴·대화 상자는 네이티브 문서 영역 위에서 입력을 소유한다. 오버레이와 네이티브 앵커는 서로를 포함할 수 없다.

`SurfaceHost`만 합성을 소유한다. 어떤 페이지, 플러그인, 사이드카, 호스트 중계기, 플랫폼 어댑터도 그 호스트가 소유한 완전한 선언 합성을 통하지 않고 네이티브 영역을 배치하거나 크기를 정하거나 순서를 바꾸거나 표시·숨김하거나 입력을 분배하거나 표시하면 안 된다.

위에서 설명한 DOM/네이티브 순서는 논리적 소유권과 클리핑의 순서이며, AppKit의 하위 뷰 순서를 무조건 뜻하지 않는다. macOS에서는 투명한 `WKWebView` backing도 네이티브 평면이 아래에 있을 때 네이티브 형제 뷰의 픽셀을 가릴 수 있다. 따라서 Darwin 호스트는 플랫폼 합성기에서 클리핑된 네이티브 평면을 투명한 앱 DOM backing보다 위에 둔다. DOM 오버레이와 입력 분배는 아래의 논리적 순서를 그대로 따르며, 네이티브 콘텐츠는 `SurfaceHost` 밖으로 나가거나 오버레이 영역을 소유할 수 없으므로, Darwin 호스트는 보이는 모든 선언 오버레이 아래에서 네이티브 평면을 잘라내고 그 자리에 오버레이의 DOM 픽셀이 보인다. 플랫폼 어댑터는 CSS 투명도가 네이티브 형제 뷰의 순서를 바꾼다고 가정하지 말고, 같은 합성 규칙을 구현하고 강제해야 한다.

## 선언

모든 `plugin.json` 표면은 합성 하나를 선언한다.

```json
{
  "surface": {
    "page": "ui/shell.html",
    "composition": { "kind": "dom" }
  }
}
```

혼합 합성은 페이지를 불러오기 전에 모든 네이티브 영역과 DOM 오버레이를 선언한다.

```json
{
  "surface": {
    "page": "ui/terminal.html",
    "composition": {
      "kind": "hybrid",
      "regions": [
        {
          "name": "view",
          "kind": "image",
          "sidecar": "@soksak/sidecar-vt-alacritty",
          "input": "dom"
        }
      ],
      "overlays": []
    }
  }
}
```

영역 이름은 중복되지 않고 `^[a-z0-9][a-z0-9-]{0,63}$`와 일치한다. 영역 배열은 뒤에서 앞으로의 순서다. 문서 영역은 `kind: "document"`, `input: "native"`를 쓴다. 그림 영역은 `kind: "image"`이며 플러그인이 이미 나열한 사이드카 하나를 지정하고 `input: "dom"`을 쓴다. `overlays`는 같은 이름 문법을 쓰는 중복 없는 이름 배열이다. 알 수 없는 종류·필드·입력 소유자, 선언하지 않은 사이드카, 중복 이름, 영역 이름과 겹치는 오버레이는 오류다. DOM 합성은 영역이나 오버레이를 선언할 수 없다.

워크벤치는 검증한 선언을 모든 바깥 표면 동기화에 포함한다. 호스트는 페이지 요청을 받기 전에 그 선언을 `SurfaceHost`에 저장한다. 호출자, 이름, 종류, 공급자, 세대 또는 연산이 선언과 다르면 호스트가 요청을 거절한다. 하위 브리지를 직접 호출해도 이 검사를 우회할 수 없다.

## 페이지 API

페이지는 합성을 한 번 만든다.

```js
const composition = await createSurfaceComposition({
  regions: { view: document.querySelector("[data-region=view]") },
  overlays: {},
});
const view = composition.region("view");
```

키는 manifest 선언과 정확히 같아야 하고 모든 값은 호출 문서의 요소여야 한다. 생성은 모든 영역을 붙이고 완전한 배치 스냅샷 하나를 보낸다. 선언이나 요소가 빠지거나 더 있으면 아무것도 붙이지 않고 실패한다.

`composition.update(change)`는 코드가 주도하는 DOM 변경을 적용하고, 선언한 모든 앵커와 오버레이를 측정한 다음 완전한 스냅샷 하나를 보낸다. 컨트롤러는 모든 앵커·오버레이·조상의 크기 변경, 뷰포트 크기 변경, 스크롤, DOM 변경을 관찰한다. 감지한 모든 변경은 같은 완전한 스냅샷을 보낸다. 어떤 관찰자나 호출자도 영역 하나만 따로 보낼 수 없다. 개별 공개 `attach`, `place`, 원시 영역 포트는 존재하지 않는다.

뷰포트나 관찰 중인 요소의 크기가 바뀌면 측정된 인셋이 그대로여도 항상 합성 스냅샷을 보낸다. 따라서 표면 전체를 차지하는 그림 영역도 표면 크기가 바뀔 때 새 래스터 설정을 받는다. 표시 중인 혼합 표면에는 선언된 표시 네이티브 영역마다 붙은 네이티브 영역이 정확히 하나 있어야 한다. 고아 영역이나 선언된 영역이 없는 표시 표면은 오류다.

인셋은 현재 마운트된 뷰포트와 요소의 CSS 사각형으로 계산한다. 네이티브 표면·영역 프레임은 AppKit point를 사용하고 backing 배율은 래스터 크기에만 적용한다. WebKit은 소수점 AppKit 프레임을 whole CSS pixel로 노출할 수 있다(예: `2x`에서 `200.5pt`가 `200` CSS px로 보고될 수 있다). 이 플랫폼 양자화는 검사로 명시하며 네이티브 프레임이나 마지막 backing pixel을 바꾸면 안 된다. 정수 `innerWidth`·`innerHeight`는 네이티브 래스터 기하를 정의하지 않는다.

반환한 영역 손잡이는 선언한 종류의 연산만 가진다. 문서 손잡이는 불러오기와 탐색을 수행한다. 그림 손잡이는 초점, 캐럿, 접근성 텍스트를 제어하고 공급자 이벤트를 받는다. 개별 영역 분리는 허용하지 않는다. 표면을 닫거나 탐색하면 완전한 합성을 제거한다.

표면을 닫을 때는 영역을 분리하거나 native 합성 선언을 제거하기 전에 마지막으로 진행 중인 완전한 합성 배치가 끝날 때까지 기다린다. 닫기는 이후 배치를 취소할 수 있지만 선언이나 native 영역을 제거한 뒤 배치가 경합하게 해서는 안 된다.

## 리비전과 원자성

합성과 래스터 진행은 분리한다.

- **합성 리비전**은 모든 영역과 오버레이의 사각형, 표시 상태, 순서, 입력 소유권을 담은 완전한 스냅샷 하나다. 호스트는 전체 스냅샷을 검증한 뒤 원자적으로 적용한다. 부분 또는 오래된 리비전은 거절한다. 바깥 표면 이동은 저장된 합성을 같은 네이티브 트랜잭션에서 동기적으로 적용하며 JavaScript나 사이드카를 기다리지 않는다.
- **래스터 리비전**은 그림 영역의 네이티브 픽셀 너비, 네이티브 픽셀 높이 또는 backing 배율이 바뀔 때만 변한다. 위치만 바뀌거나 같은 크기에서 숨김·표시하면 유지한다. 호스트가 적용한 네이티브 사각형으로 예상 래스터 위치를 계산한다. 플러그인은 `clientWidth * devicePixelRatio`로 계산하면 안 된다.

표면을 붙일 때마다 세대가 있다. 탐색, 교체, 닫기는 그 세대를 끝낸다. 영역 연산과 그림 프레임은 세대를 포함하며, 표면과 영역 이름을 다시 썼더라도 호스트는 이전 세대 데이터를 거절한다.

앱 DOM을 다시 불러오면 그 창의 모든 플러그인 문서를 교체한다. 호스트는 대기 중인 배치를 취소하고 논리 표면을 숨기며, 문서·그림 부착을 닫고 공개 항목 등록과 합성 리비전을 지운 다음 새 부착 전에 세대를 진행한다. 이 작업은 터미널 세션을 닫지 않으며 새 모듈은 같은 세션 소유자에 다시 연결한다. 단일 DOM 모델에서는 탭별 WebView 탐색 콜백으로 이 수명주기를 구현할 수 없다. 다시 읽기 명령은 페이지 process를 끝내기 전에 표면을 숨기므로 창은 페이지 없이 native 표면을 보이지 않는다. 새 페이지가 그릴 때까지 창은 배경만 보인다. 라이브러리를 열고 작업 공간으로 돌아오는 것처럼 페이지 안의 화면 전환은 페이지 없는 frame을 보이지 않는다.

연속 배치는 완전한 네이티브 프레임만 커밋한다. 새 합성 또는 래스터가 준비되지 않았으면 호스트는 이전 완전한 프레임을 계속 표시하며, 새 영역에 이전 래스터를 잘라 붙이거나 늘리거나 플랫폼 기본 배경을 노출하지 않는다. 표시 중인 그림 영역의 합성 리비전, 래스터 리비전, 정확한 크기, 표시된 스냅샷은 모두 준비된 배치에 속해야 호스트가 커밋한다. 첫 유효 스냅샷 전에는 그림 레이어가 투명해서 애플리케이션의 표면 배경이 보인다. 입력이 끝난 뒤 `host.window.presented`는 자체 배치와 `SurfaceHost`가 모두 표시 중인 각 그림 영역이 정확한 현재 래스터를 표시하고 그 결과인 네이티브 트랜잭션이 화면에 도달한 뒤에만 완료된다. 바깥 표면을 숨기거나 다시 표시하면 영역 래스터 리비전을 바꾸지 않고 이 대기 조건을 갱신한다. 이 명령은 누락되거나 실패한 표시를 받아들이지 않고 제한 시간 오류를 반환한다. 빈 네이티브 픽셀, 오래된 래스터 내용, 플랫폼 기본 배경 노출, `SurfaceHost` 밖으로 나온 네이티브 콘텐츠는 실패다.

안정된 `SurfaceHost` 커밋도 같은 완료 경계를 가진다. 안정된 표면 배치는 그 합성 안의 표시 중인 모든 그림 영역이 정확한 현재 래스터를 소비하고 표시할 때까지 완료된 것으로 처리하면 안 된다. 프로젝트 라이브러리처럼 DOM 전용 페이지에서 혼합 표면으로 돌아올 때 표시 중인 네이티브 그림 영역이 하나라도 대기 중인 상태에서 복원된 DOM 페이지를 완료로 노출해서는 안 된다. 테스트는 여러 네이티브 영역이 표시된 표면에서 다른 페이지로 이동한 뒤 돌아와, 별도의 표시 명령을 추가로 호출하지 않고 복귀 직후 모든 영역의 사각형과 표시 래스터를 검증해야 한다.

네이티브 트랜잭션 확정과 취소는 창의 다시 그리기 콜백을 동기적으로 호출할 수 있다. 호스트는 프레임워크의 이벤트 전달 잠금 밖에서 네이티브 메인 큐로 이를 실행한다. 해당 잠금을 가진 프레임워크 콜백으로 전달하는 것은 안전한 완료 경계가 아니다. 확정은 여전히 앱 문서의 표시와 정확한 현재 이미지 래스터를 기다린다. 실행 위치를 옮겨도 두 조건을 제거하지 않는다.

## 그림 전송

그림 공급자는 호스트가 보내는 `configure` 이벤트에서 부착 세대, 래스터 리비전, 정확한 픽셀 너비·높이·배율을 받는다. 공급자는 대기 중인 설정을 최신 리비전 하나로 합친다.

각 프레임에서 공급자는 전송 그림을 쓰고 `{name, generation, raster, sequence, token, width, height, scale}`을 보낸다. 호스트가 `consumed`로 답하거나 거절하기 전에는 그 전송 그림을 수정하거나 재사용하면 안 된다. 시퀀스는 한 세대와 래스터 리비전 안에서 증가한다.

호스트는 호출자, 선언, 공급자, 세대, 래스터 리비전, 시퀀스, 토큰 권한, 실제 그림 크기, 예상 네이티브 크기, 배율을 검증한다. 유효 픽셀을 호스트 소유 불변 표시 저장소로 복사하고 그림 레이어를 그 스냅샷으로 교체한 다음 `consumed`로 답한다. 네이티브 표시 레이어가 공급자가 덮어쓸 수 있는 저장소를 가리키면 안 된다. 유효하지 않거나 오래된 프레임은 이전 유효 스냅샷을 교체하지 않는다.

## 입력과 쌓임

DOM 평면은 논리적 오버레이 계층으로서 네이티브 영역 위의 소유권을 가진다. 네이티브 픽셀이 보이도록 플랫폼 합성기가 앱 DOM backing보다 네이티브 평면을 위에 둘 수 있지만, 논리적 클리핑과 입력 소유권은 바뀌지 않는다. 현재 합성 리비전의 입력 소유권은 다음 순서로 결정한다.

1. 가장 위의 선언된 DOM 오버레이
2. 네이티브 입력을 소유한다고 선언한 영역 중 가장 위의 영역
3. DOM 평면

DOM 입력을 쓰는 그림 영역은 포인터 이벤트를 앵커로 보내고, 명시적으로 초점을 얻은 뒤 네이티브 키보드 조합과 접근성은 그림 손잡이에 남긴다. 문서 영역은 선언된 DOM 오버레이가 덮은 곳을 제외한 네이티브 포인터 입력을 받는다. 임의 DOM 콘텐츠는 오버레이가 아니며 네이티브 소유 지점의 입력을 가로챌 수 없다.

## 실패 동작

합성 검증은 닫힌 상태로 실패한다. manifest 검증은 선언하지 않았거나 빠졌거나 중복되거나 입력이 충돌하는 영역과 오버레이를 거절한다. 페이지 컨트롤러는 붙이기 전에 선언과 정확히 같은 요소 집합을 요구한다. 호스트는 마지막 완전한 유효 합성을 유지하거나 해당 네이티브 영역을 숨긴다. 부분 요청을 적용하거나, 영역을 `SurfaceHost` 밖으로 옮기거나, 빠진 선언을 추론하거나, 호환 경로로 대체하거나, 좌표 정밀도를 줄이거나, 원인을 모르는 틈을 색으로 덮지 않는다.

준비 또는 표시가 실패하면 요청한 작업을 거절하고 검증 상태와 오류 화면에 알린다. 작업 대기열을 영구적으로 거절하지는 않는다. 이후 사용자 배치 작업은 새 준비를 제출할 수 있다. 거절된 준비 Promise를 재사용하지 않으며, 자동 재시도로 실패한 작업을 성공으로 보고하지 않는다.

## 인수 기준

- 분할 드래그, 창 크기 변경, 숨김·표시, 순서 변경, 탐색, 다시 불러오기, 교체, 닫기의 모든 녹화 프레임에서 네이티브 콘텐츠가 `SurfaceHost` 안에 클리핑된다.
- 녹화는 네이티브 입력 전에 시작하고 요청한 속도의 전체 제스처를 포함하며, 빠진 프레임이나 플랫폼 기본 픽셀이 하나라도 있으면 실패한다.
- 검사는 합성 스냅샷, 설정 이벤트, 그림 프레임을 지연하고 순서를 바꾼다. 오래된 세대·리비전·시퀀스는 절대 표시되지 않는다.
- 혼합 표면은 소수점 좌표와 backing 배율 변경 후에도 네이티브/DOM 쌓임과 히트 소유권을 유지한다.
- 커밋되는 모든 프레임은 정확한 현재 래스터를 사용한다. 새 래스터가 소비될 때까지 이전 완전한 프레임을 유지한다.
- 터미널 그림은 리사이즈 중 논리 텍스트를 보존한다. 폭을 줄이면 열 수를 줄여 긴 논리 행을 여러 화면 행으로 재배치하고, 폭을 늘리면 열 수를 늘려 잘림이나 좁은 상태의 영구 고착 없이 다시 재배치한다.
- 터미널 셀 너비와 높이는 배치 중에도 고정된 표시 메트릭이다. 디바이더 이동은 표면·래스터 기하만 바꾸고 글꼴이나 셀 메트릭을 바꾸지 않으며, 네이티브 기하 변경은 애니메이션하지 않는다.
- 두 네이티브 호스트가 같은 선언과 리비전 규칙을 강제한다. 구현할 수 없는 플랫폼은 시작할 때 실패한다.
