# Example model

[한국어](example-model.ko.md)

The independent window declaration, placement, association and rail-border contract is [external window sidebars](external-sidebars.md). The internal card-side contract remains independent.

The example application owns projects, spaces, and tabs. The layout library owns card geometry.

| Object | Contents |
| --- | --- |
| Project | Root path, name, color, and spaces |
| Space | Card arrangement, focused card, card sidebar widths, and tabs |
| Card | Layout slots, optional pixel size, and tabs |
| Tab | Plugin and title |

The [project contract](projects.md) defines directory identity, persistence, settings inheritance, startup selection, and project windows. Switching spaces captures the current application state and restores the selected space through `Soksak.replace()`.

The add and split buttons select a plugin for a new tab. Dropping a tab on a card center adds it to that card; dropping it at a card edge creates adjacent space. Moving the only tab in a card moves the card.

Plugins declare surfaces as `{page}`, a document inside the plugin, and declare sidebar sections. A page shows web documents in document regions. The [plugin specification](plugins.md) defines the declaration files. Settings stores section sets and their assignments to the left sidebar, plugin card-left sidebar, or right sidebar.

A card has content and at most one sidebar on each of top, bottom, left, and right. There is one card-sidebar state and command path. Left and right run from below the card header to the bottom edge of the card; between them, the content column holds the top sidebar, the content, the bottom sidebar, and the content footer from top to bottom. The card header holds, before its tools, one sidebar control (`core.card.sidebar.fold`) for each side the card shows, in the order top, bottom, left, right; each runs `core.card.sidebar.toggle` for its side and is pressed while the side is open, and it stays in the header while the side is folded, so a folded side opens again from there. Each open card sidebar ends in its own status line of footer height that names its side and its set (`<side> 사이드바 · <set name>`, element name `core.card.sidebar.status`); a folded side shows no status line. The content footer (`core.card.status`) shows the footer text that the active tab's plugin reports ([tab reports](plugins.md#tab-reports)), followed by the sides folded for lack of space, and spans only the content column at the bottom edge of the card, in one row with the status lines of the left and right sidebars, so the bottom edge of the card is one band of footer height. The content footer is one line: the state of the surface of the active tab, its error and the operation error of the tab shrink with the footer and are cut with an ellipsis when they do not fit, and each error carries its whole text as its tooltip, while the error display writes it to the application log when it appears. An explicit set overrides the active plugin default and survives tab changes. Without an explicit set, the plugin default applies. `core.card.sidebar.set {card, side, set}` accepts a known set, `off` to disable that side, or `inherit` to clear the explicit selection. Folding and sizing through `core.card.sidebar.toggle {card, side}` and `core.card.sidebar.size {card, side, size}` persist independent layout values without making a default-derived set explicit. The card remains the same size and content fills the residual area. `core.grid` reports effective sides as `sidebars`; the separate inset sidebar, panel commands, and duplicate left column are removed.

Card layout is stored in `data.sidebars`, keyed by side. Each entry may contain an explicit `set`, a `size`, and a boolean `collapsed`. An absent `set` derives the active plugin default; `off` disables the side. `inherit` removes only the explicit set and retains layout. Missing assigned sets, invalid saved fields or values, and obsolete `data.sidebar` or `data.panels` produce explicit errors; there is no migration or hidden removal. Folding hides section content and retains a visible divider with an input area. Static residual-width and divider-area checks are separate from full gesture acceptance. Fixed external sidebars and their active plugin overrides follow the external-window contract; legacy flow/pin positioning is removed.

A card-sidebar divider measures the sidebar extent at pointer-down and adds the signed pointer displacement: left/top increase toward the card center, right/bottom increase in the opposite direction. The opposite sidebar, card header and footer do not contribute to this displacement. The size is bounded by the declared sidebar limits. A drag from a folded side starts at the folded extent and opens the side when the pointer reaches the minimum size, so the edge stays under the pointer; a drag stores the size and an open choice. A click without a drag folds a side shown open and opens a side shown folded, whatever the stored choice was. The divider input box stays inside the sidebar at its inner edge; it must not extend beyond a clipped parent or put its center on a native surface.

The browser application simulates native surfaces. Browser checks do not verify native composition; native acceptance requires the host checks in [verification](../operations/examples.md).

`plane.js` owns card and tab actions. `compositor.js` measures or predicts surface rectangles. `host.js` sends native requests. Each application's `runtime/index.js` implements transport for its runtime. `environment.js` loads the application's plugins and defaults. `settings-ui.js` owns settings DOM; `card.js` handles inputs shared with `overlay.html`.

## Card tabs

A new tab takes the name `탭 <n>`, with the next number of its space, and the layout stores that name as the `title` of the tab without the mark of its plugin; `core.grid` reports it as `title`. The tab strip, the tab list and the question about unsaved changes draw the mark of the plugin, or `?` for a plugin that is not loaded, a space and the name, and the title that the surface reports replaces both. Each workbench draws that text with one function for the tab strip, the tab list and the space apps list, so a tab shows the same text in each, with the mark of a modified tab; an item of a list shows the icon of the plugin in its icon slot and no second mark. The mark is part of the drawing, not of the name, so a name that another part reads, such as the sender of a message without a reported title ([injected message](messaging.md#injected-message)), is the stored name alone.

A tab of a card header shows the plugin's tab name or the title that its surface reports. A tab is at most 200 points wide, so one long title leaves the width of the tab strip to the other tabs: a name that does not fit keeps as many of its leading characters as fit beside the ellipsis `…`, which ends it, as CSS `text-overflow: ellipsis` cuts a line: the first character is cut at the end of the room rather than replaced by the ellipsis, so a tab whose room is narrower than its first character and the ellipsis shows the cut first character without the ellipsis, in mygo as on the page, and the tooltip of the tab shows the whole name. The active tab of the focused card draws its border in the focus color, the color of the ring of the card, and the active tab of every other card draws none, so the keyboard, the ring and the tab border show one focus; the border lies inside the tab and takes no room from its name. The tab list button (element name `core.card.tab-list`, ≡) stands at the start of every card header and lists all tabs of the card; a fullscreen card shows the space apps button in its place. When the header narrows, it first shows only the active tab and then cuts it, and the button stays; a header keeps a part of the active tab at least `tab-grab-w` wide, 32 points, the part that a press grabs to drag the tab, at every width down to the minimum width of a card. The stages follow from the width of the header and the widths of its tabs alone, the same whichever tab is active: each condition takes the widest tab of the card in place of the active tab, so the active tab, which the header shows in every stage that shows a tab, always fits where the widest does, and a selection never changes the stage. The card tools fold into the ⋯ menu when the widest tab no longer fits beside them, except the fullscreen toggle and the leader mark ([group headers](groups.md#headers)), which stay in the header immediately before the ⋯ button, are counted by the header fit with that button, and are not held in the menu (tools `menu`); the header keeps every tab while every tab, or the widest tab and `tab-peek-w`, fit beside the tools. When the room beside the kept tools and the menu is less than the widest tab and less than `tab-min-w`, the kept tools fold into the menu as well and only ⋯ stays after the tab (tools `all`), so the controls fold before the tab; the header drops the active tab only when the room beside ⋯ is less than the widest tab and less than `tab-grab-w`. The minimum width of a card, `minSize` of the layout, 96 points, holds that part: the two borders of the card, the head padding `card-head-pad` on both sides, ≡ and ⋯ of `card-button` each, the two gaps `card-head-gap` and `tab-grab-w` take 90 points. The layout cases of `docs/spec/cases/layout/head.json` state these stages from the measured widths of the header.

## Card tools

The card tools stand in the header in this order, each named by one entry of `cardTools` in `packages/workbench/workbench.json`, which both workbenches read:

| Tool | Element | Name |
|---|---|---|
| Add a tab | `core.card.add` | 탭 추가 |
| Split side by side, the new card on the right | `core.card.split-x` | 좌우로 분할 |
| Split stacked, the new card below | `core.card.split-y` | 상하로 분할 |
| Split into a new group toward right, enabled while that group succeeds ([group cards](groups.md#headers)) | `core.card.group-x` | 그룹으로 좌우 분할 |
| Split into a new group toward bottom, enabled while that group succeeds | `core.card.group-y` | 그룹으로 상하 분할 |
| Make the card the leader of its level, shown in a level of two or more members and pressed on the leader | `core.card.leader` | 리더로 정하기 |
| Fullscreen | `core.card.fullscreen` | 카드 전체 화면, and 카드 배치 복원 while the card is fullscreen |
| Close | `core.card.close` | 카드 닫기 |

The tooltip and the accessible name of a tool are its name; they describe no behaviour. A disabled tool states its reason instead, without a separator: a close that no neighbour can fill shows 이 자리를 빈틈없이 메울 이웃이 없어 닫을 수 없다, and the tools that change the layout of a fullscreen card show 전체 화면에서는 배치를 바꿀 수 없다. The ⋯ menu lists each enabled tool under its name as the tooltip holds it. The header of a group card takes the same names for its tools, and its close button, named 그룹 메뉴, opens the close menu of the group with the items 그룹 닫기 and 그룹 풀기 ([group cards](groups.md#headers)).

## Card fullscreen

The card header has a fullscreen toggle immediately before the close X. `core.card.fullscreen {card}` toggles that content card between its normal arrangement and the full work area. The control has element name `core.card.fullscreen`, an explicit accessible name, and a restore icon drawn in the focus color while fullscreen, like the pressed toggles of the window header. `core.grid.fullscreen` reports the presented card ID or null; each card reports whether it is fullscreen. Fullscreen is transient presentation state, not a saved layout mutation. Other cards and their live surfaces are hidden without disposal. A hidden card shows no head and no pane, so `core.grid` reports its `acts` and its `pane` as null, and the panes of the shown cards are counted without it. The same toggle restores all original card geometry and state. Resizing the work area retains fullscreen. While a card is fullscreen, the layout does not change from the card tools: the add, split and close buttons are disabled with the title `전체 화면에서는 배치를 바꿀 수 없다` ([card tools](#card-tools)), and `core.card.menu`, `core.card.add-tab`, `core.card.split` and `core.card.close` are refused with `card <id>: the layout does not change while card <fullscreen card> is fullscreen; restore the arrangement first`. A tab drag restores normal presentation when it moves, and selecting another card restores normal presentation. While a card is fullscreen, its header starts with the space apps button (element name `core.card.space-apps`) and does not show its own tab list button, because the space list holds its tabs. The button runs `core.space.apps {card}`, which opens a selection layer titled `스페이스 앱 N개` that lists every tab of the space in groups, one group per content card. The groups follow the slicing tree of the arrangement from the start of the plane (left and top first); the heading of a group draws a map of the space's cards with that card filled, names it `카드 N`, and is indented by the card's depth in the tree, so cards under the same cut stand at the same depth. Under each heading the card's tabs are listed with their plugin mark and name, the shown tab marked active; the icon slots of a heading and of its items have one width, one left padding and one gap, so at one depth the icons stand in one column and the names start at one x, and an item of a plugin that is not loaded keeps its empty icon slot; `core.picker` reports the card of each item in `group` and the headings in `groups` (`id`, `name`, `depth`); the icon and the name of each heading and of each item have the element names `core.picker.group-icon`, `core.picker.group-name`, `core.picker.item-icon` and `core.picker.item-name`, and the status `core.picker` reports `columns` (`{groups, items}`: the x of the icon and of the name of each heading and item, relative to the left edge of the picker). The main document hides the picker while the native view draws it, so the columns are measured when the picker opens and a window check reads them from the status. Picking a tab of another card moves fullscreen to that card and shows the tab; picking a tab of the fullscreen card shows it. The selection keeps fullscreen. Invalid and sidebar-only cards fail explicitly. The OS window state does not change.

Card-sidebar expansion depends on the saved choice and available presentation space. The room of an axis is the card extent less its borders (and header and footer for height), the current layout minimum for content (currently 96 points), and the divider of each side folded by choice. Open sides whose stored sizes fit the room are shown at those sizes. When they do not fit, they are shown smaller in proportion to their stored sizes; when that would make a side smaller than the declared sidebar minimum, the side operated last (by click or drag; top or left before any operation) is shown at the size that fits, at most its stored size, and the other side folds automatically. A side that does not fit at the minimum alone folds automatically. Width applies to left/right and height to top/bottom. The status line of the card names the sides folded for lack of space. A folded side uses only the declared divider width and draws only three dots at its centre, 3 points wide and 6 points apart along the side, in the grip colour and the active grip colour on hover and press, so it differs from the bar grip of a card divider; it draws no line along the side, because such a line reads as another card edge. Where a folded strip lies next to a card divider, the input divides at the outer edge of the card: the gap between the cards up to that edge belongs to the divider (`core.divider`), which moves the boundary, and the strip inside the card belongs to the sidebar control (`core.card.sidebar.grip`), whose press opens or folds the side and whose drag sizes it. The set of an open side stops before the band of that control, because a section view is a native view above the document and would cover it. The divider widens its input to the library's grab size of 11 points only where the gap is narrower than that, and then it also takes the part of the card edge that the widening covers, a native view of the card at that edge included: the grab area is a window overlay of the page on the Wails and Tauri hosts and an element that covers the native views on the mygo host ([surface host container](native-surfaces.md#surface-host-container)), so a press, the cursor and `host.hit` there belong to the divider. Which control of the workbench takes a point of the grab area, the divider or the sidebar control, the workbench decides as at a point outside every native view. Recompute on fullscreen, resize and layout restore. Preserve assigned sets, sizes and saved user fold choices. core.grid exposes actual collapsed, requestedCollapsed, autoCollapsed, collapseReason and shownSize (the size shown, or null for a folded side). A user-folded side stays folded when more space becomes available.
