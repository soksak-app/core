# Host parity

[한국어](host-parity.ko.md)

The two application hosts (`tauriv2`, `wailsv3`) implement the same product. Parity between them is not a review opinion: `make host-parity-check` (`scripts/check-host-parity.mjs`) decides each proposition below; it reads both hosts' sources and fails on any difference. A legitimate difference does not relax a proposition; it is a change to the proposition itself, made in this document together with the correction.

## Propositions

1. **Public bindings are the same set.** The page-facing command surface each host registers — the names of the Rust commands that the `bindings!` block defines and registers and exported `Host` methods in Go, compared in snake case — is one set. A command that exists on one host and not the other fails the check.
2. **Endpoint methods are the same set.** The local [endpoint](endpoint.md) method names each build declares — base methods, subscription methods, and the diagnostics-only additions — are one set for both hosts in the same build flavor. Each diagnostics-only method that a host declares is a row of the [diagnostic builds](endpoint.md#diagnostic-builds) table, and each row of that table is a method that a host declares.
3. **The application menu is the declared contract.** Both hosts' menu bars contain the same items in the same order with the same shortcuts, per the menu contract table in [host contract](host-contract.md). The check runs against running hosts and enumerates the real menu bars; an item present on one host and missing on the other fails.
4. **A single-host exemption must still be true.** Every `<host> only: <reason>` row in the host contract's case table cites a difference that observation must still confirm. When the cited difference no longer holds, the exemption is stale and the check fails until the case becomes `both`.
5. **Tests live where their functionality lives, at one level for every language.** Production folders carry their owning tests in the same tree, and every language's suites run in the same gate. The check compares folder-by-folder and gate-by-gate; a language wired lower than another, or a test clustered away from its owner, fails.
6. **Every platform method has a caller.** Each method of every trait of the Rust platform interface (`src/platform/platform.rs`) and of every interface of the Go platform interface (`src/platform/platform.go`) is called by a production source of its host outside `src/platform`: in Rust as `.name(` or `::name(`, in Go as `.Name(` or as the method value `.Name`. Test files (`_test.rs`, `_test.go`), the items of a Rust source that only test builds compile (`#[cfg(test)]` and `#[cfg(all(test, ...))]`) and comment lines are not callers. A call inside a free function counts only when the product reaches that function: the function is an entry point (`main`, Go `init`, a `#[tauri::command]` or a cgo `//export` function), or a counting call names it from the sources of its host or of the application that links the host (`apps/tauriv2/src`, `apps/wailsv3/src`), so a function that only tests call is not a caller, and neither are functions that only call each other. A call in a method, an impl or a package-level value counts. A method without a caller fails the check and is removed with its implementations, because no build check reports an unused trait method or an exported Go interface method.

The check's output is the difference report. Corrections run Red (the check fails on the unfixed tree) and Green (the check passes after the change) through the same tool.
