## Unreleased

- Show web documents in document regions instead of URL surfaces ([native surfaces](docs/spec/native-surfaces.md#document-regions)). `plugin.json` `surface` accepts only `page`, and `home` names the first address of a surface page; `surface.url`, the workbench `external` flag, and Tauri external surface URLs are removed. `native/darwin` adds `document_view.m`: a web view inside the surface web view with its own persistent data store, http and https navigation only, state reports with the scroll position from an isolated content world, placement by viewport insets, and dialog blur. Both hosts add `DocumentAttach`/`document_attach`, place, load, go, and detach calls, check that the caller is the named surface, send `document-state` only to that surface, close regions when a surface is removed or its page commits a new document, and report regions in `host.window` `documents` and `host.hit` `{kind: "document"}`. The Tauri document commands run off the main thread, and cleanup started on the main thread does not wait. The plugin API adds `attachDocument` (placement from `ResizeObserver`, resize, and scroll events), `ownManifest`, and `page.document` in both runtimes. The browser plugin is now a page with an address bar, `browser.location`, and the `browser.navigate`, `back`, `forward`, `reload`, and `stop` commands; its toolbar uses the card tokens. The inventory lists `_setOverrideDeviceScaleFactor:` on document views. `e2e/browser.test.mjs` checks navigation, history, address typing, native scroll without activation, placement after surface moves and resizes, isolation between browser surfaces, and closing with the surface; the settings check now expects the browser point to belong to the document region. Package tests, host tests, `make native-test`, `make release-check`, `cargo check` for macOS and Windows with and without `diagnostics`, and Windows `go vet` passed. Document regions take their frame from their insets whenever the surface changes size; autoresizing had lost the insets after the surface was smaller than them. A region reports `loading` from the request of a navigation until it starts or fails, because a replaced load reported a finished load of the new address before it started.
- Measure and report more of what the window checks depend on. Capture frame files store the rectangle the window occupies in the buffer, the content and backing scales, and the display time. `diagnostics.capture.start {display?}` records around any request, and with `display` records this application's windows on the window's display, which keeps recording in a full-screen Space. The capture reports blank and suspended frames, copies frames in its handler and writes them on a separate queue (slow 2× writes of up to 480ms had dropped frames and caused the intermittent frame-count failures), and `diagnostics.capture.stop` returns `longestGap`; a drag recording with a gap over 100ms fails. `sp_input_activate` reports the step that stopped (refused, not key, webviews pending, lost) with the frontmost application, and both hosts put it in the 1006 message. `host.window` adds `maximized`, `host.screens` adds `visible`, and `host.window.fullscreen` enters and leaves full screen. `e2e/resize.test.mjs` records maximizing and restoring and reports frames whose layout is behind the window frame (250–400ms in both hosts); holding the window's Core Animation transaction until the layout presented kept frames matched but slowed the AppKit animation, could not pace the Wails display-link animation, and stalled pages that keep drawing, so it was removed.
- Make native input arrive in order and at the requested distance. A press or release from `input.pointer` answers after the document received it, reported by a script in a separate WebKit content world: with a text field focused, WebKit passes mouse events to the input method asynchronously, and a press and release sent together reached the shell page in the opposite order. A scroll is delivered after the target view has presented, because WebKit does not scroll a new document with an earlier wheel event. Wheel distances for web views in the device-pixel surface container are converted to the container's units in the application's event monitor and in native scroll input; at 2× every surface and document region scrolled half the distance. The page runtime sends sidecar messages in call order.
- Fix hangs and races found by the checks. The Tauri host held the modal view lock while waiting for the main thread in `host.window`, while the main thread waited for that lock to place the modal. The endpoint `command.run` waits for the main page without its own 10-second limit, because the main page answers forwarded commands within their declared timeout; requests to a main page that is not ready or reloads end with 1003. Core commands answer after the draws they scheduled, so `core.boundary.move` no longer returns before the cards move. `soksak-stage` replaces staged sidecar executables with new files; overwriting a file that had run made macOS kill the new process. The browser check waits for the page title and for the full scroll distance.
- Open saved spaces that name plugins or sections the environment does not register ([projects](docs/spec/projects.md#persistence)). The workbench drops their tabs, rails, and rail widths, closes a card left without tabs or gives it a new tab, skips their sections in set names, and leaves them out of library previews. Before, such a space or preview failed with `unknown plugin` or `unknown section`, for example with data saved before the terminal plugin became `shell`. `e2e/projects.test.mjs` checks both hosts.
- End both hosts cleanly on termination signals ([endpoint](docs/spec/endpoint.md#discovery)). SIGTERM, SIGINT, and SIGHUP ended the process with the default action, leaving `endpoint.json` and the socket; Wails v3.0.0-beta.16 creates its signal handler but never starts it. `OnTermination`/`on_termination` in `platform/darwin/termination.*` now turns the first signal into the quit that `host.quit` runs, which saves ready windows first, and lets later signals end the process. The Wails default handler is disabled, and the Tauri host adds `signal-hook`. Before listening, both hosts remove sockets of ended processes of the same application. `tests/termination_test.*` checks the signals in a child process and `tests/endpoint_test.*` the removal. Three existing clippy warnings in the Tauri host are fixed, and the host tree in [native hosts](docs/spec/hosts.md) now lists the document region and termination files.
- Wait for committed layouts before reporting a presented window, and record up to the presented screen ([native surfaces](docs/spec/native-surfaces.md), [exposure](docs/spec/exposure.md)). A newer surface preparation extends the window's open layer transaction, so a presentation update could finish while the screen still showed the previous layout; the maximize check failed in 3 of 12 and 2 of 20 runs on Tauri with a last frame of the previous size. `native/darwin` adds `surfaceLayoutAfterSettled`, which waits until the window has no open or queued preparation, then for the presentation update, then reads the next refresh time from the screen's `CADisplayLink`; both hosts use it for `host.window.presented`, which now returns `{displayed}`. `diagnostics.capture.stop` takes `after` and stops once the stream has delivered the screen at that time, and the harness passes it for drags and resizes. `resize.test.mjs` removes each recording right after measuring it and restores the window in a session cleanup, because the after hooks of a test run after the session closes its connection; a failed restore had skipped the removal and left 21 GB of recordings, which filled the disk and made later recordings stall. The maximize check then passed 30 consecutive runs.
- Apply modal content and positions in the order the host changed them ([native modals](docs/spec/native-modals.md)). A modal document receives its first content as a call answer and later changes as events; an answer that arrived after a later position event moved settings back to its opening position, which failed a Wails command check once. Both hosts number each content and position change, and `workbench/modal-order.js` drops older values. `core.modal` `document` adds `loaded`, and debug builds add `diagnostics.modal.hold` and `diagnostics.modal.held`, with which `modal.test.mjs` delivers the first answer after a move; it failed on both hosts before the change. The Tauri `overlay_content` command no longer runs on the main thread.
- Shorten the window zoom animation in both hosts ([native hosts](docs/spec/native-host.md)). The window frame and the web content are presented separately, so the whole animation showed the previous layout: `resize.test.mjs` measured the layout behind the window for 263ms in Wails and 432ms in Tauri. AppKit reads the length from the `NSWindowResizeTime` user default, in AppKit's own zoom and in the Wails window's replacement animation; 0 is ignored, so `native/darwin/src/window_motion.m` registers 0.001 before the first window and a value the user set still wins. The layout now follows within 116ms at worst, and `resize.test.mjs` fails over 150ms; 20 consecutive runs passed. `native/darwin/tests/window_motion_test.m` compares the resize time of a process that registers the value with one that does not (0.350s and 0.003s).
- Keep a surface at the frame the host applied ([native surfaces](docs/spec/native-surfaces.md)). Attaching the Web Inspector to a surface web view made WebKit move that view to the rest of the window and leave it there after the inspector closed: in a running application the shell surface became the full window width (0,250 1512×228 instead of 412,121 428×357), and `core.verify` reported `V7b applied == declared` off by 1083px. `webviewSetFrame` now remembers the frame of views in the surface coordinate container and restores it when something else changes it, so an open inspector overlaps the surface instead of moving it. Modals keep following the window, because a dialog modal resizes with it. `native/darwin/tests/webview_inspector_test.m` opens and attaches the inspector through `_WKInspector` and checks the surface frame; without the change it measured 0,250 1000×100.
- Let AppKit own the window buttons ([native hosts](docs/spec/hosts.md#window-buttons)). The hosts moved the buttons into a view of their own to centre them in the page's 45pt first row; AppKit took them back whenever the window title or the recording indicator changed, and the frame in between reached the screen: a recording of window moves and resizes showed the buttons missing or at the title bar position in about one of 48 changes. Each window now gets an empty toolbar with the unified compact style, so the title bar is 40pt and AppKit centres the buttons in it; `windowUnifiedTitlebar` replaces `windowPlaceControls`, and the container that held the buttons is gone. The page takes the first row height from the button area (`--chrome-h`), so the row follows the title bar. `native/darwin/tests/window_controls_test.m` checks the centring after a resize and a title change, and `e2e/controls.test.mjs` checks it through six rounds of moving, resizing, maximizing, and renaming in both hosts.
- Keep the first row and full screen in step ([native hosts](docs/spec/hosts.md#window-buttons), [exposure](docs/spec/exposure.md)). Taking the first row height from the button position made the row 1884pt in full screen, where AppKit moves the buttons out of the row: the hosts now answer the page with the button area and the title bar height, and the page keeps its row height when there is no title bar. `host.window.fullscreen` answers after the transition; macOS ignores a request made during one, so `sp_window_fullscreen` applies it when that transition ends. The name starts with `sp_` because Wails compiles its own `windowFullscreen` and the linker had picked that one, which made the host report a failure while the window did change. `native/darwin/tests/window_fullscreen_test.m` and `e2e/controls.test.mjs` check both.
- Save a project window's position in window points in the Tauri host ([projects](docs/spec/projects.md#persistence)). `windowState` returned the size in points and the position in physical pixels, so on a 2× display the saved numbers named a place twice as far from the screen origin; a window at x 755 was stored as 1510 and reopened against the right edge of the 1512pt screen, where the layout had 57pt content columns. The Wails host already stored points, so the same file meant two places. `e2e/projects.test.mjs` now compares the saved geometry with the window frame the host reports, which failed on Tauri and passed on Wails before the change.

- Draw the rail outline in the plane's CSS pixels ([native surfaces](docs/spec/native-surfaces.md)). The outline is an SVG path in an element that covers the plane, and that element carried a coordinate system the size of the grid. When the window grows, the element follows the plane before the page draws again, and the previous path is fitted to the new box: a recording of a full-screen transition showed the outline around the enlarged layout while the cards, sidebars, and surfaces were still at the previous size. Without that coordinate system the numbers in the path are CSS pixels, so the outline stays with the cards until it is drawn again. `packages/workbench/test/rail.test.mjs` checks that neither the page nor the plane gives the outline a coordinate system that scales with its element.
